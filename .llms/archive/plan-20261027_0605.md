# Replace SolidJS with React and TanStack Start — file-based routes, Effect stays the server

> Archived 2026-10-27 — historical, every phase done and the matrix green. The live page stack is React 19 and TanStack Start inside the Effect server; the boundary lives in `.llms/rules.md` and `.llms/architecture.md`.

## Objective

Replace the SolidJS 2.0 page surface with React and TanStack Start file-based routing. After this plan, pages render through Start's streaming SSR, route files follow TanStack conventions, and page data crosses the client boundary only through `createServerFn`. The Effect HTTP server remains the only listener: it keeps `/api/*`, metrics, middleware, and static assets, and forwards page requests to Start's `fetch` handler. This plan does not add Nitro, a second HTTP server, or a public page API. When the rewrite is done, a cleanup phase removes every Solid trace from the tree, including comments, catalogs, skills, and editor config. The finished plan and its handover are then archived, so the live ledger does not keep the old stack as current fact.

## Current state (verified in the tree, 2026-10-27)

- **Pages are Solid 2.0, not a meta-framework.** `package.json` depends on `solid-js`, `@solidjs/web`, `@solidjs/router`, and `@solidjs/meta` at 2.0 RC/next. `vite.config.ts` enables `@solidjs/vite-plugin` with `ssr: true` outside Storybook/Vitest, and `filesystem-routing/vite` with `types: true`.
- **The Effect plugin owns three Vite environments.** `src/builder/vite-plugin.ts` configures `client`, `ssr`, and `effect`. The client output renames assets whose names start with `virtual_solid`. Standalone mode sets `noExternal: true` on the `ssr` environment so the distroless image can resolve the page bundle. `tests/builder/vite-plugin.test.ts` asserts that `virtual_solid` naming.
- **Production SSR is a bundle import, not a dev middleware.** `src/kernel/renderer.ts` dynamically imports `dist/server/server.js` and calls `handleRequest(request, { nonce, event })`. Static files under `dist/client` are served first for non-root paths; a static miss falls through to that handler. A TypeID nonce is minted per render and written as CSP. `src/middleware/security-headers.ts` comments that HTML responses stream Solid hydration scripts.
- **Dev pages do not pass through Effect.** `effectVite` only intercepts `/api/*`, the API docs path, and `/metrics`. Vite's Solid dev server renders pages. `vpr dev` is `vp dev`.
- **Request-scoped user data uses AsyncLocalStorage.** `src/modules/identity/user/user_ssr.ts` stores `UserService` on a global symbol and writes `x-cache` with `@solidjs/web`'s `httpHeader` before the detail markup settles. `user_fn.ts` branches on `import.meta.env.SSR` and dynamically imports that module. An unparseable user id resolves to `undefined` (`user_ssr.test.ts`).
- **Routes are Solid file routes.** `src/routes/(app).tsx` is a pathless layout, `users.tsx` nests `users/`, `[id].tsx` preloads a `query`, and `[...404].tsx` sets HTTP 404 in `preload`. `src/router.ts` builds `@solidjs/router` from `virtual:file-routes`. `file-routes.d.ts` is gitignored and referenced from `src/vite-env.d.ts`. `.vscode/settings.json` excludes that generated file. `.llms/rules.md` requires `vp run build` before check and typecheck because of it.
- **StyleX output is adapted for Solid.** `src/resources/styles/props.ts` maps `className` to `class` and says so in a comment. Every page and `navbar.tsx` spreads `sx(...)`. CSS `borderStyle: 'solid'` and the `solid-accent` comment in `button.stylex.ts` are not SolidJS.
- **Storybook is Solid and empty.** `.storybook/main.ts` uses `storybook-solidjs-vite`. `.storybook/vitest-integration.ts` imports `@solidjs/vite-plugin` and aliases `storybook-solidjs-vite/renderer/solid-next`. A search for `*.stories.tsx` returns no files. `vite.config.ts` still registers a Storybook Vitest project.
- **E2E asserts Solid copy.** `e2e/screens/home/home.spec.ts` expects the feature title `Solid 2 Reactivity` and a docs link to `https://v2.solidjs.com/`. `e2e/screens/not-found/` also names Solid. CI (`.github/workflows/test.yml`) builds, checks, typechecks, runs unit tests, then Chromium E2E.
- **Catalogs and skills still name Solid.** `pnpm-workspace.yaml` catalogs `@solidjs/*`, `solid-js`, `storybook-solidjs-vite`, and `@solidjs/diagnostics`. `.agents/skills/deep-audit/references/performance.md` is a false hit (`consolidate`), not a Solid claim.
- **TypeScript is Solid-shaped.** `tsconfig.json` sets `jsx: preserve`, `jsxImportSource: @solidjs/web`, and `verbatimModuleSyntax: true`.
- **No TanStack package is installed.** Searches for `tanstack` and `react` in `package.json` dependencies return no matches.
- **External facts checked against current docs, not the tree.** TanStack's manual SSR guide (`/router/latest/docs/how-to/setup-ssr`) says TanStack Start is the recommended SSR path and limits the Express `entry-client` / `entry-server` recipe to servers that are not already integrated. Start's server entry is a `fetch(request)` handler (`/start/latest/docs/framework/react/guide/server-entry-point`). The Start custom-server example imports `./dist/server/server.js` and calls `handler.fetch` (`TanStack/router` `e2e/react-start/custom-basepath/express-server.ts`). Start's plugin can set `vite.installDevServerMiddleware` (`@tanstack/start-plugin-core` 1.170.6 schema). Server functions dispatch on the `/_serverFn` prefix and run inside request AsyncLocalStorage (`start-server-core` skill, library 1.169.17). Loaders are isomorphic; only `createServerFn` stays server-only (`/start/latest/docs/framework/react/guide/execution-model`). Start warns that `verbatimModuleSyntax` can leak server code into the client bundle. `@tanstack/react-start` 1.168.6 peers `vite >= 7` and `react` / `react-dom` 18 or 19, and requires Node `>= 22.12`. This repo requires Node `>= 24.22`.

## Decisions

- **D1 (2026-10-27): TanStack Start renders pages; Effect remains the only HTTP server.** The owner picked this over the manual Router recipe and over Nitro. Start owns the document shell, streaming, hydration, and the generated route tree. `renderer.ts` calls the built `fetch` handler in production. Dev page rendering stays on Vite, with Start's own middleware, because that is how `vpr dev` already splits pages from `/api`. The cost: two SSR implementations must agree on the `fetch` contract, and Start's plugin must not replace the `effect` environment or swallow `/api`. Rejected: the Express manual setup — it adds `entry-client.tsx`, `entry-server.tsx`, and a second server the Effect listener would have to duplicate. Rejected: Nitro — it replaces the listener this repository's middleware stack is built around.
- **D2 (2026-10-27): Page data moves to `createServerFn`; `/api/*` stays the public contract.** The owner picked server functions over a loader that reuses `user_fn.ts` and over SSR `fetch('/api')`. Loaders call server functions. Server-function handlers call `UserService` through the existing runtime. `user_fn.ts` and `user_ssr.ts` are deleted, not wrapped. The cost: page data and `/api` are two readers of one service, and a server function is an RPC endpoint, not a public API. CSRF middleware stays on the Start default. Rejected: keeping the `import.meta.env.SSR` bridge — it preserves a Solid-shaped split the rewrite is removing. Rejected: SSR HTTP to `/api` — it makes rendering depend on the listener calling itself.
- **D3 (2026-10-27): Route files move to TanStack conventions; URLs do not change.** The owner picked this over custom Solid filename tokens. `__root.tsx` owns the document. `_app.tsx` replaces `(app).tsx`. `users/$id.tsx` replaces `[id].tsx`. `$.tsx` replaces `[...404].tsx`. Pathless layout, nested users layout, and the 404 status are preserved. The cost: every route import and E2E copy assertion moves in one phase. Rejected: `indexToken` / `routeToken` aliases — they keep names no TanStack example uses.
- **D4 (2026-10-27): Storybook switches to React and gains no stories.** The owner picked a framework swap over deletion and over leaving the Solid framework in place. Scripts and the Vitest project stay. The cost: an empty Storybook still has to build. Rejected: deferral — `storybook-solidjs-vite` cannot render React components, so `vpr storybook` would be a known-broken command.
- **D5 (2026-10-27): `verbatimModuleSyntax` is turned off.** The owner accepted Start's warning. `jsx` becomes `react-jsx`. `jsxImportSource` is removed. The cost: TypeScript no longer enforces `import type` by itself; the bundler and lint rules have to catch value imports that pull server code into the client. Rejected: leaving the flag on and waiting for a leak — the leak is a production bundle defect, not a type error.
- **D6 (2026-10-27): No compatibility layer.** The owner waived backward compatibility for this early-stage tree. Solid packages, `filesystem-routing`, `file-routes.d.ts`, `App.tsx`, and `Document.tsx` are removed in the phase that replaces them. No re-export, alias, or dual router remains.
- **D7 (2026-10-27): Page-response `x-cache` is measured, not assumed.** Today `httpHeader('x-cache', ...)` writes the header on the HTML response before the shell flushes. Start's `setResponseHeader` inside a server function applies to the `/_serverFn` response. During SSR the handler runs in the page request's AsyncLocalStorage, but that does not prove the header is copied onto the HTML response. Phase 3 probes a built detail page with and without `?nocache=1`. If the HTML response loses `x-cache`, the server function returns `cache` on the payload and a small Start request middleware copies it onto the page response before the head flushes. The API response contract is unchanged. The cost: one probe can add a middleware file the plan does not otherwise need.
- **D8 (2026-10-27): No Solid trace remains after the rewrite.** The owner required a historical cleanup once the work is finished. Phase 7 deletes Solid mentions from code, comments, tests, catalogs, skills, editor config, docs, and the live ledger. A case-insensitive search for `solid`, `@solidjs`, `filesystem-routing`, and `file-routes` must return no hits except the words kept below. CSS `borderStyle: 'solid'` and the phrase `solid-accent` in `button.stylex.ts` are not SolidJS and stay. Git history is not rewritten. The cost: the finished plan cannot stay live, because its current-state section names the old stack. Rejected: leaving comments and catalogs until a later pass — the owner asked for the cleanup at the end of this plan, not as a follow-up.

## Execution rules

- **Atomic commit per phase** is authorized. Each phase heading names its message. Self-serve commits are allowed during this plan's working session. After phase 7, stop and recommend the closing message — do not commit that close unasked.
- **Execution waits for the owner's explicit "continue with phase N".** A written choice on this plan is not permission to start phase 1.
- **No compatibility layer, no legacy route names, and no leftover Solid trace.** Delete replaced Solid files in the same phase that adds their replacements. Do not keep a re-export, a dual renderer, a Solid token alias, or a comment that names the old stack. Phase 7 is the sweep that proves the tree is clean. Git history is not rewritten.
- **Effect's public HTTP contract stays.** `/api/*`, `/api/health`, metrics, the envelope, middleware order, and the nonce CSP stay. Do not add Nitro, Express, or a second listen port.

- **E2E is relevant.** Existing Playwright scenarios are updated with the UI they describe. New scenarios are added only for a behavior the current screens do not cover.
