# Findings from the Marko + Vite + vanilla-extract migration

What the move to Vite (both targets), Marko pages and vanilla-extract left open or unverified. Plans touched: none. The migration itself is described in `rules.md` ("Frontend contracts", the builder bullet) and `architecture.md` ("Frontend", "Build and deploy").

## 1. Not exercised in the session that built it

- **status**: resolved
- **resolution**: run over real ports on 2026-10-16: `pnpm dev` and `pnpm dev --mode worker` (pages, API, the inline `<style>` under the widened policy, a POST), `pnpm preview` (`nodePreview`), `pnpm preview --mode worker` in workerd (pages, `/assets` links, the unwidened policy, the lowercase email index on D1), `node dist/server/index.mjs serve`, and `./dist/edgy serve` (SEA assets). A browser hydrating `/users` is now covered by `pnpm e2e` (item 4). Vite's reaction to a style edit is covered by `e2e/screens/hot-reload.spec.ts` (item 7).
- **trigger**: the first time someone opens `pnpm dev` in a browser and edits a page.

## 2. `users.name` was `NOT NULL` in the migration while the application treated it as optional

- **status**: resolved
- **resolution**: `name` is required end to end on the owner's instruction: `UserSchema` and `UserCreateRequestSchema` require a non-blank name of at most 200 characters, the repository inserts it as given, `userRow` and the tests supply one, and a missing or blank name is a `400` naming `name` (`api.test.ts`). The migration was already `NOT NULL`. Databases created before it need `migrate:reset --up --seed`.

## 3. A failed page was answered as JSON

- **status**: resolved
- **resolution**: errors follow the path (owner's rule): under `/api` JSON, everywhere else an HTML error page (`web/pages/error.marko`, `makeErrorHandler`). `/` is now the front page (`modules/home`) and no longer a plain-text liveness answer. Consequence worth knowing: `/health` (503 while draining) and `/metrics` errors are HTML too, outside `/api`; a probe reads the status, a scraper only reads 200. If a probe ever needs the envelope, `/health` is the place to carve out.

## 4. No browser-level test

- **status**: resolved
- **resolution**: `e2e/` (Playwright Test, `pnpm e2e`, UI mode `pnpm e2e:ui`) drives Chromium against the production Node build: hydration (the `/users` filter), the page's stylesheet, the pager, the HTML and JSON error split, and the CSP (no violation on any page, an un-nonced inline script blocked). Chromium and the mobile profile were run here (18 tests); Firefox and WebKit are configured but were not installed. Not covered: the Worker build in a browser, and Vite's hot-reload socket on a style edit (item 1).

## 5. A native-addon dependency would not be traced any more

- **status**: resolved (guarded, not supported)
- **resolution**: a Node build now stops when a run-time dependency, direct or transitive, ships a native addon (`binding.gyp`, `"gypfile": true`, or a `.node` file): `builder/native.ts` (`findNativeAddons`) is called from `nodeOutput`'s `buildStart`, so `pnpm build` and `pnpm compile` both fail with the package names and the two ways out. Supporting an addon (external + copying it and its dependencies, and nothing for the executable) was left unwritten: no package exists to try it on. `tests/native_addons.test.ts` covers the detection on synthetic packages; a real build was run with a `binding.gyp` planted in `typeid-js` and failed as intended. Reading `dependencies` only: an `optionalDependencies` addon (such as `fsevents`) is not seen.
- **was**: the Rolldown builder detected native packages, kept them external and copied them into `dist/server/node_modules`; per-package chunking went with it. The Vite build inlines everything (`ssr.noExternal`), which cannot work for a package with a `.node` binary, and no step copies one. No current dependency has an addon (`node:sqlite`, a pure-JS Redis client).
- **trigger**: wanting a dependency that ships an addon. It needs `ssr.external` for that package plus a copy step in `builder/output.ts` (and `seaConfig.assets` for the executable).

## 6. Rough edges of the Vite build

- **status**: resolved, with one accepted workaround
- **resolution**: (a) the Worker build drops the server environment's unused stylesheet copy (`dropServerStyles`; `dist/worker/assets/` is gone, the pages still link `public/assets/*.css`); (c) the stale `dist/client` and `dist/ssr` were deleted, and nothing writes them any more; (d) Wrangler's debug log goes to `.wrangler/logs` unless `WRANGLER_LOG_PATH` says otherwise. (b) stays: `@vanilla-extract/vite-plugin` 5.2.6 (the latest) still sets `ssr.external`, which the Cloudflare plugin refuses, so `releaseSsrExternal` removes it for the Worker.
- **trigger**: a new release of `@vanilla-extract/vite-plugin`: try the Worker build without `releaseSsrExternal` and delete it if it passes.

## 7. Ports and the dev server, exercised in-process only

- **status**: resolved
- **resolution**: `e2e/screens/hot-reload.spec.ts` (project `Dev`, Chromium against `pnpm dev`) edits `web/styles/users.css.ts` and waits for the open page's computed colour to change with no navigation by the test. The page does not hot-swap the stylesheet: the marker the test first planted in the page was gone afterwards, so a style edit is a full reload (the pages are server-rendered, so Vite has no client module to patch). `pnpm dev` ran over a real port; touching a file under `src/` restarted the application in process (two quick touches restarted twice, one after the other) and the pages and API answered afterwards; touching `.env.example` did not restart it. `dev --mode worker` and `preview --mode worker` listen on `127.0.0.1:3000` by default (`strictPort`). `PROXY_PROTOCOL` ran against a real TCP peer: the header's address was the rate-limit key, a trusted peer without a header was dropped, and a reset in the middle of the header did not stop the server.
- **trigger**: a deployment behind a real PROXY-protocol balancer.

## 8. `wrangler.jsonc` was edited by hand after the migration

- **status**: resolved
- **resolution**: the owner's `DATABASE_AUTO_MIGRATE: "true"` is now the documented single source for the Worker's migration (the Vite config no longer overrides it); the file's header, `docs/deployment.md` and `rules.md` say so, with the race caveat and `--var DATABASE_AUTO_MIGRATE:false` for deployments once the schema exists.

## 9. `nodePreview` was not exercised

- **status**: resolved
- **resolution**: `pnpm build && pnpm preview` served pages, API and assets through the proxy on the configured port. The `X-Forwarded-For` it sets is ignored by the server unless `TRUST_PROXY` lists the loopback address, which is the intended default.
