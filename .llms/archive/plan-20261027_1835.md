# Align the TanStack Start SSR surface with the documented configuration

## Objective

Correct the misconfigured parts of the TanStack Start SSR implementation found by the audit (`.llms/audit/audit-20261027_1835.md`) and align the remaining surface with the documented configuration and the `riipandi/tanstart` reference. After this plan: page navigation is type-safe client-side routing (`<Link>`), `src/paths.ts` no longer exists, one generator owns the route tree, the generator paths cannot drift into `src/src/`, and the router carries the reference template's preload behavior. The Effect HTTP server stays the only listener; the audit's verified-correct items (plugin option shape, `ssr.nonce`, the `createStart` request middleware, the dev split, the coherent dependency set) are not touched.

## Current state (verified in the tree and by probe, 2026-10-27)

- **Plugin configuration is schema-valid.** Every key `vite.config.ts` passes to `tanstackStart()` parses against the installed `start-plugin-core@1.171.55` zod schema and matches the documented defaults; `vite.installDevServerMiddleware` is a real Vite-wrapper option consumed by `dev-server-plugin/plugin.js`.
- **The dependency set is coherent.** `react-start@1.169.4` pins the exact core versions installed (`start-client-core@1.170.39`, `start-server-core@1.169.45`, `start-plugin-core@1.171.55`, `router-core@1.171.39`). No skew to fix.
- **Two misconfigurations stand.** (1) `src/paths.ts` builds URLs as strings and its four consumers render plain `<a href>` — full document reloads, no type-safe routing; `$id.tsx` already uses `<Link>`. (2) `package.json` carries `prebuild: tsr generate` plus `@tanstack/router-cli` — the hook never fires under `vpr build` and the CLI duplicates the generator `start-router-plugin` already runs on every dev session and build.
- **The generator paths are fragile.** `routesDirectory: 'routes'` and `generatedRouteTree: 'routeTree.gen.ts'` resolve against `srcDirectory` — the trap that once wrote the tree to `src/src/`. The reference template passes absolute `resolve()` paths.
- **The router lacks the reference's preload options.** No `defaultPreload` / `defaultPreloadStaleTime`; with string-href navigation it never mattered — with `<Link>` it becomes the visible difference.
- **SSR `origin` is unverified.** `router-core` defaults the server-side origin to `http://localhost`; nothing in the tree exercises a non-localhost host yet.
- **The audit cleared the rest.** `ssr.nonce`, `createStart` + `requestMiddleware` (`src/start.ts`), the dev split (`effectVite` claims only `/api/*`, `/api-docs`, `/metrics`), the auto-declared `Register`, and the nonced stylesheet/entry tags in built HTML are all per the documented behavior.

## Decisions

- **D1 (2026-10-27): page navigation uses TanStack's `<Link>`; `src/paths.ts` is deleted.** The owner directed this ("src/paths.ts juga seharusnya tidak berlaku di tanstack start"). Navbar entries, the users list links, and the home CTA become `<Link to=...>` with typed params; no string URL builder survives. The cost: the navbar becomes a client component boundary check (it already is — it renders React) and E2E `href` assertions must still hold (`<Link>` renders the same anchor markup). Rejected: keeping `paths.ts` as a typed wrapper over route paths — it duplicates what the router's generated types already provide, and D5 forbids the shim.
- **D2 (2026-10-27): the Start plugin is the only route generator.** `prebuild: tsr generate` and `@tanstack/router-cli` are removed; `start-router-plugin` runs `router-generator@1.167.46` on dev and build. The documented CI ordering (build before check/typecheck so a clean checkout has the tree) stays and is re-verified in phase 2. Rejected: keeping the CLI "for CI" — the hook it relied on never executed.
- **D3 (2026-10-27): generator paths are absolute.** `resolve('./src/routes')` and `resolve('./src/routeTree.gen.ts')` match the reference template and remove the `srcDirectory` resolution trap. Emitted paths and imports stay identical.
- **D4 (2026-10-27): preload on intent is adopted.** The owner picked the recommendation: `defaultPreload: 'intent'` with `defaultPreloadStaleTime: 0` — the reference template's values. Phase 4 executes.
- **D5 (2026-10-27): no compatibility layer.** Deleted URL builders, deleted CLI, changed config — no re-export, alias, or dual mechanism remains. Git history is not rewritten.
