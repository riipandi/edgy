## I-1 — `vpr app serve` from source always fails page rendering with a 500

- status: resolved (71f524022)
- area: kernel (`src/kernel/renderer.ts`)
- plan: found while validating the per-request CSP nonce change (2026-10-29)
- summary: `distRoot` in `src/kernel/renderer.ts` probes `dir/server/server.js` walking up from `moduleDir` and falls back to `path.resolve(moduleDir, '../dist')`. Running from source, `moduleDir` is `src/kernel`, so the probe checks `src/kernel/server/`, `src/server/`, and `<root>/server/` — the built bundle lives at `<root>/dist/server/server.js`, which no probe step reaches — and the fallback resolves to the nonexistent `src/dist`. Every page request through the Effect renderer in source mode fails with `Cannot find module .../src/dist/server/server.js` (500). The module comment claims dev support ("up the tree from the source layout during development"), but the probe only matches once `moduleDir` is already inside `dist`, i.e. production.
- verified: production entry (`node dist/entry.js serve`) renders pages correctly; `vpr dev` serves pages through the vite pipeline (no CSP nonce in dev, pre-existing); only the source-mode `vpr app serve` page path is broken. API endpoints are unaffected in all modes.
- trigger: fix when `vpr app serve` from source needs to render pages (e.g. API+page integration testing without a build), or on the next touch of `renderer.ts`'s bundle resolution. First move: add `<root>/dist` to the probe walk (probe `dir/dist/server/server.js` alongside `dir/server/server.js`) or resolve the root from the workspace root marker instead of walking from `moduleDir`.
