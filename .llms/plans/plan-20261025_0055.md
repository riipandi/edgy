# Replace the node:sqlite driver with Turso

## Objective

The database driver becomes Turso's own stack, and Node's built-in `node:sqlite` leaves the tree:
`@tursodatabase/database` (embedded, native) for a local file or `:memory:`, and
`@tursodatabase/serverless` (SQL over HTTP, pure JS) for a remote Turso database. Both are Turso SDKs;
`@libsql/client` is never added. `src/database/dialect/sqlite.ts` is deleted and replaced by a Kysely
dialect adapted from `tursodatabase/kysely-libsql` — same shape (`SqliteAdapter`, `SqliteIntrospector`,
`SqliteQueryCompiler`, a driver whose connection executes compiled queries) with the libsql client
swapped for a Turso executor.

The configuration loses `DATABASE_DRIVER` (nothing else was ever selectable) and `DATABASE_PATH`, and
gains `DATABASE_URL` — one variable that resolves to a local database or a remote one — plus an optional
`DATABASE_TOKEN` for the remote transport.

  - Turso's own SDK matrix assigns exactly this split: local → `@tursodatabase/database`, remote Turso →

## Decisions

- **D1 (2026-10-25): two transports behind one dialect, both Turso packages, never `@libsql/client`.**
  `DATABASE_URL` selects the transport: `:memory:` and `file:…`/bare paths take `@tursodatabase/database`,
  `libsql://`, `turso://`, `https://` and `http://` take `@tursodatabase/serverless`. The cost: two
  dependencies instead of one, and a small executor adapter per transport; the benefit: the configuration
  the owner asked for (one URL, optional token) is honest — a single package cannot reach a remote
  database at all.
- **D2 (2026-10-25): the URL contract is decided in one place and fails loudly.**
  `resolveDatabaseTarget(url)` in `src/kernel/config/database.ts` returns either
  `{ kind: 'embedded', path }` or `{ kind: 'remote', url, token }`. Accepted embedded forms: `:memory:`,
  a `file:` URI (prefix stripped), or a bare path. Accepted remote forms: the four schemes above.
  Anything else — `postgres://`, `mysql://`, an empty string — is a configuration error naming the
  accepted forms, not a silent fallback to a local file. `DATABASE_TOKEN` with an embedded URL is
  ignored with one warning log line, so a token that does nothing is never silent. The cost: a URL
  with an unknown scheme no longer "just works" as a path; that is the point.
- **D3 (2026-10-25): the dialect is `kysely-libsql`'s shape over a Turso executor.**
  `src/database/dialect/turso.ts` exports `TursoDialect` (`createAdapter` → `SqliteAdapter`,
  `createIntrospector` → `SqliteIntrospector`, `createQueryCompiler` → `SqliteQueryCompiler`,
  `createDriver` → `TursoDriver`), `TursoDriver` and `TursoConnection` (`executeQuery`, `streamQuery`,
  `beginTransaction`, `commitTransaction`, `rollbackTransaction`). The connection talks to a
  `TursoExecutor`: `execute(sql, params) → { rows, insertId, numAffectedRows }`, `begin`/`commit`/`rollback`,
  `close`. The embedded executor prepares and branches on `reader` (`all` vs `run`) — in-process, so
  prepare is free; the remote executor uses the compat client's `execute({ sql, args })`, one round trip
  per statement, which is the libsql client's own contract without the libsql dependency. The cost: one
  interface and two ~40-line implementations instead of one direct client call.
- **D4 (2026-10-25): the dialect owns an async lock, because a transaction window is not a statement.**
  Turso's promise API serializes each native call, not a `BEGIN … COMMIT` span: a statement from another
  request can land inside the window and be committed or rolled back with it — the hazard the library
  itself documents for its deprecated `transaction()` helper. `TursoDriver` therefore holds one
  promise-chain mutex; `executeQuery` acquires and releases around a statement, `beginTransaction`
  acquires and holds until commit/rollback. The cost: ~20 lines, and a long transaction blocks other
  queries — which is what a single-connection SQLite already does. Rejected: `transactionAsync` (callback
  scoped; Kysely's driver API is connection scoped); no lock at all (a defect, not a design).
- **D5 (2026-10-25): the configuration is `DATABASE_URL` + optional `DATABASE_TOKEN`, and nothing else.**
  `DATABASE_DRIVER` is deleted — `choice('DATABASE_DRIVER', ['sqlite'])` described a choice that did not
  exist. `DATABASE_PATH` becomes `DATABASE_URL` (default `storage/data/app.db`, so a bare local path stays
  the default shape); `DATABASE_TOKEN` is a `secret()`. `DATABASE_AUTO_MIGRATE` is untouched. The cost:
  every deployment environment renames one variable; `.env.local` is the owner's file and is **not**
  rewritten by this plan — it is listed as a required owner edit.
- **D6 (2026-10-25): the native module stays external, and the guard learns one allowlist.**
  `--mode standalone` cannot inline a `.node` binary, so the Turso packages are excluded from `noExternal`
  and named in the leak guard's allowlist; `Dockerfile` copies the resolved
  `node_modules/@tursodatabase/**` next to `entry.js`, and the image keeps working. The cost: `dist/` is
  no longer self-contained, the README's "single file, zero native dependencies" claim is retired, and
  the image grows by the prebuilt binaries (~15 MB). Rejected: dropping standalone mode for the container
  (a bigger deployment change than the driver swap itself); the WASM build `@tursodatabase/database-wasm`
  (+43 MB, WASI-threads, browser-oriented).
- **D7 (2026-10-25): the telemetry label stays `store: 'sqlite'`.** The engine is still SQLite-compatible,
  and the label feeds the Grafana dashboards and `dependencyDuration` series. Renaming it to `turso`
  would silently empty every existing panel for no signal. The cost: the label names the engine family,
  not the npm package.
- **D8 (2026-10-25): no statement cache and no prepared-statement reuse in this plan.** The parked roadmap
  item (`.llms/roadmap/parked-unlocks.md`, "Kysely statement cache over `node:sqlite`") stays parked; the
  new dialect prepares per query exactly like the old one did. The cost: the migration is behavior-neutral
  on the query path, which is what makes it reviewable.

## Shape and enforcement points

| What                                              | Where                                                     | The record                                                                 |
| ------------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| One URL resolves to one transport                 | `src/kernel/config/database.ts`                           | an unknown scheme is an error, never a silent local file                    |
| Kysely over Turso, no `node:sqlite`               | `src/database/dialect/turso.ts`                           | the dialect is the only place that names a driver package                   |
| A transaction window cannot be interleaved        | `TursoDriver`'s lock                                      | `beginTransaction` holds the lock until commit or rollback                  |
| Migrations still run in transactions              | `src/database/migrator.ts` (`disableTransactions: false`)  | the dialect's begin/commit/rollback is exercised by every migration run     |
| The database file keeps its permissions and WAL   | `openTursoDatabase`                                       | `chmod 0600`, `foreign_keys`, `journal_mode = wal` survive the swap         |
| The container still boots                          | `Dockerfile` + `src/builder/vite-plugin.ts`                | the guard allows the Turso packages by name and nothing else                |
| Configuration is documented once                   | `docs/configuration.md`, `.env.example` (generated)        | the example file is regenerated, never hand-edited                          |
| The reasoning behind D1/D3/D4/D6                   | `.llms/architecture.md`, persistence section               | the transport split, the lock and the external-binary trap are written down |

## Execution rules

- **Atomic commit per phase** is authorized; each phase's heading names its suggested commit message;
  self-serve commits are allowed during this plan's working session.
- **Execution waits for the owner's explicit "continue with phase N".** When the phases have all landed,
  the agent stops and recommends the closing commit message with its paths — it does not commit the
  closing state on its own.
- **No backward compatibility and no legacy code** — the owner's standing waiver for this early-stage tree:
  `src/database/dialect/sqlite.ts` is deleted, `DATABASE_DRIVER` and `DATABASE_PATH` disappear, and no
  alias, fallback, or deprecation shim keeps either alive.
- **`docs/commandline.md` is out of scope** — no command changes in this plan; if a phase finds that it
  must change, the phase stops and asks.
- **Destructive commands may run only against temp databases** created under `/tmp` or a temp directory;
  the repository's `storage/` database is copied for a read-only compatibility probe and is never reset,
  dropped, or seeded. The owner's `.env.local` is never rewritten.
- **The owner's parallel work is untouchable:** `src/App.tsx`, `src/Document.tsx`,
  `src/kernel/http/api.ts`, `src/observer/tracing.ts`, `.zed/settings.json` — no phase stages or edits them.
- **Per-phase validation runs before each phase's commit.**
- **E2E is required in this plan** (the application boots on a different driver): `vpr e2e` runs in phase 3
  (call sites) and again in the final phase. If the environment cannot run it, the phase records the
  exact blocker instead of marking it n/a.

## Explicitly out of scope

- **`@libsql/client`** — never added, at any phase; `@tursodatabase/serverless` replaces it for the remote
  path.
- **Turso Sync / embedded replicas** (`@tursodatabase/sync`) — a different deployment model (local writes
  with push/pull); it needs its own plan.
- **A live Turso Cloud database** — no credentials in this environment; the remote path is validated
  structurally (fetch stub) and its failure mode probed, and that limitation is recorded rather than
  papered over.
- **Statement cache / prepared-statement reuse** — stays parked in `.llms/roadmap/parked-unlocks.md` (D8).
- **Renaming the telemetry `store` label** — `sqlite` stays (D7).
- **The Turso engine's concurrent-write features** — the application keeps one connection and single-writer
  semantics; a pool is a separate design.
- **The owner's `.env.local`** — needs a one-line edit by the owner (`DATABASE_PATH` → `DATABASE_URL`);
  the plan flags it and does not touch the file.
