# Close the 2026-10-29 audit findings — F1–F8 fixed, F5/F9/F10 parked with unlocks

Fix the seven actionable findings from `.llms/audit/audit-20261029_0421.md` (F1–F4, F6–F8), park the three documented tradeoffs (F5, F9, F10) as roadmap entries with named unlocks, and leave the tree with every audit finding at a terminal status. The sequential 409 path is already tested (`tests/routes/api/users.test.ts:179,292`); no concurrent test exists (grep for `concurrent` in that file: absent).

No malformed-cursor test exists (grep for `cursor` in the test file: only the `next_cursor: null` assertion at line 55).

- **F7** — `src/middleware/rate-limit.ts:263` falls back to the literal `'local'` when `request.remoteAddress` is absent, collapsing all such clients into one bucket.

- **F5/F9/F10** — documented tradeoffs: CORS any-origin echo (`src/middleware/cors.ts`), unauthenticated `/metrics` when enabled, best-effort cache invalidation (`src/kernel/cache.ts:145-148`, `Effect.ignore`). None has a fix trigger that has fired.
- **Audit report correction** — `.llms/audit/audit-20261029_0421.md` lines 26, 35, 51-52, 71, 81 claim F1/F2 regression tests were already added; they were not (grep-proven above). The report is corrected to "specified, lands with the plan" as part of this plan's ledger sync.

## Decisions

- **D1 (2026-10-29): F1 is fixed at the repository layer.** `user_repo.ts` catches the unique-constraint driver error on `create`/`update` and fails with `UserEmailConflict`, so the constraint's single point of truth maps to the domain error where the constraint lives; the service stays declarative. The cost the pick carries: the repo must recognize a driver-specific error shape (SQLite/Turso constraint message or code) rather than a typed error.
  Rejected: service-layer catch — leaks DB-dialect knowledge into `user_service.ts`, and every future caller of the repo would repeat it.
- **D2 (2026-10-29): F3 uses opportunistic pruning on the write path.** The token-bucket upsert deletes the key's expired rows, plus a low-probability global sweep of fully-expired rows, self-contained in `rate-limit.ts`. The cost the pick carries: every write carries a small delete cost, and pruning cadence is load-dependent (a quiet table prunes rarely).
  Rejected: periodic sweep — needs a background-job mechanism the kernel does not have yet.
  Rejected: record-only — the unbounded growth is real on every deployment, not conditional.
- **D3 (2026-10-29): F8 is fixed; F5, F9, F10 are parked as roadmap entries.** F8's fix is small and unambiguous (no secret default outside dev). F5 and F9 unlock when auth lands; F10 is consistent with the TTL design until a stronger guarantee is requested. The cost the pick carries: the CORS and `/metrics` exposures remain until auth ships — they are documented, accepted tradeoffs.
  Rejected: fixing all info items — requires auth/config decisions nobody has asked for.
