# Replace Marko with SolidJS 2 across the frontend — full migration, no compatibility layer

> Plan drafted 2026-10-18. Executes only on the owner's explicit
> "continue with phase N". No phase starts until then.

## Objective

The pages layer moves from Marko 6 templates (`.marko`) to SolidJS 2 components (`.tsx` over `solid-js/web`), rendered server-side by the existing h3 + Effect page handlers. Every Marko artifact — dependencies, builder plugins, type-check pass, test project, declarations, and the `.marko` files themselves — leaves the tree; the docs and the ledger record Solid as the renderer. h3 keeps routing, middleware and the response envelope; Effect keeps every service program; Panda CSS stays the styling system. No compatibility layer: the early-stage tree switches in one pass per phase, old code deleted in the phase that replaces it.

## Current state (verified in the tree, 2026-10-18)

- **Pages are three `.marko` files** — `web/pages/home/page.marko`, `web/pages/users/page.marko`, `web/pages/error/page.marko`, one tag `web/tags/app-shell.marko` (the full-document layout), one nested tag `web/pages/users/tags/user-list.marko` (the only interactive component: a filter input narrowing the list client-side).
- **The kernel renders through one seam.** `src/kernel/http/page.ts` declares a page as `load` (an `Effect<A, AppError, HttpEnv>`) plus `template: () => Promise<{ default: HtmlTemplate<A> }>`; `src/kernel/http/html_response.ts:1-60` renders via `template.render({ ...input, $global: { signal, cspNonce } }).toReadable()` into a streamed `Response`. The error page plugs into the same seam (`src/app.ts:41`, `src/kernel/http/error_page.ts:25`).
- **CSP is nonce-driven because of Marko.** `html_response.ts` generates a per-response nonce and allows exactly one inline script (`script-src 'self' 'nonce-…'`); its comment names Marko as the reason. `pnpm dev` also widens `style-src` and `connect-src` for Vite.
- **The builder wires Marko in three places.** `builder/edgy.ts:52` adds `@marko/vite`; `builder/node.ts:13-14` relies on Marko reading the server build to find each page's browser entries and patching that manifest into the server bundle; `builder/worker.ts:9-10` orders `buildApp` "in Marko's order" (server, then browser) and `dropServerStyles` drops per-page stylesheets the server emits; `builder/output.ts:27-29` sets the executable bit in the client build's `closeBundle` for the same Marko timing reason.
- **Typecheck runs two compilers.** `pnpm typecheck` = `tsc -b --noEmit && mtc` (`@marko/type-check`); `tsc` skips `.marko` files by design (`web/marko.d.ts` declares the module shape).
- **Component tests are one file** — `web/pages/users/tags/user-list.test.ts`, project `marko` in `vitest.config.ts` (jsdom, `resolve.conditions: ['browser']`, `tests/components_setup.ts`), using `@marko/testing-library`.
- **E2E exercises hydration and CSP through Playwright** — `e2e/screens/users.spec.ts` (filter narrows only after the page script runs), `e2e/screens/home.spec.ts` (`watchPolicy`/`injectInline`: un-nonced inline script must be blocked), `e2e/screens/hot-reload.spec.ts` (a style edit reaches an open page under `pnpm dev`), all against the production Node build via `webServer` in `playwright.config.ts`.
- **Package surface.** Runtime dep `marko@^6.4.6`; dev deps `@marko/testing-library`, `@marko/type-check`, `@marko/vite`. No `solid-js` anywhere yet.
- **The roadmap parks Marko features.** `.llms/roadmap/roadmap-20261016_0809.md` ("Marko features parked": out-of-order streaming, lazy-loading tags, patch protocol) becomes obsolete the moment Marko leaves.
- **Architecture records the earlier evaluation.** `.llms/architecture.md:25` already names Marko's selection reason and notes "Octane was too young"; this plan replaces the renderer, not the server-owned-pages design.

## Decisions

- **D1 (2026-10-18): SolidJS 2 (`solid-js@^2.0.0-rc`, RC accepted) with `vite-plugin-solid`, rendered through `renderToStream` from `solid-js/web`.** The owner explicitly accepts the RC/beta status. Solid fits the seam verified above: it is a renderer, not a router or server, so h3 keeps every routing and middleware contract; `renderToStream` returns a Web `ReadableStream<Uint8Array>` that feeds `htmlResponse`'s `Response` directly; the runtime is pure Web API, so the Worker build keeps no new Node dependency. The cost: hydration is whole-tree (no Marko-style selective hydration), so every page ships the Solid client runtime — accepted for this tree's small pages, revisited only if a page's payload becomes a measured problem.
  Rejected: staying on Marko — the owner's ergonomics requirement (JSX) is the reason the migration exists.
  Rejected: Octane / TSRX — Octane is beta with no verified Workers path inside this builder (recorded in `architecture.md`); TSRX is a new language dialect, which defeats the JSX ergonomics goal.
- **D2 (2026-10-18): the page contract keeps its shape — `load` stays an Effect, the template slot becomes a Solid component.** `definePageHandler`'s spec changes only the second field: `template: () => Promise<{ default: Component<A> }>` where the component receives `A` as props. `htmlResponse` gains a Solid adapter (`renderToStream(() => <Page {...input} />)`), keeping timeout, cancellation, tracing, error envelope and headers untouched. The cost: `$global` (signal, cspNonce) has no Solid equivalent, so `$global.cspNonce` is dropped with the inline script it served.
  Rejected: a generic renderer abstraction in the kernel — one renderer, no second consumer; an interface for one implementation is dead weight.
- **D3 (2026-10-18): the CSP nonce mechanism is deleted, not ported.** Solid hydrates from an external module script (`script-src 'self'`), so the single inline script Marko needed disappears; the policy drops `'nonce-…'` and the per-response `cache-control: private, no-cache` can relax where no other reason for it remains (measured in phase 3; `html_response.ts`'s nonce comment names Marko as the reason, and Marko will be gone). The un-nonced-inline-script-must-block E2E test stays — the policy still blocks it.
  Rejected: keeping the nonce for future inline scripts — no such script exists or is planned; YAGNI on an early-stage tree.
- **D4 (2026-10-18): one document layout — `app-shell` becomes the sole Solid layout component that owns `<html>` and includes `HydrationScript`.** Pages compose it; `renderId` stays single-root per page (no multi-root hydration need today). The `error` page keeps its own minimal layout because `html_response` must render it even when the app shell itself is broken.
  Rejected: per-page head management (`onHead`) — the layout component already owns the document; head injection machinery earns nothing at three pages.
- **D5 (2026-10-18): the browser entry moves from Marko's page-manifest patching to explicit entries.** Marko today discovers each page's browser script from the server build and patches the manifest (`builder/node.ts:13-14`). With Solid, each interactive page declares its hydration entry (a `client.tsx` beside the page calling `hydrate`) listed in Vite's `build.rollupOptions.input` for the browser environment; the page component links its built asset. The builder stops relying on Marko's manifest patch; `builder/output.ts`'s executable-bit timing and `builder/worker.ts`'s build order keep their build-app sequence but lose the Marko framing. The cost: adding an interactive page means remembering the entry — enforced by a code comment at the entry list and caught by the users E2E (no hydration → filter dead).
  Rejected: automatic entry discovery via glob at config time — magic that hides a required coupling; the explicit list is shorter than the discovery plugin.
- **D6 (2026-10-18): components are typed by their props, tested with `@solidjs/testing-library`; `mtc` and `web/marko.d.ts` are deleted.** Typecheck collapses to `tsc -b --noEmit` — JSX is ordinary TypeScript. The vitest project `marko` renames to `components` (same jsdom + `resolve.conditions: ['browser']` setup, per `rules.md` "Traps"); `tests/components_setup.ts` swaps jest-dom registration to the Solid library.
  Rejected: keeping a `marko` project name for the panel — a lying name outlives its truth.

## Explicitly out of scope

- **Solid islands / selective hydration (Marko's per-component script model)** — the owner deferred it; whole-tree hydration is accepted (D1). Trigger to revisit: a measured page payload problem or a marketing page with one widget (Solid's `NoHydration`/`Hydration` covers it without builder work).
- **Solid Start / a Solid-owned router or file-based routes** — routing stays h3; any Solid routing surface would contradict the architecture record.
- **Streaming fragments via `Loading` boundaries with Effect promises** — the current pages resolve `load` before render; the `renderToStream` streaming path is already available if a page later needs it.
- **Styling changes** — Panda CSS stays exactly as configured; the port moves class names verbatim.
- **A `solid-js` stable-bump plan** — when 2.0 leaves RC, a roadmap entry (opened in phase 7/8 if still relevant) tracks the version lift; this plan pins the RC the owner accepted.
