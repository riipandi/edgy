# Harden the Turso driver

## Objective

Close the seven findings of audit-20261025_0551, in the order their blast radius demands. The audit
found that the driver's happy paths are sound and its **failure paths** are not: a single failed
`COMMIT` ends all database access for the process, a stalled request holds the only connection
forever, and a cleartext URL ships the bearer token in the open. Each phase lands one coherent
change with the test that proves it.

The three decisions the owner made on 2026-10-25 are binding for this plan:

- **`http://` stays accepted, with one warning at boot.** A local `sqld` on loopback keeps working;
  the exposure becomes visible in the log instead of silent.
- **The remote transport is verified at open.** A `select 1` bounded by the query timeout runs when
  the database is acquired, so a wrong host or a revoked token fails the layer, not the first request.
- **The remote query timeout is 5 seconds**, matching the local busy timeout, with no new
  configuration key.

## Current state (verified in the tree and by the audit, 2026-10-25)

- `src/database/dialect.ts:66-76` — `remoteExecutor.commit` awaits `transaction.commit()` and only
  then clears the slot. The client's `commit()` closes the session in a `finally` and rethrows, so a
  failed `COMMIT` leaves a **closed** transaction installed; every later `execute` picks it and
  throws `Transaction is closed`. The same shape in `rollback`. Reproduced with a stub that fails one
  `COMMIT`: `commit failed: Transaction is closed`, then `query after the failed commit: FAILED`.
- `src/database/dialect.ts:41` — `createClient({ url, authToken })` sets no `defaultQueryTimeout`, so
  `Session.createAbortSignal` (`compat/index.js:366`) returns `undefined` and the captured request
  carries no abort signal (`{"abortSignal":false}`). `TursoConnection.executeQuery` never receives
  the caller's `signal` either, and `SqliteAdapter.supportsMultipleConnections = false` puts every
  query behind one mutex.
- `src/database/dialect.ts:236-238` — the comment promises the remote transport fails at acquire; it
  performs no I/O. Measured: acquire `0 ms`, first query failed `30 ms` later.
- `src/kernel/config/database.ts:10` — `http://` is in `REMOTE_SCHEMES` and passes through unchanged.
- `src/database/dialect.ts:113-117` — the sidecar loop covers `-wal` and `-shm`; this engine writes
  `<db>-tshm`. `storage/data/` shows `app.db` and `app.db-wal` at `0600`, `app.db-tshm` at `0644`.
- `src/database/dialect.ts:141-151` — `streamQuery` advances by `chunkSize`; `0` loops forever and
  starves the event loop (a 1-second timer never fired).
- `src/database/dialect.ts:27-35` and `:55-60` — the local executor always reports
  `insertId: BigInt(lastInsertRowid)`, so an `UPDATE` reports an earlier row's id
  (`{"numAffectedRows":"1","insertId":"42"}`); the remote executor omits it when the server sends none.
- `src/database/dialect.test.ts` — the "streams a select in chunks" spec pushes `[chunk]` into a row
  array, so it asserts row order, not chunking.

## Decisions

- **D1 — the transaction slot is cleared before the await, never after.** `commit` and `rollback`
  take the handle out of the slot first and then await it. A failure can no longer poison the slot,
  and `rollback` on an already-closed transaction is swallowed so the original error survives to the
  caller. Rejected: clearing in a `finally` — it works for `commit` but leaves `rollback`'s own
  failure able to escape as the reported error, hiding the network cause.
- **D2 — the remote transport gets a 5-second query timeout** through the client's
  `defaultQueryTimeout`. The published `Config` type does not declare it while the runtime honors it
  (`compat/index.js:366`), so the option is applied through a narrow local type rather than a cast to
  `never`. The value matches the local `timeout: 5_000`, so one number describes both transports.
- **D3 — open verifies the remote transport with one bounded `select 1`.** It runs through the
  executor, so it is subject to D2 and fails the layer with the client's own message. Rejected: a
  HEAD request or a config-only check — neither proves the token or the endpoint.
- **D4 — `http://` stays accepted and logs one warning at boot.** The message names the variable and
  says the token travels unencrypted; it is emitted by the same resolver that builds the target, next
  to the existing "token is ignored" warning. Rejected: refusing the scheme (breaks a loopback sqld)
  and silence (the risk stays invisible).
- **D5 — the sidecar sweep is driven by the database's own basename, not a fixed suffix list.** It
  narrows every file that starts with `<basename>-`, so a future engine rename cannot reintroduce the
  gap. The `-shm` entry disappears with the list.
- **D6 — `streamQuery` clamps a non-positive `chunkSize` to 1** instead of throwing. Kysely forwards
  the caller's number verbatim; a driver that pins the process on a plausible argument is the worse
  failure. The comment states that both transports buffer.
- **D7 — `insertId` is reported only for an insert.** The local executor inspects the statement's
  leading keyword; the remote executor keeps omitting the field when the server sends none. Both
  transports then agree on the shape, and no caller can read a stale rowid.

## Shape and enforcement points

| What                                            | Where                                              | The record                                                              |
| ----------------------------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------- |
| A failed commit cannot poison the connection     | `remoteExecutor.commit` / `rollback`               | the slot is empty before the await; a spec fails one `COMMIT` and queries after |
| No query can hang the process                    | `createClient` options                             | `defaultQueryTimeout: 5_000`; the spec asserts the request carries a signal |
| A bad remote URL or token fails at acquire       | `openTursoDatabase`                                | one bounded `select 1` before the Kysely instance is returned            |
| A cleartext URL is visible                       | `databaseConfig`'s resolver                        | one warning naming `DATABASE_URL` and the unencrypted token              |
| Every file the engine creates is owner-only      | `openLocal`                                        | the sweep matches `<basename>-*`, `-tshm` included                        |
| A chunk size cannot pin the event loop           | `TursoConnection.streamQuery`                      | `chunkSize` clamped to at least 1                                        |
| `insertId` means what its name says              | both executors                                     | reported for an insert only, absent otherwise                            |
| The behavior is guarded                          | `src/database/dialect.test.ts`                     | each spec fails when its behavior is reverted by hand                    |

## Execution rules

- **Atomic commit per phase** is authorized; each phase's heading names its suggested commit message.
- **Ask before changing a contract** that this plan does not name.
- **No backward compatibility**: this tree does not keep a legacy path alive.
- Destructive work: temp databases under `/tmp` only. A live Turso database is created **only** as
  `edgy-turso-probe-<stamp>` in group `default-ap`, name-checked before any destroy, and destroyed in
  the same phase. No pre-existing Turso database is ever connected to or modified.
- Tokens are never printed: read from an env var, created with `-e 1d`, and never written to a file
  that outlives the phase.
