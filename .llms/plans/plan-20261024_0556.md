# Delete the dead code and duplicated test scaffolding — D9 of the 2026-10-23 deep sweep

## Objective

Close the last open item of the deep sweep (issue-20261023_0701, finding D9): the tree carries
empty scaffolds, a duplicated shutdown helper, unused config type aliases, a duplicated test
config literal, a pointless fixture alias, and five unused devDependencies. After execution the
kernel/config/test surfaces contain only consumed code, the dependency list names only used
packages, and no test harness registers matchers nothing uses. The plan does not add behavior,
touch public HTTP surfaces, or re-introduce any compatibility shim.

## Current state (verified in the tree, 2026-10-24)

- **Three empty scaffolds with no importer.** `src/kernel/http/responder.ts`,
  `src/kernel/http/validator.ts`, and `src/kernel/pagination.ts` each contain exactly
  `export default {}`; a grep for `responder`, `http/validator`, and `kernel/pagination` over
  `src/`, `tests/`, and `e2e/` returns no importer outside the files themselves.
- **`awaitShutdownSignal` exists twice, verbatim including its comment.** `src/kernel/graceful.ts:8`
  exports it (`Effect.callback` over `SIGINT`/`SIGTERM` with an off-in-finalizer return);
  `src/command/serve.ts:23` carries a private copy of the same body, while serve.ts imports only
  `gracefulServerLayer` from that module.
- **Six config type aliases have no consumer.** `CacheConfig` (`src/kernel/config/cache.ts:12`),
  `DocsConfig` (`docs.ts:14`), `SecurityConfig` (`security.ts:111`), `ServerConfig` (`server.ts:11`),
  `LoggingConfig` (`logging.ts:30`), and `ObservabilityConfig` (`observability.ts:30`) are each
  referenced only by their own definition line and by the re-export block at
  `src/kernel/config/config.ts:48-50`. `telemetryEnabled` (`observability.ts:27`, re-exported at
  `config.ts:50`) has no consumer at all. One constraint: `LogFormat` (`logging.ts:31`) is consumed
  by `src/observer/logger.ts:5` and derives from `LoggingConfig['format']`, so it survives by
  deriving inline from `loggingConfig` instead.
- **The `AppConfigShape` literal is duplicated.** `src/modules/user/user_service.test.ts:11-45`
  spells out the full config object; `tests/fixtures/config.ts:5-40` spells out the same object.
  The only difference is `cache.maxEntries` — 16 in the test (to exercise eviction), 256 in the
  fixture. The fixture already exposes the override pattern (`limitedConfig` spreads `config`).
- **`testServices = testService` is a pure alias.** `tests/fixtures/users.ts:44`; six test files
  import `testServices`, nothing imports `testService` directly.
- **Five devDependencies are unused and jest-dom is registered for nothing.** No file under
  `src/`, `tests/`, `e2e/`, `vite.config.ts`, or `.storybook/` references
  `@solidjs/testing-library`, `@vitest/browser-playwright`, `@solidjs/diagnostics`,
  `@solidjs/start-devtools`, or `@testing-library/jest-dom` matchers; `vitest-setup.ts` contains
  only the jest-dom registration and is wired at `vite.config.ts:124` (`setupFiles`). The
  `@vitest/browser-playwright` catalog entry in `pnpm-workspace.yaml:20` becomes unreferenced with
  the package removal. (`@solidjs/diagnostics` also appears commented-out in the catalog — the
  comment line stays.)

## Decisions

- **D1 (2026-10-24): delete, never shim — per the owner's standing waiver.** The tree is early
  stage; scaffolds and duplicates go outright, no re-export stubs keep old import paths alive.
  Rejected: keep the six aliases "for future consumers" — the grep proves zero consumers today,
  and a new consumer can add the alias when it exists.
- **D2 (2026-10-24): `LogFormat` survives by deriving inline** — `export type LogFormat =
  ValueOf<typeof loggingConfig>['format']` in `logging.ts` — so the consumed export stays and the
  unconsumed `LoggingConfig` alias goes. Rejected: keep `LoggingConfig` as the base of `LogFormat`
  — it keeps an unused public alias alive to save one line.
- **D3 (2026-10-24): the user-service test keeps its own `maxEntries: 16` via the fixture's spread
  pattern** — `Layer.succeed(AppConfig, { ...config, cache: { ...config.cache, maxEntries: 16 } })`
  — the same shape `limitedConfig` already uses, so the eviction intent is visible at the test and
  a new config key no longer breaks two literals. Rejected: point the test at the fixture as-is —
  it would silently weaken the eviction test.
- **D4 (2026-10-24): `testService` is renamed to `testServices` at the definition** — the six
  consumers already say `testServices`; the singular name was the export nobody used. Rejected:
  keep both names — the alias is the finding.
- **D5 (2026-10-24): `vitest-setup.ts` is deleted together with its `setupFiles` line** — its only
  content is the jest-dom registration, so an emptied file would be one more scaffold of the kind
  this plan removes. Rejected: keep the file with a placeholder comment — same reason.
