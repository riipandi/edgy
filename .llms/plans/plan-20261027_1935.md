# Adopt TanStack Query, the devtools panel, and a global error boundary

## Objective

Bring the page surface to the `riipandi/tanstart` reference shape for data and developer tooling: TanStack Query owns page data under the router context (SSR-dehydrated), the unified TanStack devtools panel runs in development, and a generic global error boundary replaces Start's default error surface. StyleX stays as-is — it is already at reference parity. The refactor deletes the pre-Query loader scaffolding it replaces. The Effect HTTP server, `/api/*`, the `x-cache` bridge, and the nonce CSP are untouched.

## Current state (verified in the tree, 2026-10-27)

- **StyleX is at reference parity.** `useCSSLayers: { before: ['reset'], prefix: 'stylex' }`, `enableDevClassNames`, the dev-only `/virtual:stylex.css` link and runtime script in `__root.tsx`, and the build-time extraction with `assets/stylex.css` dedupe all match the reference's wiring. Nothing to implement; only preservation through the refactor.
- **`defaultPreloadStaleTime: 0` already landed** (plan `plan-20261027_1835`, phase 4) — the pinned `router-query` skill names it a critical prerequisite for Query-driven freshness.
- **No Query, no devtools, no error boundary.** `package.json` has no `@tanstack/react-query`; `__root.tsx` registers no `errorComponent`; rendering defects reach Start's default error surface (the M4 leak surface, currently mitigated only at the loader layer).
- **The `import-protection` warning is reproduced.** `setResponseStatus` is called inside the isomorphic loaders of `src/routes/(app)/users/$id.tsx:44` and `src/routes/$.tsx:13`; the client pass warns in `vpr dev` (4× when client modules load) and in `vpr build` (4×) even though `behavior.build: 'mock'` — the mock silences nothing. The plugin's `isCompilerSafeBoundaryCall` treats usage inside `createIsomorphicFn().server(...)` as a compiler-safe boundary, so the sanctioned fix moves the call into such a boundary.
- **Peers resolve.** `react-router-ssr-query@1.167.3` wants `react-router >=1.170.33` (1.170.46 ✓); `react-router-devtools@1.167.2` wants `router-core ^1.171.30` (1.171.39 ✓); `devtools-vite@0.8.5` wants vite 6–8 ✓. `minimumReleaseAge: 1440` applies — installs resolve to versions older than 24h, so exact patches may lag latest; the peer ranges above are what matter.
- **The pinned `router-query` skill sets the contract:** `QueryClient` is created **inside** `getRouter()` (a module-level singleton leaks data between SSR requests), the router gains `context: { queryClient }` and `Wrap`, `setupRouterSsrQueryIntegration({ router, queryClient })` handles dehydration/hydration/streaming, and the recommended data pattern is a static query in the loader plus `useSuspenseQuery` in the component.
- **Reference deviations to make deliberately:** the reference's `GlobalError` prints `error.message` — ours must not (the M4 leak); the reference renders `<DevTools>` unconditionally and hands it a fresh `QueryClient` from a second `getContext()` call — ours renders it only in development and must show the router's actual client.

## Decisions

- **D1 (2026-10-27): static query in the loader, `useSuspenseQuery` in the component.** The owner picked the recommended pattern. Loaders run `context.queryClient.query({ ...queryOptions, staleTime: 'static' })`; components subscribe with `useSuspenseQuery` for cache updates. SSR dehydration and client hydration ride `setupRouterSsrQueryIntegration`. Rejected: `useSuspenseQuery`-only without loaders (loses prefetch-on-intent) and Query-as-client-cache-only (dual source of truth).
- **D2 (2026-10-27): a missing user answers `null` and keeps the inline not-found body.** The owner picked behavior preservation: `queryFn` maps the server function's `undefined` to `null` (serialization drops a top-level `undefined`), the loader still answers 404 during SSR, and the component still renders the not-found copy inside the shell. Rejected: throwing a not-found error into the error boundary — it would change the UX and break the existing E2E assertions.
- **D3 (2026-10-27): the root route becomes `createRootRouteWithContext<{ queryClient }>` with `shellComponent: RootDocument`.** The owner picked full reference alignment. The document shell stays mounted across match transitions; the `GlobalContext` type lives beside the provider. Rejected: keeping the plain `component` idiom — Query forces the context, and half-aligning keeps two idioms in one file.
- **D4 (2026-10-27): the devtools follow the owner's tanstart example, with two deliberate deviations.** `@tanstack/react-devtools` unified panel with the Query and Router devtools as plugins, configured like the reference (`position: 'bottom-left'`, `urlFlag: 'devtools'`, hotkeys), plus `@tanstack/devtools-vite` in the Vite plugin chain. Deviations: (1) the panel renders only when `import.meta.env.DEV` — the reference renders it unconditionally, and the production bundle must not ship devtools code; (2) the panel receives the router's actual `QueryClient`, not a second client from a fresh `getContext()` call (the reference hands the panel a client that never receives queries).
- **D5 (2026-10-27): the global error component is generic.** It renders the reset action and a back-home link but never the error message — the M4 finding showed Start's default surface prints internal messages, and the reference's `error.message` display would reintroduce that leak. The loader-level masking stays: the loader logs the real cause server-side and throws a safe message that the boundary can display.
- **D6 (2026-10-27): the catch-all `$.tsx` stays; only `errorComponent` is registered.** The catch-all is a real route with a real URL and sets the 404 status in its loader; `notFoundComponent` would lose that. The owner picked this.
- **D7 (2026-10-27): no compatibility layer.** Replaced loader scaffolding (`Route.useLoaderData` annotations, the type-cycle comment, the `userTitle` shape if it changes) is deleted in the phase that replaces it. Git history is not rewritten.

## Phases

1. **Query foundation under the router context** — Install `@tanstack/react-query` and `@tanstack/react-router-ssr-query`. Create `src/provider.tsx` with the `GlobalContext` type (`queryClient: QueryClient`), `getContext()`, and `RootProvider`. In `src/router.tsx`: create the `QueryClient` inside `getRouter()`, pass `context: { queryClient }` and `Wrap: RootProvider`, and call `setupRouterSsrQueryIntegration({ router, queryClient })` before returning. Rewrite `__root.tsx` to `createRootRouteWithContext<GlobalContext>()` with `shellComponent: RootDocument` — the shell keeps the StyleX wrapper, the dev StyleX links, and `HeadContent`/`Scripts`. Pages stay untouched this phase. Validation: `vpr check`, `vpr typecheck`, `vpr test` (304/304), `vpr build`, and a built-server probe (pages 200, `x-cache`, 404s) — rendering is unchanged. _Commit: `feat(web): put TanStack Query under the router context`._

2. **Global error boundary** — Create the error boundary component (StyleX-styled, in `src/resources/components/` or a `src/routes/-boundaries.tsx` dash file): generic copy ("Something went wrong"), a reset action wired to the router's `errorComponent` reset, and a back-home `<Link>`. It never renders the error message. Register it as `errorComponent` on the root route. Validation: `vpr check`, `vpr test`, `vpr build`, probe green. The boundary's runtime behavior is exercised by phase 4's loader masking path — this phase only registers it. _Commit: `feat(web): register a generic global error boundary`._

3. **Server-only status helper** — Add a tiny isomorphic wrapper (e.g. `src/kernel/ssr_status.ts`, `createIsomorphicFn().server((status: number) => setResponseStatus(status))` importing from `@tanstack/react-start`). Replace the direct `@tanstack/react-start/server` imports and calls in `src/routes/(app)/users/$id.tsx` and `src/routes/$.tsx`. Validation: `vpr dev` with a client-module fetch produces zero `import-protection` warnings; `vpr build` log contains none; the built-server probe still answers 404 for unknown id, malformed id, and unmatched path. _Commit: `fix(web): keep the 404 status helper out of the client bundle`._

4. **Pages on TanStack Query** — Create `src/modules/identity/user/user_queries.ts` (client-safe): `usersQueryOptions` (`queryKey: ['users']`, `queryFn: listUsers`) and `userQueryOptions(id)` (`queryKey: ['users', id]`, `queryFn` calling `getUser` and mapping a missing user to `null`). Rewrite both pages: the users list loader awaits the static query and the component reads `useSuspenseQuery`; the detail loader awaits its static query, calls the status helper when the result is `null`, returns the payload for `head`'s title, and keeps the log-then-safe-throw catch; the detail component reads `useSuspenseQuery` and renders the not-found copy for `null`. Delete the now-obsolete `Route.useLoaderData` annotation, the type-cycle comment, and the `userTitle` `undefined` branch if the types no longer need it. The `x-cache` bridge is untouched — `fetchUserPage` still records the verdict during SSR. Validation: `vpr check`, `vpr test`, `vpr build`, built-server probe (detail title, `x-cache: hit`/`bypass`, unknown id 404 with the not-found body, users list), and `vpr e2e --project Chromium` 8/8 without spec edits. Confirm the SSR HTML carries the dehydrated query payload. _Commit: `feat(web): serve page data through TanStack Query`._

5. **Devtools panel in development** — Install `@tanstack/react-devtools`, `@tanstack/react-query-devtools`, `@tanstack/react-router-devtools` (dev dependencies) and `@tanstack/devtools-vite`. Add `devtools()` to the Vite plugin chain before `tanstackStart` (taking the `uiPreview` gate if Storybook breaks). Create `src/routes/-devtools.tsx` mirroring the reference panel (position, hotkeys, `urlFlag: 'devtools'`, Query and Router plugins) but receiving the router's `QueryClient` through the root route context — verify the panel shows the router's queries, and if the shell component cannot reach the context, thread it through a component that can. Render it from `RootDocument` only when `import.meta.env.DEV`. Validation: `vpr dev` serves the panel (a browser or E2E probe opens `/` and the devtools mount); `vpr build`'s client bundle contains no devtools identifiers (grep); `vpr storybook:build` green. _Commit: `feat(web): add the TanStack devtools panel in development`._

6. **Clean sweep** — Search the tree for the replaced scaffolding and any drift: `useLoaderData`-based annotations that lost their purpose, comments describing the loader-only data path, unused imports the migration left behind, and any module-level `QueryClient`. Delete what the Query phases made obsolete. Also verify `getContext()` is called only inside `getRouter()` (per-request client, no second call site). Validation: the sweep grep returns no live hits; `vpr check`, `vpr typecheck`, and `vpr test` green. _Commit: `refactor(web): drop the pre-query loader scaffolding`._
