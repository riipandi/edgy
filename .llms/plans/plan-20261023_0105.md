# Adopt Effect v4 surfaces and retire the workarounds — tracing, metrics, trust proxy, Redis rate limiting, cache policy, static serving, HttpApi, healthcheck

## Objective

The 2026-10-22 Effect audit found the tree idiomatic for Effect 4.0.5 but leaving several shipped surfaces without their framework counterpart: OTLP tracing configured yet no request spans, an unlabeled request counter, a proxy-blind rate limiter, a failure-pinning cache, hand-rolled static file serving, a dead `healthcheck` stub, and hand-routed API contracts. This plan lands the framework features (HttpApi, HttpStaticServer, HttpMiddleware.tracer/xForwardedHeaders, effect/persistence RateLimiter with Redis, Metric attributes) and repairs the error-channel violations. After the plan: the wire contract is defined once in `HttpApi`, request spans flow to the OTLP collector, the rate limiter can run per-IP shared across instances via Redis, and no scaffold or shim remains where a v4 primitive exists.

## Current state (verified in the tree, 2026-10-23)

- `Effect.promise` wraps failable work in `src/command/serve.ts` (`migrateToLatest`, `runSeeders`), `src/command/migrate-up.ts`, `migrate-down.ts`, `migrate-reset.ts` (loop of `migrateDownStep`), `migrate-status.ts`, `migrate-seed.ts`, `src/builder/vite-plugin.ts` (`migrateAndSeed`), `src/kernel/renderer/solid.ts` (`loadBundle`). A rejection becomes a defect; `Effect.promise` doc (`node_modules/effect/src/Effect.ts:1366`) names `tryPromise` as the failure-aware variant.
- `OtlpTracer.layer` is provided by `TelemetryRuntimeLayer` (`src/observer/tracing.ts`), but `HttpMiddleware.tracer` (`node_modules/effect/src/http/HttpMiddleware.ts:251`) is applied nowhere (absence claim: grep for `tracer` across `src/` finds no HTTP wiring), so no server span is ever created and incoming `traceparent` headers are ignored.
- The request counter has no attributes (`src/observer/metrics.ts:4-7`); `requestLog` (`src/middleware/request-log.ts`) logs `method path status duration` but records none of it on the metric.
- The rate limiter keys on `request.remoteAddress` (`src/middleware/rate-limit.ts:56`) with process-local Maps; proxy headers are not honored. The built-in `HttpMiddleware.xForwardedHeaders` (HttpMiddleware.ts:319) rewrites `remoteAddress` from `X-Forwarded-For` **unconditionally** — no trust gating — so it cannot carry the pocket-id trust-list semantics on its own. Multi-instance deployments cannot share counters (recorded in `.llms/architecture.md`, "Operational limits"). The migration `src/database/migrations/00004_rate_limits_table.ts` already ships the persistent store: `rate_limits(key, window, count)` with primary key `(key, window)` and an index on `window` for expired-entry cleanup.
- `Cache.make` caches lookup failures for the full TTL (`src/modules/user/user_service.ts:21-25` + `node_modules/effect/src/Cache.ts:340-342`: "failed lookups are cached and will fail again until the entry expires").
- Static files are hand-rolled in `src/kernel/renderer/solid.ts` (six-entry MIME map, manual traversal guard, no ETag/304/byte-range/cache-control); `HttpStaticServer` (`node_modules/effect/src/http/HttpStaticServer.ts:72-216`) provides all of it and fails missing files with an `HttpServerError` whose reason is `RouteNotFound` (`HttpStaticServer.ts:197-204`).
- `src/command/healthcheck.ts` is a stub (`export default {}`), not registered in `src/command/cli.ts`; the only reference is a commented `HEALTHCHECK` block in `Dockerfile:85-87`. `compose.yaml` healthchecks are HTTP-based and belong to the collector, not this app.

## Decisions

- **D1 (2026-10-23): migrate the API surface to HttpApi server-side — HttpApiEndpoint definitions, HttpApiBuilder handlers, error→status via HttpApiSchema, tests rebuilt around the contract.** The owner picked full migration over deferral; the wire contract (paths, statuses, envelopes) becomes defined once and type-checked, which is the blueprint's job. The cost the pick carries: the largest diff of the plan (handlers, module composition, 11 route tests, dev/prod handler parity), and response envelopes/statuses may shift where HttpApiSchema maps errors differently than the manual `catchTag` responses did — the test matrix and `docs/api-endpoint.md` are the safety net.
  Rejected: defer to a later plan — the owner explicitly chose full migration; deferring leaves the manual router and a contract definition drifting apart.
  Rejected: browser-side `HttpApiClient` — it pulls an Effect runtime into the client bundle; `user_fn.ts` keeps a small typed fetch wrapper (bundle budget first, adoption is a separate unlock). Registered below in out-of-scope.
- **D2 (2026-10-23, corrected by the owner): trust proxy follows the pocket-id `TRUST_PROXY` concept.** `TRUST_PROXY` is a string config: `false` (default) trusts no proxy, `true` trusts every address, otherwise a comma-separated list of proxy IPs or CIDR ranges (parsed with `node:net`'s `BlockList`, which covers IPv4 and IPv6). The built-in `HttpMiddleware.xForwardedHeaders` trusts unconditionally, so the plan adds a small `trustProxy` middleware instead: when the direct peer address is trusted, the client IP is the rightmost `X-Forwarded-For` entry that is not itself a trusted proxy (with `X-Real-IP` as fallback); otherwise the direct peer address stands. Rate limiting and the access log consume the resolved address. Cost: a misconfigured list silently falls back to proxy IPs — the docs state the exact list format.
  Rejected: plain boolean flag — the owner corrected this to the pocket-id list semantics (spoofing control per proxy).
  Rejected: `HttpMiddleware.xForwardedHeaders` as-is — trusts every sender.
  Out of scope, pocket-id's other proxy knobs: `TRUSTED_PLATFORM` and `PROXY_PROTOCOL` (no platform requirement in this tree).
- **D3 (2026-10-23, corrected by the owner): the rate-limit store is a two-choice config — `RATE_LIMIT_STORE` = `database` (default) | `redis`; the memory mode is dropped.** `database` persists the fixed window in the existing `rate_limits` table (`key`, `window` bucket stamp, `count`) through the `Database` service: one upsert (`on conflict do update set count = count + 1`) per consume plus an indexed delete of expired windows; counters survive restarts and are shared by processes pointing at the same SQLite file. `redis` wires `NodeRedis` (connection URL in `RATE_LIMIT_REDIS_URL`, default `redis://localhost:6379`) → `RateLimiter.layerStoreRedis` → `RateLimiter.consume` fixed-window. Both backends expose one contract — consume(key, max, window) → allowed + `RateLimit-*` headers — so the middleware and its tests stay store-agnostic. Cost: in redis mode the boot requires Valkey/Redis reachable (layer build fails otherwise); in database mode every request performs a SQLite write (WAL keeps it cheap for the blueprint's scale).
  Rejected: keeping the in-process memory limiter as a third mode — the owner dropped it; `00004_rate_limits_table.ts` exists precisely for the persistent path.
- **D4 (2026-10-23): implement `app healthcheck` as a readiness CLI — ping the `Database` service with a bounded timeout, exit 0 on success, non-zero on failure — and register it in the CLI.** It backs the commented `Dockerfile` HEALTHCHECK. Cost: the container probe conflates process liveness with database readiness; accepted for the single-process SQLite topology this blueprint serves.
  Rejected: delete the stub — the owner picked implement; the commented Dockerfile block shows the intent was always a container probe.
- **D5 (2026-10-23): serve static files through `HttpStaticServer` and reduce `renderPage` to the Solid handoff.** Mount at the catch-all route: GET/HEAD requests hit the static app first, a `RouteNotFound` failure delegates to the SSR effect; the explicit `/` SSR route stays (no `index.html` takeover of the dynamic home page). Cost: one static `cacheControl` policy for all assets (hashed filenames make an immutable-ish policy safe); MIME coverage moves to the framework's table.
  Rejected: keep the hand-rolled branch — it is a partial reimplementation of a stable v4 module with fewer features and its own traversal logic to maintain.
- **D6 (2026-10-23): `HttpMiddleware.tracer` becomes a global router middleware in both composition roots** (`src/kernel/http/serve.ts` and the dev `apiHandler` in `src/kernel/http/api.ts`), so prod SSR and API requests and the dev `/api` path all produce spans and propagate W3C context. Cost: one span allocation per request even with telemetry disabled (dropped by the native tracer) — accepted as negligible.
- **D7 (2026-10-23): the request counter gets bounded attributes — `method` and a status class (2xx/3xx/4xx/5xx) — plus a request-duration histogram.** Bounded classes keep label cardinality flat. The exact dynamic-attribute mechanism comes from the `Metric` module's attribute helpers (verified at implementation; the module exposes attribute composition at `node_modules/effect/src/Metric.ts:1038` area).
- **D8 (2026-10-23): cache failures are no longer pinned.** The user lookup wraps `Cache.get`; on a failed exit the entry is invalidated (`Cache.invalidate`) and the failure propagates — the next request retries the lookup instead of replaying the stale failure until TTL. Cost: a sustained outage hits the lookup on every request instead of a cached failure (no TTL-throttled retry) — accepted; the limiter upstream already shapes that load.
- **D9 (2026-10-23): every `Effect.promise` call site becomes `Effect.tryPromise`** with a caught rejection mapped into a named error, while the existing `result.error !== undefined` checks stay for Kysely's result-object failures.

## Execution rules

- **Atomic commit per phase** is authorized; each phase's heading names its suggested commit message; self-serve commits are allowed during this plan's working session.
- **Execution waits for the owner's explicit "continue with phase N".** When the phases have all landed, the agent stops and recommends the closing commit message with its paths — it does not commit the closing state on its own.
- **Early-stage grant (owner, 2026-10-23): no backward compatibility, no legacy shims, no deprecation windows.** Kysely migrations may be edited in place; a database reset is allowed only when the owner asks for it in the same turn. The app never writes outside `storage/` during probes.
- **The owner's parallel work is untouchable:** nothing outside `src/`, `tests/`, `docs/`, `Dockerfile`, `compose.yaml`, `.env.example`, `package.json`, and `.llms/` without naming it first.
- **Per-phase validation runs before each phase's commit.**
- **E2E only when relevant** — Playwright runs when a phase touches a page route; recorded n/a otherwise, never skipped silently.
