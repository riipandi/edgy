# Contracts and change rules

## Contracts

- `ApplicationLayer` in `src/kernel/layers.ts` composes domain feature services over `DatabaseLayer`. Feature modules never import `DatabaseLayer` directly.
- `serve --auto-migrate` applies pending database migrations before starting the HTTP listener. `DATABASE_URL` is the sole switch between SQLite transports: `file:` (or bare path) selects `@tursodatabase/database` with multiprocess WAL; `libsql://`, `turso://`, `https://`, or `http://` selects `@tursodatabase/serverless` over HTTP with mandatory `DATABASE_TOKEN`. `:memory:` is rejected at startup because external commands (`healthcheck`, `migrate:up`) run in separate OS processes and require shared disk access.
- Remote Turso connections are verified at acquisition with a `SELECT 1` pre-flight query and bounded by a 5-second query timeout. The remote executor uses a single HTTP session stream and clears transaction slots before awaiting, preventing connection poisoning on failed commits.
- Feature domain services depend on repository interfaces. Implementations live inside feature modules (`src/modules/<name>/<feature>_repo.ts`) and execute queries using Kysely over the `Database` service. HTTP handlers must not construct database queries directly.
- Feature schemas augment the empty `Database` interface in `src/database/schema.ts` via declaration merging.
- Security headers are applied globally by `src/middleware/security-headers.ts` (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`); a response that already carries a CSP keeps it and still receives the other three headers, and the docs layer passes its own `docsCspFor()` fallback. SSR page responses override CSP with a per-process TypeID nonce (`script-src 'self' 'nonce-...' 'strict-dynamic'`). Fonts are self-hosted via `@fontsource-variable/*` in `src/assets/fontface.css`; no external font origins are permitted.
- CORS is configured globally via `src/middleware/cors.ts`. `CORS_ENABLED` controls activation (default `true`); `CORS_ALLOWED_ORIGINS` specifies allowed origins (default `*` internally echoing caller with credentials).
- Request metrics use strictly bounded label values: `http_requests{method, status_code, route}` and `http_request_duration_seconds{method, route}`. Method maps unknown methods to `OTHER`; status codes are exact numbers; route is the matched HttpApi route template or `page`/`unmatched`.
- Access logging has one owner: `request-log` (`src/middleware/request-log.ts` and, for dev page traffic, `src/middleware/dev-access-log.ts`). The framework's built-in response record is disabled (`disableLogger: true` on `HttpRouter.serve` and the dev `toWebHandler`), so every request emits exactly one access line plus one metric update through the shared `recordAccess`/`recordAccessFailure` core. Quiet paths (`/.well-known/appspecific/com.chrome.devtools.json` exact, `/favicon`, `/apple-touch-icon`, `/assets/`, `/_serverFn/`, `/__tsd/`, `/metrics` exact) are silent on success — no line, no metrics — but a quiet-path failure still logs a WARN with its cause and records the metric. Client disconnects (interrupts tagged `ClientAbort`) are neither logged as errors nor recorded as `500`s. Dev page requests carry the same shape through the Start-side middleware, which runs under the DEV guard only and skips Effect-owned paths (`/api/*`, `/metrics`, `/api-docs`).
- Log sinks must degrade, never defect: the batched stdout sink falls back to `stderr` when a write fails and always resumes its flush callback (`src/observer/logger.ts`).
- Log message phrasing: Initial word is capitalized for narrative logs (`Database connected`, `No pending migrations`); data-first records maintain data at head (`GET /api/users 200 7ms`).
- Dependency telemetry measures duration via `dependency_duration_seconds{store, op}` with bounded `store ∈ {sqlite, redis}` and fixed `op ∈ {query, read, ping, cache-get, cache-invalidate, rate-limit-consume}`. Metric labels and trace attributes must never include SQL queries, cache keys, or table names.
- `/api/health` implements the alexliesenfeld/health contract: concurrent probes under a shared 2-second budget returning `{"status":"ok"|"unhealthy","details":{...}}`. Health responds with `200` on complete health or `503` upon any component failure. It is exempt from API response envelopment and rate limiting. The `healthcheck` CLI executes the exact same core checks and exits with `0` or `1`. An unhealthy body names the failing dependency with a stable `error: "unavailable"` code; the raw failure detail goes to the server logs, never the response.
- Graceful shutdown (`src/kernel/graceful.ts`) handles `SIGINT`/`SIGTERM` directly: drops idle connections immediately, gives in-flight requests a bounded drain window (`drainTimeout`, default 10 seconds) before closing remaining sockets, then closes database and Redis pools in sequence and exits `0`. A subsequent signal forces immediate exit with status `128 + signum`.
- Positional CLI parsing in `src/command/root.ts` inspects the first non-flag argument (`subcommandOf`), selecting server runtime or one-shot execution without detaching finalizers. Global flags are canonical instances (`--help`, `--version`, `--log-level`).
- Database migrations (`migrate:up`) are strictly forward-only: `--to <name>` rejects already-applied targets. Rollbacks require `migrate:down --count <n>` or `migrate:reset`.
- One-shot CLI commands output colored step reports via `src/command/helper.ts` (cyan running, green success, yellow dry-run). Log filtering (`--log-level`) does not silence command console reports.
- `generate:config` enforces symbolic-link safety and prevents accidental overwrite of active `.env` files. `--check` validates currency in CI without modifying files.
- `NODE_ENV` (`development`|`test`|`production`, default `development`) is a validated config field. When `NODE_ENV=production`, telemetry is enabled, and `OTEL_EXPORTER_OTLP_HEADERS` still equals the development default, boot fails with a named error — the dev ingestion key must never ship.
- Response envelopes: Every `/api/*` endpoint (except `/api/health`) conforms to `.llms/api-response.md`. Success returns `{status: "success", data?, message?, metadata, links?}`; error returns `{status: "error", message, error: {code, retryable, details?, debug?}, metadata}`.
- Errors under `/api/*` map to generic tagged error classes in `src/kernel/http/errors.ts` (`ApiValidationError`, `ApiNotFoundError`, `ApiConflictError`, `ApiRateLimitedError`, `ApiInternalError`, `ApiServiceUnavailableError`). Handlers supply call-site error codes (e.g. `USER_NOT_FOUND`, `EMAIL_CONFLICT`).
- All unhandled defects under `/api/*` are intercepted by `src/middleware/error-response.ts` and reshaped into the standard `ErrorEnvelope`. Database failures return sanitized `503` with code `DATABASE_ERROR` without exposing SQL or connection details.
- Unique-constraint violations map to conflicts at the repository layer: `user_repo.ts` matches the SQLite cause chain (`isEmailTaken`) and raises `UserEmailConflict`; the service's existence pre-check is a fast path, not the authority. Handlers translate it to `409 EMAIL_CONFLICT`.
- Cursor pagination query parameters (`limit`, `cursor`, `sort_by`, `sort_order`) are standardized in `src/kernel/http/pagination.ts`. Cursors are opaque base64url JSON strings encoding keyset values; `decodeCursor` rejects null, arrays, empty objects, and wrongly typed values as invalid. Invalid cursors trigger `400 INVALID_CURSOR`.
- Interactive API documentation (`/api-docs` via Scalar) and OpenAPI spec (`/api/openapi.json`) are served only when `API_DOCS_ENABLED=true`.
- Rate limiting enforces a token-bucket algorithm with continuous refill (`refillRateMillis = window / limit`). Counters persist to the `rate_limits` table or Redis (`REDIS_ENABLE=true`). Outages fail closed with `503 DATABASE_ERROR`. Exclusions (`/api/health`) are prefix or exact matches. Bucket keys attribute to the client socket address, falling back to the `x-forwarded-for` header, then `local`. Expired rows are pruned opportunistically on the write path (every 20 consumes) — no background sweeper.
- Standalone builds (`vpr build:standalone`) inline all JavaScript dependencies into `dist/entry.js` and verify zero bare external package imports remain. The Turso native binding is copied to `dist/node_modules/` for the host platform.
- Standalone builds automatically generate `dist/oxfile.toml` for OxMgr cluster process supervision (`cluster_mode = true`, `cluster_instances = 4`). Clustered deployments must execute migrations prior to starting workers.
- Pages are TanStack Start file routes under `src/routes`, imported through the generated `src/routes.gen.ts` (gitignored). The Start plugin owns route-tree generation (`start-router-plugin` runs on every dev session and build) — no CLI generator exists. Both `router.routesDirectory` and `router.generatedRouteTree` in `vite.config.ts` are absolute `resolve()` paths because the generator resolves its values against `srcDirectory`, and the generator's `tmpDir` is pinned to `.output/tanstack` so no `.tanstack/` directory appears at the repo root. The generator rewrites the tree only when its computed content changes, so its mtime is not a freshness signal. CI must run `vp run build` before `vp run check` and `vp run typecheck` so a clean checkout has the declaration.
- The Effect listener stays the only listener. In production `src/kernel/renderer.ts` imports the built Start server bundle and calls its default `fetch(request)`; in `vpr dev` Start's own middleware renders pages inside Vite. Start's plugin set must not claim `/api/*`, `/api-docs`, or `/metrics`.
- Internal page navigation renders `<Link>` from `@tanstack/react-router` with typed `to` and `params` — never a hand-rolled URL builder or a string `href`. External links stay plain `<a>`. Active-state styling computes from `useLocation` alongside `aria-current`.
- Page data crosses the client boundary only through `createServerFn`: `src/modules/identity/user/user_fns.ts` holds the client-safe wrappers, `user.server.ts` holds the `UserService` handlers (resolving the request-scoped `AsyncLocalStorage` context and reading `nocache` via `getRequest()`). `/_serverFn` is Start's internal dispatch path, not a public API — the public contract remains `/api/*`.
- Page data is served through TanStack Query: `src/modules/identity/user/user_queries.ts` defines `queryOptions` wrapping the server functions; loaders run `context.queryClient.query({ ...options, staleTime: 'static' })` and components subscribe with `useSuspenseQuery`. The `QueryClient` is created inside `getRouter()` via `getContext()` (`src/provider.tsx`) — one client per request, never a module-level singleton, because a shared client leaks SSR data across requests. `setupRouterSsrQueryIntegration` handles dehydration, hydration, and streaming; the provider is the explicit `Wrap` in `router.tsx` (`wrapQueryClient: false` keeps one provider layer).
- A detail page whose user does not exist answers HTTP 404 during SSR while still rendering the not-found body inside the shell; the catch-all answers 404 the same way. Page loaders log their real failure server-side and rethrow a message that is safe for Start to serialize onto the error page — never let an internal error message reach the client. The root route's `errorComponent` (`src/routes/-boundaries.tsx`) is the global error surface and stays generic: no `error.message`, only a reset action and a home link.
- `setResponseStatus` is called only through `src/kernel/ssr_status.ts` (`createIsomorphicFn().server(...)`); route files never import `@tanstack/react-start/server` directly, or the import-protection guard warns in dev and build. Inside a `.server()` boundary the compiler treats the import as safe to strip.
- Server functions are CSRF-protected: the `createCsrfMiddleware` instance in `src/start.ts` (filtered to `handlerType === 'serverFn'`) rejects any `/_serverFn` request whose `Sec-Fetch-Site` marks it cross-site, whose `Origin` differs from the request origin, or that carries no browser cross-site marker at all (a bare `curl` answers 403). Page requests, `/api/*`, and the HTML `x-cache` bridge pass untouched — the middleware never sees a non-server-fn handler.
- The TanStack devtools panel (`src/routes/-devtools.tsx`, wired through `@tanstack/devtools-vite`) renders only under `import.meta.env.DEV` and receives the router's own `QueryClient` via the root route context; the production bundle and HTML must contain no devtools identifiers.
- The router factory sets `defaultPreload: 'intent'` with `defaultPreloadStaleTime: 0`: links preload their loaders on pointer or keyboard intent, and the navigation itself still revalidates. The SSR `origin` option stays unset — the Effect renderer forwards the real request and Start emits relative URLs (probes show a spoofed `Host` cannot inject an absolute redirect target).
- The detail page's `x-cache` response header reaches the HTML response only through the page-meta bridge: the server-function handler records the cache verdict on `src/kernel/pagemeta.ts` and the Start request middleware in `src/start.ts` copies it onto the outgoing response. `setResponseHeader` inside a server function does not affect the HTML response.

## How to change it

- Adding domain features: Create `src/modules/<name>/` with route definitions, handler factories, service logic, and repository implementations. Export `HttpApiGroup`, handlers factory, and service layer from `src/modules/<name>/module.ts`.
- Registering a module: Add the module's `HttpApiGroup` to `api` in `src/kernel/registry.ts`, merge its service layer into `moduleServiceLayer`, and merge its handler factory into `moduleHandlerLayer`. Do not touch `src/kernel/layers.ts` or `src/kernel/http/api.ts` directly.
- Defining endpoints: Declare endpoint schemas in `<feature>_route.ts` wrapped in `SuccessEnvelope` and `ErrorEnvelope`. Implement handlers in `<feature>_handler.ts` using `respondSuccess` and `respondError`.
- Updating user write operations: `POST /api/users` assigns role `10` (SUBSCRIBER); `PATCH /api/users/:id` updates partial fields (`null` clears value); `DELETE /api/users/:id` hard-deletes the record. Duplicate emails trigger `409 EMAIL_CONFLICT`. Writes invalidate cached lookups.
- Testing conventions: Drive command tests through `run(args)` in `src/command/root.ts` capturing output and virtual databases. Mock external services at the layer boundary. Capture application logs with silent loggers to keep test output clean.

## Traps

- Standalone leak detection: The external-import scanner in `src/builder/helpers.ts` matches `import`/`export` keywords naively. Avoid placing bare import statements in multiline comments or template literals in bundled server code.
- Native SQLite addon: Turso native binaries cannot be bundled into JS chunks. The build copies the platform-specific binding to `dist/node_modules/@tursodatabase/`. Standalone output is portable only to identical OS/architecture environments.
- Schema generic binding: Schema wrapper helpers (`SuccessEnvelope`, `ErrorEnvelope`) must constrain generic parameters to `Schema.Top` to preserve HttpApi's internal AST type inference. Constraining to `Schema.Schema<A>` breaks type inference, causing unrelated typecheck errors across the composition root.
- Multiprocess WAL locking: Local SQLite files require `experimental: ['multiprocess_wal']` in `src/database/dialect.ts`. Opening the database with external tools (such as CLI `sqlite3`) without multi-process WAL support will lock the file and cause runtime failures in `serve` and `healthcheck`.
- Server-function serialization: `createServerFn` serialization drops a top-level `undefined` from the payload, so a not-found result needs an explicit shape on the wire — `userQueryOptions` maps a missing user to `null` before it reaches the query cache. Route files that read `head`'s `loaderData` resolve it with an extra `undefined` union; `userTitle` accepts `UserResult | null | undefined` instead of casting.
- Dev env loading: do not replace `loadEnvFile('.env.local')` with Vite `loadEnv(..., '')`. The empty prefix still skips unprefixed keys, so the composition root keeps the default `DATABASE_URL` and `/api/health` answers 404 when that file is missing.
