# Contracts and change rules

## Contracts

- `ApplicationLayer` in `src/kernel/layers.ts` is the composition point for application services; it builds the user service over one `DatabaseLayer` instance per layer scope.
- `serve --auto-migrate` applies migrations and then serves requests with the same scoped `Database` service. `DATABASE_URL` is the only switch between transports: a `file:` URI (or a bare path) opens a local file, `libsql://`/`turso://`/`https://`/`http://` opens a remote database and requires `DATABASE_TOKEN`. `:memory:` is refused, because the healthcheck probe and a migration run open the database from their own process and would each get a private one.
- The remote transport is bounded and verified: every request carries a 5-second abort signal and acquiring the database runs one `select 1` before it is handed out (`src/database/dialect.ts`), so a bad host or a revoked token fails the layer at startup instead of the first query. The transaction uses one stream and no handle is kept in a slot, so a failed `COMMIT` cannot poison the connection and the original error always survives. `insertId` is reported only for an `INSERT` on both transports. An `http://` URL logs one boot warning; the sidecar sweep narrows every `<basename>-*` file the engine writes, not a fixed suffix list. `streamQuery` clamps a non-positive chunk size to one row — Kysely forwards the caller's number verbatim, and a driver pinning the event loop is the worse failure.
- Feature services depend on repository interfaces. Repository implementations belong in their feature module and use the database service; keep Kysely query construction out of HTTP handlers and application services.
- A feature's Effect entity schema defines its row type and Kysely table type; it augments `src/database/schema.ts`'s `Database` interface instead of registering tables centrally.
- Every server response carries the hardening headers from `src/middleware/security-headers.ts` (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`). The CSP allows inline styles only; a change that needs inline scripts must revisit the policy, not drop it. Page responses are the exception: the SSR bundle emits inline hydration scripts, so `renderPage` mints a per-request TypeID nonce (`nonce_…`), passes it to the Solid bundle's `handleRequest`, and sends `script-src 'self' 'nonce-…' 'strict-dynamic'` on that response alone — the global middleware skips responses that already carry a CSP. Fonts are self-hosted (fontsource variable packages imported through `src/assets/fontface.css`); the CSP admits no third-party origins.
- CORS is global middleware (`src/middleware/cors.ts`) built on Effect's `HttpMiddleware.cors`: `CORS_ENABLED` (default on) gates it and `CORS_ALLOWED_ORIGINS` (comma-separated absolute origins, default empty) narrows it — an empty list echoes any caller origin because `credentials: true` forbids the literal `*`. It is registered as a global middleware (an `Effect.map(AppConfig, …)` fn, the `trustProxyMiddleware` pattern), not a `Layer.unwrap` returning `middleware(...).layer` — the global form's `.layer` is `undefined` and a global layer inside `Layer.unwrap` crashes the router build.
- Request metrics carry bounded identities: `http_requests` is labelled `{ method, status_code, route }` — method collapses to the known set (others recorded as `OTHER`), `status_code` is the exact code, and `route` is the matched route template derived from the HttpApi contract (plus the `page` and `unmatched` literals), so series count stays bounded by the route table; `http_request_duration_seconds` is labelled `{ method, route }`. The class form (`2xx`, `4xx`, …) no longer exists.
- The request log (`src/middleware/request-log.ts`) skips quiet paths — requests with no signal: browser and tooling probes, favicons, hashed bundles, and metric scrapers. A quiet path skips both the log line and the metric record. The default set (`/.well-known/`, `/favicon`, `/apple-touch-icon`, `/assets/` prefixes plus the Prometheus `/metrics` exact) matches the rate-limit exclusion shape (`{ path, exact? }`, trailing slashes normalized, `exact` = equality else prefix) and can be replaced wholesale per mount with `requestLogMiddleware({ quietPaths })`; a custom set does not merge with the defaults. The `/.well-known/` prefix is deliberately broad so machine-to-machine discovery documents — ACME, security.txt, the OAuth/OpenID set (`jwks.json`, `openid-configuration`, `oauth-authorization-server`) — stay quiet as the API grows them.
- A log message that starts with a word is capitalized (`Database connected`, `No pending migrations`, `Would rollback 00003_…`); a data-led record keeps its data first (`GET /api/users 200 7ms`, `00001_create_platform_tables 2026-…`). Tests assert the exact string, so a message and its assertion change together.
- Dependency calls are traced and timed: `dependency_duration_seconds` is labelled `{ store, op }` with `store ∈ {sqlite, redis}` (`sqlite` covers both database transports — the series name predates the swap and is kept) and a fixed op set (`query`, `read`, `ping`, `cache-get`, `cache-invalidate`, `rate-limit-consume`). Spans carry the same bounded attributes (`cache.status`, `limiter.verdict`); a query string, cache key, or table name must not become a span attribute or metric label.
- `/api/health` is the one health probe, served by the health core in `src/kernel/healthcheck.ts`: named checks (`database` = the database ping) run concurrently under a shared 2-second probe budget, and the report carries the aggregate `status` plus per-check `details` (`up`/`down`, `timestamp`, `error` when down) — the alexliesenfeld/health shape. All up answers `200` with `{"status":"ok",…}` and any down answers `503` with `{"status":"unhealthy",…}` — readiness semantics, fail-closed. The healthcheck CLI runs the same core through the same checks (so the endpoint and the command cannot drift), prints `Healthy`/`Unhealthy`, and exits `0`/`1`; the connection lifecycle lines (`Connecting …`, `Database connected`, `Closing …`, `… closed`) are serve's operator signal — the shared `DatabaseLayer` the one-shot commands use logs none of them. There is no separate liveness endpoint; a supervisor that must not restart on a database outage should not key off this endpoint.
- The serve command owns the shutdown sequence: it waits for `SIGINT`/`SIGTERM` itself (`src/kernel/graceful.ts`) and completes the server scope **normally**, because Effect's interrupt detaches async finalizers — a scope closed by interruption abandons them, so `runMain`'s signal handling is not used for the server path. The signal logs `Shutting down (received <signal>)`, the HTTP server drains (up to its 20-second graceful-shutdown timeout; idle keep-alive sockets are dropped first), the database and Redis connections close with their own log lines (`Closing …` then `… closed`, the Redis pair bracketing a scope the store owns), and the handler logs `Application terminated` last; the process exits `0` and any later signal — the same one or the other — exits immediately with `128 + signum`.
- The process entry selects the runtime from the first positional argv token (`subcommandOf` in `src/command/root.ts`), not from a fixed index: the server path skips `runMain` (its interrupt-based exit detaches finalizers) and disables telemetry export only for the one-shot path. A global flag before the subcommand must not change which path runs. In the server path a `CliError` is not printed again — the command's own handler rendered it — only non-CliError failures print their stack.
- The CLI's global flags are exactly the documented three — `--help`, `--version`, `--log-level` — provided as the canonical `GlobalFlag` objects (`CliConfig.layer({ builtIns: [Help, Version, LogLevel] })`). A copied or rebuilt built-in parses and then does nothing: `Command.run` installs the level and dispatches the wizard by object identity. `--log-level`'s value is lowercased before the run, so `Debug` and `debug` agree with what `LOG_LEVEL` accepts.
- `migrate:up` is forward-only: `--to <name>` refuses a target that is already applied (Kysely's `migrateTo` walks backwards) and the `--dry-run` branch refuses it the same way. Rolling back belongs to `migrate:down --count` and `migrate:reset`.
- The one-shot commands present their report through the console (`src/command/helper.ts`): colored by state — cyan while a step runs, green on success, yellow in a dry-run preview — grouped under their step's line and separated by blank lines, without timestamps. `serve` keeps the logger's format for every line it emits — the API handler merges the composition's `LoggerLayer` at the outermost layer of its web handler, so request logs print in the same format as the auto-migrate lines. `--log-level` filters the logger, not the console presentation, and the tests capture reports from `output`, not `logs`.
- `generate:config` resolves the symbolic-link chain of its target before deciding, so a dangling or chained link to a dotenv file is refused like a real `.env`; `--force` alone is a no-op, and `--stdout` with `--check` is rejected. Destructive confirmations share `confirmDestructive` (`src/command/helper.ts`): `--force` skips the prompt, and without a TTY the answer is a refusal rather than a hang.
- Every failure under `/api/*` answers JSON (`src/middleware/error-response.ts`): declared endpoint errors encode through the HttpApi contract (`{"_tag":"NotFound"}`, `{"_tag":"Conflict"}`, `{"_tag":"ServiceUnavailable"}`), while the causes HttpApi turns into die-level defects — request-decode failures (`HttpApiSchemaError`), unmatched paths, and unhandled defects — reshape into `{"_tag":"HttpApiDecodeError","kind":…,"message":…}` (400), `{"_tag":"NotFound"}` (404), and `{"_tag":"InternalServerError"}` (500). The reshaping middleware is path-scoped to `/api/`, so page defects keep the platform's empty-body default. An `/api/*` wildcard fallback route in `apiRoutes` answers unknown paths and unregistered methods with the JSON 404 before the SSR catch-all can claim them; `routeLabel` maps the wildcard to `unmatched`. The rate-limit store outage answers `503` with `{"_tag":"ServiceUnavailable"}` instead of plain text. Middleware nesting follows merge-list order — earlier in the list wraps outer — so the error-body middleware must sit before the request log to keep the raw-failure warning.
- User repository failures return a sanitized `503` response. The underlying database cause must not be included in the HTTP body.
- The API wire contract is defined once in Effect HttpApi: endpoint schemas live in the feature module's route file (`src/modules/<name>/<feature>_route.ts`, re-exported from the module's `module.ts`), handler factories receive the composed `HttpApi`, and every failure a handler can produce must be declared in the endpoint's `error` set — an undeclared failure becomes a 500 defect. Path-params validation belongs in the endpoint's `params` schema (a decode failure is an automatic 400).
- `/api-docs` (Scalar reference) and `/api/openapi.json` exist only when `API_DOCS_ENABLED=true`; the paths are constants in `src/kernel/http/api.ts`.
- API routes are rate-limited through the configured store: fixed-window counters in the database, or shared counters in Redis when `REDIS_ENABLE=true`. The process-local memory mode no longer exists. The limiter middleware wraps the user routes; exclusions are `{ path, exact }` — `exact: true` matches the pathname alone, otherwise the exclusion is a prefix (and a configured trailing slash is ignored) — so `/api/health` is exempt entirely and a readiness probe never consumes the budget, never trips the limit, and stays answerable when the limiter's store is down. On the throttled routes a store the middleware cannot read answers `503` — fail closed.
- Redis unavailability at boot delays serve within a bounded window (`src/kernel/redis-boot.ts`, 30 attempts 1 s apart) instead of killing it; runtime reads keep degrading exactly as before and the limiter stays fail-closed. The compose `app` service additionally gates on redis `service_healthy` so a cold start never races.
- The runtime metrics sampler and the `/metrics` endpoint share the `METRICS_ENABLED` gate: with the flag off there is no endpoint and no sampling fiber.
- `APP_BASE_URL` must be an absolute http(s) URL; the parser rejects empty and whitespace-only values. An empty OS environment variable counts as unset and takes the documented default — the rejection guards non-env config sources.
- A standalone build inlines every runtime dependency into the emitted bundles, the SSR bundle (`dist/server/`) included; the build fails naming any static or dynamic import of a bare package specifier that remains. Validation that covers the standalone artifact must probe an SSR render (e.g. `/`) against the built container, not only API endpoints — `node_modules` on the host masks externalized imports.
- Database and runtime resources must be closed with Effect scopes or `ManagedRuntime.dispose()`.

## How to change it

- Add application behavior to a feature service, expose required operations through its repository interface, and implement persistence in the feature module using the database adapter service.
- A feature module is self-contained: its service layer (e.g. `modules/identity/user/user_layer.ts`) wires its own repository and cache dependencies inside the module, so the kernel composition (`kernel/layers.ts`) only ever supplies `AppConfig`, `Scope`, and `Database`. A module's package `module.ts` (e.g. `modules/identity/module.ts`) re-exports its `HttpApiGroup` (e.g. `UsersApi`), its handlers factory (e.g. `usersHandlers`), and its merged service layer under its own name (e.g. `identityLayer`) — the kernel imports a module through that barrel alone, never a feature file directly.
- Add a feature endpoint by declaring it in the module's `HttpApiGroup` contract (`<name>_route.ts`), implementing the handler in that module's factory (`<name>_handler.ts`, `<name>Handlers(api)`), and re-exporting both from the module's `module.ts` alongside the module's merged service layer. Then wire the module in: merge its layer into `ApplicationLayer` in `kernel/layers.ts`, add its group to `HttpApi.make(...).add(...)` in `src/kernel/http/api.ts`, and provide its handlers factory to `apiRoutes` — these are the two kernel files a new module touches today. Add the matching behavior to `docs/api-endpoint.md` in the same change.
- The user write surface (`src/modules/identity/user/`): `POST /api/users` takes `{ email, name?, avatar_url? }` and creates with role `10`; `PATCH /api/users/:id` merges the partial patch (absent stays, explicit `null` clears); `DELETE /api/users/:id` hard-deletes. A duplicate email — including one owned by another user — fails with `409`; keeping one's own email is not a conflict. Writes invalidate the user's cache entry, and the storage layer stamps `updated_at` (Kysely's insert type does not honor `defaultTo(sql\`…\`)` defaults).
- Replace external dependencies in tests with service layers; use `TestClock` for time-dependent behavior.
- Tests keep the runner output clean: a composition under test that logs gets a silent logger (`Logger.layer([Logger.make(() => void 0)])`), and it must ride the outermost `Effect.provide` around the whole program — the serve layer spawns its own listening and request fibers during the layer build, and only a logger ambient around that build reaches them; a logger provided into an inner layer does not. When the noisy fibers belong to a composition the test cannot wrap (`apiHandler`, the dev forwarding), `quietConsole()` from `tests/fixtures/console.ts` filters the composition-format records from the process streams instead. A test that asserts on log lines captures them with `Logger.make(({ message }) => lines.push(...))` in the same outermost position. Application logs must never reach the test runner's console.
- A command-level test drives the real `run(args)` from `src/command/root.ts` through `src/command/cli.ts` (capturing `Logger` + `TestConsole`, a real filesystem, and a SQLite database in a temp directory); assert on log lines, console output, and the exit. Do not call a command's handler directly — the flags, defaults, and refusals are the contract.
- Keep expected failures in Effect error channels and map them at the HTTP boundary. Do not retry writes unless they are proven idempotent. A command reports an expected refusal as `CliError.UserError` (message, no defect trace), not as a bare `Error`.

## Traps

- The Vite development API handler and production HTTP server share one middleware stack (`kernel/http/stack.ts`) but keep different composition entry points — dev adds `Layer.succeedContext`, serve adds the SSR router and the dispose finalizer; keep both covered when changing application services.
- `kernel/runtime.ts` owns the one `ManagedRuntime` (built from `ApplicationLayer` + `CoreLayer`) and its disposal; it is used to bridge Solid's server renderer to Effect services in development. Production SSR receives the request's `UserService` through the renderer's async context and must not create a second database runtime per request.
- Configuration and endpoint documentation can drift; verify each documented surface against the route layers and configuration definitions.
- Migration and seeding helpers live in the Effect error channel (`src/database/migrator.ts`): they require the `Database` service, so a fresh database must be migrated before first use — a `rate_limits`-backed limiter fails the request (500) when the table is absent.
- In test compositions that wrap `apiRoutes` with `HttpRouter.provideRequest`, the request-provided context does not override layer-level services: fakes for `Database` must be provided at the layer level, after the rate-limit counter layer, or the tag is not found / the real service wins.
- A local database file is opened through `LOCAL_CONNECT_OPTIONS` (`src/database/dialect.ts`), which carries `experimental: ['multiprocess_wal']`. Without it the engine holds an exclusive lock for the connection's lifetime, so the healthcheck probe and any `migrate:up` run fail with `File is locked by another process` while `serve` holds the database. Every process of this application passes the same option; a tool outside it (`sqlite3`, the `turso` CLI) opening that file without the option conflicts with the server.
- The SQLite engine loads its native binding at runtime, so the standalone build copies `@tursodatabase/database-<platform>` into `dist/node_modules/` (dereferenced out of pnpm's store) and the leak guard skips that directory. The Turso JavaScript is inlined; only the compiled addon stays a file, which makes `dist/` portable only for the platform it was built on.
- The standalone build's external-import leak guard is syntax-naive: it only matches `import`/`export` at a line start or right after `;`, followed by whitespace, `{`, or `*`. Writing that exact shape inside a comment or a template literal in bundled code produces a false positive and fails the build for no real leak.
- A container build for local or development use passes `--build-arg DISTROLESS_TAG=debug-nonroot`; the plain `nonroot` tag ships no `/busybox`, and the entry shebang is `#!/busybox/env node`.
