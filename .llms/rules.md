# Rules

Contracts, how-to-change recipes, traps. Read the section a change touches before touching it. Why a thing is shaped as it is: `architecture.md`. Where it lives and which command runs it: `shape.md`.

## HTTP contracts

- **Every API response is an envelope** (spec `api-response.md`; types and builders in `src/kernel/http/envelope.ts`). Success: `{ status: 'success', data, metadata, links? }`. Error: `{ status: 'error', message, error: { code, retryable, details?, debug? }, metadata }`. `metadata` is `status_code`, `request_id` and, when they apply, pagination, `trace_id` (a `trc_` id, only when the trace was recorded), `cache` (`hit`/`miss`/`bypass`) and `rate_limit`, on success and error alike. Field names are snake_case: they are the wire contract. `message` is set only by `defineMessageHandler` (no `data`). Outside the envelope: `/metrics` (Prometheus text), `/.well-known/*` (RFC formats), and the HTML pages.
- **Endpoints are declared, not written.** `defineHandler` (`src/kernel/http/handler.ts`) takes `{ params?, body?, query?, response, status?, run }`, reads the body, decodes the inputs, runs the program and encodes the value through `response` into `data`; `run` receives exactly the inputs declared. Handlers never call `runEffect`, `readBody`, `getQuery` or `decode`. `defineMessageHandler` (`{ message, run }`) is for acknowledgements; `definePagedHandler` is for collections (below). Create answers `201` (`status: 201`). Handlers accept `Effect<A, E extends AppError, HttpEnv>`.
- **`HttpEnv` is assembled, never listed.** `HttpServices` (`runtime.ts`) is an empty interface that each service augments beside its definition (`declare module '../../kernel/http/runtime.ts' { interface HttpServices { user: UserService } }`); `HttpEnv` is their union, so the kernel names no domain service. A service a handler uses must declare itself there.
- **One runtime, no singleton.** `serveHttp` captures the command's service context into an `HttpRuntime`, `createApp` attaches it to each request (`provideRuntime`), and `runEffect` and the observer read it with `runtimeOf(event)`. Never build a second `ManagedRuntime` on Node (a second connection and logger). The Worker builds one per isolate and tests one per test app.
- **An error renders itself.** Every application error implements `AppError` (`src/kernel/errors.ts`): `status`, `code` (stable, `UPPER_SNAKE`), `clientMessage`, `retryable`, optional `detail`. `runEffect` only renders: `NotFound` 404 with `error: { id }`, `ValidationError` 400 with the issue list, `Conflict` 409, `RequestTimeout` 504, `DatabaseError` 500 `Database error`; a defect is 500 `Internal server error`; an interrupted fiber (client hung up) is 499. `clientMessage` and `detail` reach the client, so they never carry internals. A new error is a class with those members; the kernel needs no edit, and the type check is `E extends AppError` on the handler.
- **Error reporting.** A failure with `status >= 500` and any defect reaches the error reporters (`src/observer/error_reporter.ts`) once, with its cause. Expected failures carry `ErrorReporter.ignore`; interruptions are skipped by Effect. `runEffect` wraps the program in `Effect.withErrorReporting`; the default reporter logs `Request failed` at `Error` with the request id; more reporters go in `ErrorReporter.layer([...])`.
- **An error explains itself, and says no more than the log level allows.** `error_body.ts` builds `{ code, retryable, details?, debug? }`: an `AppError` owns its code and `retryable` (`DatabaseError.retryable` is the transient check the read retry uses); an h3 or middleware error has none, so the code comes from the status and `Retry-After` is repeated as `details.retry_after`. `debug` (`{ type, message }`, server errors only) exists only when `HttpRuntime.diagnostics` is true (`LogLevel.isEnabled('Debug')`), so production never leaks it. Anything that reaches a client or a log passes `src/kernel/redact.ts` first (`redactText`, `redactValue`, `describeFailure`); a validation message for a secret-named field is replaced, since a schema message can quote the value. `metadata.trace_id` and `x-trace-id` are set on errors too; the request log carries `errorCode`. Emails and other personal data are not redacted by shape: keep them out of messages.
- **An error is JSON under `/api` and HTML elsewhere.** `createApp` sets `onError: makeErrorHandler(() => import('../app/pages/error.marko'))` (`error_page.ts`); `isApiPath` (`/api` and `/api/…`, not `/apiary`) decides. `/health` and `/metrics` errors are HTML too. Both renderers copy `event.res.errHeaders` into the `Response` they build, because h3 does not merge them; the page also replaces the fixed CSP with its own nonce'd one. If the page cannot render, the envelope answers.
- **The catch-all.** `notFoundRoutes` (`src/routes/route.ts`) is registered last, for every method but `HEAD` (h3 serves a `HEAD` from the `GET` route only when no other route matches first). It **throws** an `HTTPError`, because h3's `onResponse` middleware converts h3's own not-found marker with a default config and bypasses `onError`. `404`, or `405` with `Allow` when `allowedMethods` (`allowed_methods.ts`) finds the path under other methods: it asks rou3's `findAllRoutes` over h3's router (`app['~rou3']`, the one internal property used; `allowed_methods.test.ts` fails if it goes), ignores the `/**` catch-all, and adds `HEAD` where there is `GET`. `rou3` is a direct dependency pinned to h3's version. `Allow` is set on `event.res.errHeaders`.
- **Collections paginate by cursor.** `run` returns a `Page<A>` (`src/kernel/pagination.ts`: `items`, `limit`, `next`); the spec gives `items` (one element's schema) instead of `response`. The query is `paginationQuery(sortable, defaults)` (`src/kernel/http/pagination.ts`): `limit` (plain digits, 1 to 100), `cursor`, `sort_by` (an allow-list typed as a union), `sort_order`. There is no `page`, no total and no "every record" mode. A cursor is base64url JSON `{ s, o, v, i }` (sort column, order, last sort value, last id; opaque, not secret, only ever bound as a parameter, at most 512 characters) and belongs to the sort it was issued for: another `sort_by`/`sort_order` (defaults included) or an undecodable cursor is `400 VALIDATION_FAILED`. `toPageRequest` yields the `PageRequest` a repository takes. A repository fetches `limit + 1` rows after the anchor with a row-value comparison `(sort column, id) > (value, id)` (`<` for `desc`; `id` alone when sorting by `id`), orders by the sort column then `id` **in the same direction**, and returns `makePage(rows, request)`, which drops the look-ahead row and encodes the last kept row's cursor. Sortable columns must be non-null. `paginationMeta` and `paginationLinks` derive `limit`, `has_more`, `next_cursor` and relative `self`/`first`/`next` links in one place. `user_query_plan.test.ts` fails if a keyset query stops using its index.
- **Request lifecycle limits.** `runEffect` passes `event.req.signal` (a disconnect interrupts the fiber) and wraps the program in `Effect.timeoutOrElse` with `REQUEST_TIMEOUT` (504). `bodyLimit(BODY_LIMIT)` rejects oversized bodies with 413 as they are read. `loadShedding` answers `503` + `Retry-After: 1` past `MAX_IN_FLIGHT` (default 1024, `0` off), using `provideRuntime`'s count; `/health` and `/metrics` are exempt; refusals are logged as warnings, counted in `http_requests_shed_total`, and carry the request id and CORS headers. Field bounds live in the schemas (`email` ≤ 254, `name` ≤ 200).
- **Untrusted input is bounded before use.** An inbound `x-request-id` is kept only if it matches `[A-Za-z0-9._:-]{1,128}`, else a fresh id is minted. A JSON body is read within `REQUEST_TIMEOUT` by the handler's own stream reader (`readBodyWithin`, not h3's `readBody`, which cannot be cancelled): at the deadline it cancels the read and answers `408` with `Connection: close`, so a half-sent request releases its socket. The same reader parses the JSON (`400 Invalid JSON body`). `redactText` truncates to 16 KB and scans linearly (a keyword search, then a bounded sticky match at each hit, never a pattern tried at every offset): keep any new pattern in that style. Metric labels that come from the client are folded to a fixed set (`metricMethod`); never label a metric with a path or a header. Every OTLP export and every log sink write has a 5 s deadline; shutdown's last telemetry flush has 1 s.
- **Health.** `GET /` is the front page, not a probe. `GET /health` is readiness at the root: 200 only if `DatabaseService.ping` succeeds (else 500), and `503` once shutdown begins (`unlessDraining`, `HttpRuntime.beginDrain`; logged as a warning). `GET /metrics` exists only with `METRICS_ENABLED`, is plain Prometheus text, and has no auth.
- **Resource endpoints live under `/api`.** `apiRoutes` registers each module's routes (`userRoutes` declares `/users`, so the path is `/api/users`); groups nest and still merge into one trie. Probes, `/metrics` and `/.well-known` stay at the root. Middleware shared by the whole API sits on `apiRoutes`.
- **Validation runs inside the program** (`decode`, `src/kernel/http/decode.ts`): a body, params or query failure is a `ValidationError` (400 with issues). Malformed JSON never reaches the program.
- **Schemas are per resource and derived** (`src/modules/<resource>/<resource>_schema.ts`): one entity `Struct` (`UserSchema`, type `User`) is the source; request, response and params schemas and the Kysely table type (`UsersTable`, merged into `Database` in `src/database/schema.ts`; the repository mints the `user_` id) come from it. Domain code uses the inferred types; no hand-written row or input interfaces.
- **Response data is encoded through its schema**: only declared fields reach the client, so a new column does not leak through `selectAll()`. An encode failure is a defect (500). Database rows are not decoded on read (the migration owns their shape); decode in the repository only for a column that needs a transformation.
- **Request id.** Minted by the `requestId` middleware as a `req_` TypeID, inbound `x-request-id` echoed when valid. Written to both `res.headers` and `res.errHeaders`, because h3 merges only the latter into error responses. Never drop the `errHeaders` write.
- **Response headers are contract.** `/api` answers `cache-control: no-store` (`cacheControl({ errors: true })` covers errors too); every response carries `server-timing: total;dur=<ms>` (set by the observer on both paths); collections repeat their links as an RFC 8288 `link` header; CORS exposes `x-request-id`, `x-ratelimit-*`, `retry-after`, `link` (`EXPOSED_HEADERS` in `cors.ts`: a header a script must read has to be listed). A header that must survive errors is set on both `res.headers` and `res.errHeaders`.
- **Middleware order is contract** (`src/app.ts`): `provideRuntime` → `developmentMode` (dev only) → `cors` → `requestId` → `securityHeaders` → `httpObserver` → `loadShedding` → `bodyLimit`, registered before route groups mount. The runtime exists for everyone, preflight is answered early, the observer can read the id, later responses carry the security headers, a rejected body is still logged with its id. Reordering breaks the observer and the runtime lookup.
- **Route groups** (`defineRouteGroup`, `src/kernel/http/router.ts`): a group owns an isolated `H3` mounted at `prefix`, with patterns relative to it; its middleware runs only for its routes. `mount` merges its routes into the parent trie (no nested fetch). App-level config and hooks do not reach a mounted group, so shared behaviour is global middleware. A group at prefix `''` would wrap every later route, so pages carry the limiter per route.

## Security contracts

- **Security headers are fixed** (`src/middleware/security_headers.ts`): `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, a `default-src 'none'` CSP (an HTML page replaces only the CSP). Set on `res.headers` and `res.errHeaders`. No `Strict-Transport-Security`: TLS ends at the proxy or the platform.
- **A body must be JSON.** A handler that declares `body` answers `415` to any other `Content-Type` before reading (`requireJson`).
- **There is no authentication.** No product rule exists for who may call what; `apiRoutes` is where it goes.
- **A user has a required, non-blank `name`** (`NameSchema`: at most 200 characters, one non-whitespace); `users.name` is `NOT NULL`; a missing or blank one is a `400` naming `name`.
- **Rate limiting counts through a `RateCheck`** (`src/middleware/rate_limit.ts`): a fixed window per client address, shared by `apiRoutes` and the HTML pages (`/`, `/users`; route-level `rateLimitMiddleware`). Probes, `/metrics`, assets and `/.well-known` stay reachable. `RATE_LIMIT_ENABLED` decides whether the plugin is registered; `RATE_LIMIT_MAX` ≥ 1 when on (startup check). A `RateDecision` always has `limit` and `resetAt`, and `remaining` unless the store only answers yes/no (the Workers binding; then `ApiRateLimit.remaining` and `x-ratelimit-remaining` are absent). It sets `x-ratelimit-limit/remaining/reset` on every response of the group, errors included, puts `rate_limit` in both envelopes' `metadata`, and answers `429` with `retry-after`. Tests set the peer with `makeTestApp().request(path, { ip })`.
- **Stores.** `memory` (default, `makeMemoryRateCheck`): in-process, synchronous, bounded to 50 000 clients, so the effective limit is `max` times the instance count. `redis` (`makeSharedRateCheck`, `rate_limit_shared.ts`): Effect's `RateLimiter` (`fixed-window`, `onExceeded: 'fail'`) over Redis/Valkey, global, Node only (`NodeRedis` imported lazily by `src/layers.ts`). `cloudflare` (`makeBindingRateCheck`, `rate_limit_binding.ts`): Workers' Rate Limiting binding named by `RATE_LIMIT_BINDING`, per location, eventually consistent, allowance and period (10 or 60 s) fixed in `wrangler.jsonc`, so `RATE_LIMIT_MAX` is only reported (keep it equal to `limit`) and `RATE_LIMIT_WINDOW` only feeds `retry-after`; Workers only, and `worker.ts` dies at isolate build if the binding is missing. A store the platform lacks stops startup. Shared stores **fail open and fast** (250 ms budget, 10 s cooldown, one warning; only a real "limit exceeded" refuses). KV is not a store (no atomic increment, eventual consistency, one write per second per key).
- **The client address** (`clientAddress`, `src/middleware/client_ip.ts`: a pure function of the socket address, the headers and `ClientIpTrust`) is, in order: the `TRUSTED_PLATFORM` header if set and valid (with a socket, only from a `TRUST_PROXY` peer; with none, as on Workers, as sent; a missing, malformed or unbelieved one falls back to the socket, never to `X-Forwarded-For`); else the socket's address unless it belongs to a `TRUST_PROXY` proxy (`TrustedProxies`: none, all, or `IpRange`s from `kernel/ip.ts`, which handles IPv4, IPv6 and IPv4-mapped sockets without `node:net`, so the Workers bundle stays clean); then `X-Forwarded-For` from the right, skipping trusted proxies (an empty entry is skipped, a malformed one stops the search and the socket's address is used); then `X-Real-IP`; no address at all is `unknown`, one shared bucket. A range covers one address family (`::/0` does not match IPv4). Workers have no socket: set `TRUSTED_PLATFORM`.
- **`PROXY_PROTOCOL`** (a `TrustedProxies`) is read from the TCP connection, not a header. `acceptProxyProtocol` (`kernel/http/proxy_protocol.ts`, Node only, called by `serveHttp` right after `serve(…, { manual: true })` and before listening) takes the server's `connection` listeners off, reads a PROXY v1 or v2 header from a listed peer (buffered until complete, 5 s, v1 ≤ 107 bytes, v2 payload ≤ 536), redefines the socket's `remoteAddress`/`remotePort` (where srvx and h3 read the client, so the limiter, `TRUST_PROXY` and logs follow), pushes the bytes after the header back with `unshift`, then calls the original listeners. A listed peer without a valid header is destroyed; an unlisted peer passes through untouched. It keeps an `'error'` listener on the socket until the header is read, or a reset would crash the process. `proxy_protocol.test.ts` drives it through a real `http.createServer` without a port.
- **`CLOUDFLARE_LOCATION_HEADERS`** puts `country`/`city` (`CF-IPCountry`, `CF-IPCity`) on the request log through the `locationHeaders` plugin (`event.context.location`), registered only when on, and believed only when `TRUSTED_PLATFORM` is set and holds a valid address on this request. `clientLocation` sanitises: two letters or digits, `XX` dropped, city printable ≤ 64.

## Frontend contracts

- **Layout.** `app/pages/*.marko` (one per page), `app/tags/*.marko` (components; Marko discovers `tags/`, so `user-list.marko` is `<user-list>` with no import), `app/styles/*.css.ts` (vanilla-extract; `theme.css.ts` holds the `createTheme` tokens and theme class, applied to `<html>` in `tags/app-shell.marko`; other files import `vars` from it). `app/marko.d.ts` declares `*.marko` for `tsc`; only `mtc` (in `pnpm typecheck`) checks a template (`export interface Input`). Oxlint and oxfmt do not see `.marko`.
- **A page is `definePageHandler({ load, template })`** (`src/kernel/http/page.ts`) in the module that owns the data (`user_pages.ts`: `usersPageHandler`, and `userPages` mounted at the root by `pageRoutes`). `load` is an Effect over `HttpEnv`, so a page uses the services the API uses. It runs through `runProgram` (`responder.ts`: timeout, cancellation, span, error reporting, `?nocache=true`, `x-cache`). `template` must be `() => import('…/app/pages/x.marko')`, never a static import: a static one makes every module that mentions the page unloadable outside Vite (`pnpm app migrate:up` is plain Node), and in dev the fresh `import()` picks up an edited template. The result streams; `$global.signal` is the request's `AbortSignal` and `$global.cspNonce` the per-response nonce.
- **A page failure is thrown**, not rendered by the page: `definePageHandler` throws `HTTPError({ status, message: clientMessage })` (a hung-up client gets a bare `499`) and the error hook renders it. `refusal`/`failure` in `responder.ts` belong to the envelope alone.
- **HTML responses have their own CSP** (`contentSecurityPolicy`, `html_response.ts`; used by pages and error pages through `htmlResponse`, which streams the template and sets `content-type`, `cache-control: private, no-cache` and the nonce'd CSP on the headers it is given: `event.res.headers` for a page, a copy of `errHeaders` for an error page): `default-src 'none'; script-src 'self' 'nonce-…'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`. The nonce reaches Marko's inline resume script and the `<script>`/`<link>` tags through `$global.cspNonce`. Under `pnpm dev` (`event.context.development`) `style-src` gains `'unsafe-inline'` and `connect-src` gains `ws: wss:`, nowhere else. Both platforms must set it: `startDevApp` passes `development: true`, `src/worker.ts` passes `import.meta.env.DEV` (Vite replaces it with `false` in a build); forgetting it on the Worker makes the browser block Vite's injected `<style>` tags in `pnpm dev --mode worker`. Never add `'unsafe-inline'` to `script-src`.
- **Browser assets are `/assets/**`**, named `assets/<name>-<hash>` by Vite. `assetRoutes` (`assets.ts`: `serveStatic`, `cache-control: public, max-age=31536000, immutable`, no index) serves them from an `AssetSource` (`meta`/`contents` over an opaque id; h3 has already normalised it, never decode it again). `node_assets.ts` (Node only; `node:sea` does not exist on Workers) has `directoryAssets(root, scope)` (confined to `root` and to ids under `scope`, since the Node root also holds `index.mjs`: strict name pattern, no `..`, `startsWith(root + sep)`) and `embeddedAssets()` (SEA blobs keyed `assets/<name>`). `serveHttp` picks: dev server → none (Vite serves source); else `embeddedAssets() ?? directoryAssets('<entry dir>', '/assets/')`. On Workers Cloudflare's assets binding serves `/assets/**` before the Worker runs (the plugin adds `assets` to the generated `wrangler.json`; do not declare it in `wrangler.jsonc`), so `createApp` gets no `assets`.
- **`pnpm dev` is `vite`, and the application runs inside it.** `devServerPlugin` (`builder/dev.ts`, `apply: 'serve'`, node platform) puts `.env`/`.env.local` into `process.env` where unset, creates a module runner on the SSR environment and mounts the application after Vite's own middleware (`post` hook): one process, one port, no proxy. The application is `startDevApp` (`src/dev.ts`, loaded through the runner, which is how it imports `.marko` and `.css.ts`): a `ManagedRuntime` over `CoreLayer` + `AppLayer`, migrations at each start (unset `DATABASE_AUTO_MIGRATE` means on in dev; only an explicit `false` opts out), then `makeNodeApp({ development: true })` (`src/application.ts`, shared with `serveHttp`) behind `toNodeHandler`. The watcher covers `src/` (tests excluded) and `.env`/`.env.local`: it stops the application (`beginDrain`, up to 2 s for in-flight requests, then `runtime.dispose()`), clears the runner's cache, starts a new one and sends `full-reload`; a failed start is shown for every request until the next change. A style edit also reloads the page (the pages are server-rendered, so there is no client module to patch). Not in dev: the PROXY reader, the `/assets` route, `serve`'s flags. Running `serve` natively fails at the first page (`import('….marko')` under plain Node).
- **Vitest loads pages through the same plugins** (`vitest.config.ts`; `marko()` is not linked under test, so no browser entries are named). `makeTestApp(env, { assets })` mounts an `AssetSource`. Page tests assert on the HTML (`Showing <!>2`: Marko's text-node markers), the CSP nonce and the shared headers.

## Where HTTP code lives

- **`src/kernel/http/`** is generic mechanism: it knows h3 and Effect, no resource, and does not grow with the endpoint count. It must not import `modules/` or `routes/`.
- **`src/middleware/`** holds plugins: global ones registered once in a fixed order and group-level ones (`rateLimit`, `cacheControl`).
- **`src/modules/<resource>/`** is a vertical slice: `*_schema.ts`, `*_repo.ts`, `*_service.ts`, `*_handler.ts`, `*_routes.ts`, tests beside. A module imports `kernel/` and `database/`, never another module's internals. `src/routes/route.ts` mounts every module (`apiModules` is the one list under `/api`); `src/services.ts` wires their layers.
- **Reads that can be cached go through `makeReadThrough`** (`src/kernel/cache/read_through.ts`), never an ad-hoc `Cache`. It wraps Effect's `PersistedCache`, shaped by `config.cache`: `CACHE_ENABLED=false` is a plain lookup; `memory` is the in-process half only (`LocalCachePersistence` stores nothing, TTL zero); `redis`/`cloudflare` keep the entry in the shared store for `CACHE_TTL` plus a local copy for `CACHE_LOCAL_TTL`. The key is a `Persistable.Class` (`UserLookup`) whose success schema includes `null` ("known missing"). **Only a success is kept**: both TTL functions return zero for a failure (`Cache` stores a failed lookup for the full TTL otherwise), so a transient error is retried, never replayed; any new cache must do the same. A write must `invalidate` the keys it touches. Store failures are never the request's: a `PersistenceError` or `SchemaError` falls back to the lookup, and shared backings go through `guardBacking` (`guard.ts`: 250 ms, 10 s cooldown, read becomes a miss, write a no-op, one warning). `cache` in the request log and `metadata.cache` come from a per-request `CacheTally` (`runEffect` provides it as `CacheTrace`; `summarizeTally`: bypass, else miss if any read missed, else hit; absent when nothing read through a cache), and the same word goes out as `x-cache` (`HIT`/`MISS`/`BYPASS`, on both header sets, exposed by CORS). `?nocache=true` on a `GET` sets `CacheBypass`: a bypassed read neither reads nor writes. `Persistence` comes from the root: Node `CachePersistenceLayer` in `layers.ts` (Redis shares one `RedisLayer` with the rate limiter), Workers `cachePersistence` in `worker.ts` (`layerBackingEdgeCache` over `caches.default`: per location, no global purge, nothing stored on `*.workers.dev`), tests `makeTestApp({ cacheBacking })`. A store the platform lacks stops startup. KV is not a cache store (60 s minimum TTL, minutes of staleness, one write per second per key).
- **Identifiers are TypeIDs, each declared beside what it identifies** with `defineId(prefix)` (`src/kernel/objectids.ts`: `{ prefix, make, schema }`; throws at import on a malformed or duplicate prefix): `UserId` (`user`), `RequestId` (`req`), `TraceId` (`trc`, `observer/trace_id.ts`), `InstanceId` (`inst`, `telemetry.ts`). No shared list. `make()` mints a UUIDv7-based id; `schema` is a pattern check (a wrong id is a `400` before any query). Row ids are minted by the repository: `users.id` is `text`. The trace id is the exception: `metadata.trace_id` is the OpenTelemetry id re-encoded as `trc_…` (`traceTypeId`, `traceHexOf` reverses it); the span carries it as `trace.typeid`, request log lines as `traceId`.

## Naming conventions

- **No `index.ts` barrels.** A directory's entry file is named for what it holds (`config/service.ts`). The exception is `src/database/migrations/index.ts`, the static registry.
- **A schema value ends in `Schema`; its inferred type does not**: `UserSchema` is the value, `User` is `typeof UserSchema.Type`. Wire contracts are `<Resource><Action><Request|Response>Schema` and `<Resource>IdParamsSchema`; `Request`/`Response` in a name always means HTTP (so the cache key is `UserLookup`). Export a type only when code consumes it; for a schema that transforms, export `typeof XSchema.Encoded` as `X…Encoded` (`Type` is the domain shape, `Encoded` the wire shape).
- **Derive, do not repeat**: request and response schemas reuse the entity's fields (`UserSchema.fields.email`); the Kysely table type is the entity, or `Omit<Entity, …>` plus `Generated<…>`.
- **Exceptions, on purpose**: the envelopes (`ApiSuccess`, `ApiError`, `ApiErrorBody`) are plain interfaces (the responder builds them; nothing decodes them); configuration declarations (`src/kernel/config/`) are not `Schema` values and keep lower-case names (`serverConfig`).
- **File suffixes** inside `src/modules/<resource>/`: `*_schema.ts`, `*_repo.ts`, `*_service.ts`, `*_handler.ts`, `*_routes.ts`. The class inside keeps the `UserRepository`/`UserService` form (a service tag, not a schema). Tests: `*.test.ts` is unit/integration (Vitest), `*.spec.ts` is end-to-end (Playwright, `e2e/`).

## Code comments

A comment carries what the code cannot say, and nothing else. Keep it short.

- **Write one for** a non-obvious reason (why this and not the obvious alternative), a contract or invariant a caller must respect, a trap (an order that matters, a platform quirk, a failure that looks harmless), or a unit.
- **Do not write one that** restates the next line or the name, narrates a change ("now", "no longer", "used to", "we decided"), explains how the code got here, or opens with filler ("Note that", "Basically", "This function...", "In order to"). A good name replaces a comment.
- **Never mention** a decision, plan, issue, audit, ticket, roadmap, session, the owner or the user, and never point to a file or path ("see foo.ts"). When the counterpart matters, name the concept or symbol. Reasons and history belong in `architecture.md`, open findings in `.llms/issues/`.
- **Shape.** One summary line for an exported symbol; more only for a contract or trap. No `@param`/`@returns` repeating the signature, no banners, no commented-out code, no TODO without something to act on. English, plain sentences, under about 100 characters.
- **Directive comments** (`oxlint-disable-next-line`, `@ts-expect-error`, `@vite-ignore`, `/// <reference />`, shebangs) stay on the line they apply to, with a reason when not obvious.
- **Update or delete** a comment in the change that makes it wrong. A stale comment is a defect.

## Observability contracts

- **The logger never blocks a request on Node** (`src/observer/logger.ts`): lines are formatted on the calling fiber into a buffer; a detached fiber writes it to stdout once per `LOG_FLUSH_INTERVAL`. The scope finalizer drains the rest, so graceful shutdown loses nothing and a hard crash loses at most one window. On Workers `ConsoleLoggerLayer` writes each line straight to `console.log`. Services log with `Effect.log*`, never `console.*`; CLI output (`print` in `src/command/helper.ts`) is not a log and stays direct.
- **Log config** (`src/kernel/config/logging.ts`): `LOG_LEVEL`, `LOG_TRANSPORT` (`console`, `file`, `otlp`, a comma-separated list parsed by `choiceList`: an unknown or empty entry fails at startup; each sink receives every line), `LOG_FILE`, `LOG_ROTATION`, `LOG_FILE_MAX_FILES`, `LOG_FORMAT` (`pretty` | `json`, console only), `LOG_FLUSH_INTERVAL`.
- **The file sink is our own code** (`src/observer/log_file.ts`; Effect v4 has no rotation). `LOG_FILE` is a base path; the file written is `<stem>_<stamp><ext>` with `rotationStamp` giving `YYYYMMDD_hh` (hourly), `YYYYMMDD` (daily), `YYYYMMDD` of the Monday (weekly) or `YYYYMM` (monthly), all UTC. `LOG_FILE_MAX_FILES` (default 14, `0` keeps all) prunes older files when a new one opens, and only names matching the pattern are ever deleted. Entries carry their own timestamp (`LogEntry.at`), so a batch straddling a boundary splits across two files; a restart in the same period appends. One handle is open at a time, closed by a finalizer registered *before* `Logger.batched`, so the batcher's final flush runs first. Always JSON lines, in the key order of `jsonLogger` (`log_json.ts`: `timestamp`, `level`, `message`, `annotations`, `cause`, `spans`, `fiberId`), which `LOG_FORMAT=json` shares. A failed write goes to stderr and drops that batch. A `LOG_FILE` that cannot be opened stops startup. The sink needs `FileSystem` and `Path`, so `CoreLayer` feeds `NodeServices` into `LoggerLayer`. Workers ignore `LOG_TRANSPORT`.
- **Kysely logging goes through the Effect logger** (`makeQueryLogger`, `src/database/service.ts`). SQL and duration print at `Trace` only; a failed statement logs at `Warn` with SQL and error text. Bound parameters are never logged. The callback runs outside any fiber, so it takes the request id from `currentRequestId()` (`request_context.ts`, an `AsyncLocalStorage` filled with `run`, never `enterWith`, which workerd lacks).
- **The pretty sink prints each fact once.** `renderPretty` omits an annotation whose value is already a whole word of the message (`0.49` in `0.49ms`); the JSON sink keeps every annotation.
- **Request logs and metrics come from one plugin** (`http_observer.ts`): `http_requests_total` and `http_request_duration_ms` (labelled `method`, `status`) cover every response, 404s and h3-level errors included. New instruments go in `metrics.ts`. The registry is process-wide: tests in one process share it, so assert a difference, not an absolute value. `GET /metrics` serves it when `METRICS_ENABLED`.
- **Telemetry is OTLP over HTTP/JSON** (`src/observer/telemetry.ts`; no gRPC, no protobuf), on by default and aimed at the Compose collector (`OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318`, header `authorization=edgy-dev-ingestion-key`). `OTEL_SDK_DISABLED=true` turns it off, and `telemetryEnabled` (`config/observability.ts`) is the one definition of "on" (an empty endpoint cannot disable it: Effect's env provider treats an empty string as unset). `wrangler.jsonc` sets it for deployed Workers, `tests/app.ts` for every test app, `main.ts` for every one-shot CLI command (only `serve` exports; exit would otherwise wait on the collector). The development ingestion key is refused with a collector that is not local. `TelemetryLayer` installs `OtlpTracer`, `OtlpMetrics` and their shared `Flusher`; `TelemetryRuntimeLayer` adds the `fetch`-based `HttpClient` and JSON serialization and is built once per composition root (Node `CoreLayer`, `worker.ts`, `tests/app.ts`), given to the app and to the OTLP log sink so they share one `Flusher`. Headers come from the secret `OTEL_EXPORTER_OTLP_HEADERS`; the resource carries `service.name`, `service.version` and a per-process `service.instance.id`. Export is buffered, sent every `OTEL_EXPORT_INTERVAL` (default 5 s) or when a batch fills; an exporter whose collector fails switches off for 60 s and drops its buffer. Node flushes at shutdown (scope finalizer, after the server stops); a Worker flushes from `waitUntil`, at most once per interval.
- **Tracing** (`runEffect`). One server span per request named `METHOD route-pattern` (the matched route, never the raw path), attributes `http.request.method`, `url.path`, `http.route`, `request.id`, `http.response.status_code`. A W3C `traceparent` continues the caller's trace and its sampled flag wins; otherwise the span is a root, recorded for `OTEL_TRACES_SAMPLE_RATIO` of requests (default 0.7). A client error (< 500) is an answer, carried as a value (`Outcome.refused`) so the span ends `Ok`; only 5xx and defects fail it. `metadata.trace_id` is returned only when traces are exported and this one was sampled. `event.context.trace` keeps the span so the request log line, written after the fiber ended, joins the trace. Spans use `captureStackTrace: false`.
- **Noise requests are quieted by a hard-coded list** (`quiet_paths.ts`, tested entry by entry; deliberately not configuration, since it changes with browsers and bots, not deployments). Groups: `browser` (`/favicon.ico`, `apple-touch-icon*`, `/.well-known/appspecific/*`), `crawler` (`/robots.txt`, `/sitemap.xml`, `/ads.txt`, `/security.txt`), `probe` (`/health`, `/metrics`), `scanner` (`/wp-*`, `*.php`, `/.env*`, `/.git/`, `/phpmyadmin`, `/cgi-bin/`, `/actuator`, … only while the answer is 404). A quiet request is logged at **Debug** (annotated `quiet=<group>`), never dropped; one that fails (`/health` 503, any 5xx) is logged normally. Metrics count every request; a probe is also left out of `http_request_duration_ms` and its trace is not recorded (unless the caller sent a sampled `traceparent`). A path is listed in exactly one group (checked at import).

## Shutdown contract

- `SIGINT`/`SIGTERM` reach `NodeRuntime.runMain`, which interrupts the `serve` fiber. The finalizer calls `beginDrain` (`/health` turns 503), waits `SHUTDOWN_DRAIN_DELAY` (default 0), stops listening, waits until no request is in flight (bounded by `SHUTDOWN_TIMEOUT`), closes the remaining sockets with `close(true)`, releases the database and flushes the log buffer last. srvx's own handler is disabled (`gracefulShutdown: false`): two handlers race the finalizers and can drop buffered lines. Do not re-enable it.
- **Drain on requests, never on `server.close()`.** `close()` resolves only when every *connection* has ended, and a socket that never completed a request (a speculative preconnect, a half-sent header) is neither idle nor in flight, so awaiting it stalls for the whole timeout. `provideRuntime` counts requests (`inflight.ts`) and the count ends when the response **body** ends, is cancelled or fails, not when the handler returns, so a drain waits for streamed pages. Every body is a stream: a test that does not read a response leaves its request counted. The warning `Shutdown timed out with N request(s) still in flight` therefore means real work was cut off.
- **Shutdown is announced by our own logs** (`Shutting down`, with the in-flight count when non-zero; `Server stopped`); srvx's are off (`silent: true`), so removing them makes a stop invisible. `silent: true` also hides listen failures, so `serveHttp` awaits `server.ready()`: a busy port exits with status 1.

## CLI contracts

- **Commands are flat and colon-named**: `serve`, `config:generate`, `openapi:generate`, `migrate:up|down|status|reset|seed` (`src/command/`, wired in `cli.ts`). One file per command; `helper.ts` holds `print`, `printWarning` (plain console output), `ensure` (argument checks; not a bare `return` beside `return yield*`), `confirmDestructive`, `remoteFlag` and `announceRemote`.
- **Destructive commands** (`migrate:down`, `migrate:reset`) prompt via `Prompt.Confirm`; `--force` skips it; a non-TTY session without `--force` refuses with a `UserError` (non-zero exit). Keep this pairing on any new destructive command.
- **`--remote`** (`migrate:up`, `migrate:down`, `migrate:status`) points at the real D1 database. `Command.provide` takes the layer as a function of the parsed input, so the flag reaches `databaseLayer({ remote })`, which forces the D1 driver. `d1BindingNodeLayer` (`database/d1_node.ts`, Node only: `d1.ts` is shared with the Worker bundle and must not import `node:fs`) writes a copy of the Wrangler config (`wrangler.remote-<pid>.tmp.json`, JSONC read by `parseJsonc`, the `D1_BINDING` binding marked `remote: true` by `withRemoteD1`, removed on scope close) and starts `getPlatformProxy({ configPath, remoteBindings: true })`, which needs the Cloudflare login. `migrate:reset` and `migrate:seed` do not take it, on purpose: production data is never wiped or filled from the CLI. Exercised only up to Wrangler's auth demand; a run against a real account has not been seen.
- **Generators** (`generated.ts` holds what they share: flags, check, confirmed overwrite). `config:generate` writes `.env.example` from `appConfig.specs`: a new file is created freely; replacing a different one needs `--overwrite` plus `confirmDestructive` (`--force` is rejected without `--overwrite`); `--check` fails when stale; `--stdout` prints; any real dotenv name (`.env`, `.env.local`, …) is refused. `openapi:generate` writes `docs/openapi.json` (below).
- **`openapi:generate` derives the OpenAPI 3.1 description of `/api`; nothing is written by hand.** A handler built by `defineHandler`/`definePagedHandler`/`defineMessageHandler` records what it declared (`documentHandler`, `handler_doc.ts`: kind, `summary`, `params`, `query`, `body`, `response`, `status`). `routesOf` runs a group's `routes` callback against a recorder (nested groups included; `RouteTable` is the narrow method set a group may use), so no app is needed. `buildOpenApi` (`openapi.ts`) turns schemas into JSON Schema (`Schema.toJsonSchemaDocument`, the encoded side, so a query is strings) inside the response envelope, with one shared `ApiError` as every operation's `default`. A route whose handler declared nothing is an error, not a gap. Descriptions come from `.annotate`/`.annotateKey`. `docs/openapi.json` is exempt from `oxfmt`, `openapi.test.ts` compares it with the generator, CI runs `--check`; regenerate with `pnpm app openapi:generate --overwrite --force` after any route or schema change.
- **`--dry-run`** touches the database only to read (`getMigrationInfos`). `migrate:reset --seed` requires `--up`; `migrate:down --count` ≥ 1 (both `CliError.UserError`). `--to` on `migrate:up` takes a migration **name**, and a target earlier than the applied state is refused (Kysely would roll back).
- **`serve --auto-migrate`** migrates before the server starts and never seeds. `serve` provides `AppLayer`; migrate commands provide `DatabaseLayer` (driver chosen by `DATABASE_DRIVER`). `Effect.provide(layer)` is reserved for `main.ts` (lint `effecttsgo/strict-effect-provide`).
- **`pnpm app <command>` is plain Node** (`node ./src/main.ts`, native type stripping): no Vite. `serve` belongs to production (`node dist/server/index.mjs serve`, `pnpm start`); development is `pnpm dev`.

## Database contracts

- **Two drivers, one contract.** `DatabaseService` (`src/database/service.ts`) is all a repository sees: `db`, `query`, `read`, `ping`. `DATABASE_DRIVER=sqlite` builds it over `node:sqlite` (`sqlite.ts`), `d1` over a D1 binding (`d1.ts`, needs `D1Binding`); `makeDatabaseService` is shared. Node picks in `database/layer.ts`; the Worker wires D1 in `worker.ts`. There is **no `transaction` on the service**: Kysely's `transaction().execute` takes no signal, so a callback that never settles would hold the single SQLite connection with no way to cancel, and D1 has none. The first endpoint that needs one adds it with a deadline and a `signal` its callback must honour. The driver's own transactions (the migrator's `BEGIN IMMEDIATE`) remain.
- **Queries go through `query`** (maps any rejection to `DatabaseError`); repositories, the migrator and seeders do not call `Effect.tryPromise`. On `node:sqlite` `query` runs through `db.connection().execute(run, { signal })`, so one still waiting when its request is cancelled never runs (a `504` must not create the row the client's retry would create again). **Reads go through `read`**: identical on SQLite; on D1 a transient failure (`isTransientFailure`: connection lost, storage timeout, overloaded, temporarily unavailable, timed out, `SQLITE_BUSY`, locked) is repeated up to twice with jittered backoff (50 ms base), logged at `Warn`; deterministic failures are not. Never pass a write to `read`.
- **Uniqueness violations are a domain error.** `isUniqueViolation` recognises SQLite codes 2067 and 1555 on the `DatabaseError` cause and the text `UNIQUE constraint failed` (D1 reports no code); the repository turns them into `Conflict`. Other constraint failures stay `DatabaseError`.
- **Migrations are a static registry** (`src/database/migrations/index.ts`), not a directory scan: keys `NNNNN_name` (zero-padded), each file exports `up` (+ optional `down`), keys match the export binding. A new migration adds the file **and** registers it; an unregistered file silently never runs. Kysely owns `kysely_migration` and `kysely_migration_lock`: never hand-edit them. `migrateDown(steps)` resolves the target name from the executed list and delegates to `migrateTo` (`migrator.ts`; Kysely's own is one-step). **Seeders are idempotent** by contract (`seeder.ts`, e.g. `onConflict doNothing`). `src/database/schema.ts` is the Kysely `Database` type; a migration that changes the schema updates it in the same change.
- **SQLite migrations are atomic and locked** (`NodeSQLiteAdapter`, `dialect/sqlite-dialect.ts`): `supportsTransactionalDdl` is true, so the batch and its bookkeeping share one transaction, and the driver opens every transaction with `BEGIN IMMEDIATE`, so a second process waits for the write lock (up to the busy timeout) and then finds nothing pending. A plain `BEGIN` reads first and fails at once with `database is locked` when the other process committed in between (`migration_race.test.ts` runs two real processes). A raw statement returns rows when SQLite says it has result columns (`explain query plan` works). `users` has an index on `(name, id)` and a unique `users_email_lower_idx` on `lower(email)` (migration `00000`; the repository stores `email` lowercase); a new sortable column needs its own `(column, id)` index.
- **SQLite connection lifecycle** lives in `SqliteDatabaseLayer`: opens once per scope, creates the parent directory, destroys on scope close; nothing else opens a connection. It sets a 5 s busy timeout, `journal_mode = WAL` (not for `:memory:`; leaves `-wal`/`-shm` files) and `synchronous = NORMAL`. The connection caches prepared statements (`NodeSQLiteConnection`, 128 entries, LRU). There is no mutex of our own: Kysely's `RuntimeDriver` serialises a single-connection adapter. The driver is synchronous, so a long query or migration stalls the event loop: the known ceiling of the single-process design.
- **D1 specifics.** The dialect (`dialect/d1-*.ts`, adapted from `kysely-d1`, MIT) declares its own `D1Database` type. D1 has no interactive transactions. Kysely's SQLite introspector reads columns through `pragma_table_info`, which D1 rejects (`SQLITE_AUTH`), so `D1Introspector` lists tables from `sqlite_master` only, with empty `columns`: anything needing column metadata must not run on D1. `DATABASE_AUTO_MIGRATE` migrates at Worker start; isolates starting together can race on the first migration, so `wrangler.jsonc` sets it `true` (a new D1 needs no separate step; `dev`, `preview` and `deploy` agree) and a deployment whose schema exists turns it off with `pnpm run deploy --var DATABASE_AUTO_MIGRATE:false` after `pnpm app migrate:up --remote`.
- **D1 on Node is local only** (without `--remote`): `D1BindingNodeLayer` gets the binding from wrangler's `getPlatformProxy`, which reads the same `wrangler.jsonc` and `.wrangler/` state as `wrangler dev`, so `DATABASE_DRIVER=d1 pnpm app migrate:up` prepares what `pnpm dev --mode worker` serves. `wrangler` is imported through a variable on purpose: a literal import is followed by the bundler and adds ~20 MB to the build (`/* @vite-ignore */` silences Vite's warning).
- **Never import a Node-only module from the Worker's import graph.** `src/worker.ts` reaches `app.ts`, `services.ts`, `database/d1.ts`, `database/service.ts`, `observer/` and `kernel/`; none may import `node:sqlite`, `layers.ts`, `database/layer.ts`, `database/sqlite.ts`, `d1_node.ts`, `server.ts` or `@effect/platform-node`. A violation breaks the Worker bundle (`pnpm preview --mode worker` fails to start).
- **A Worker that cannot build its app answers `503`** through `startupFailureResponse` (the envelope under `/api`, plain text elsewhere; a `req_` id also in the Worker's log with the redacted cause), since no logger or error hook exists; the next request retries the build.
- **`GET /health` shares one database round trip per second** (`Effect.cachedWithTTL`, failures included). `HOST` defaults to `127.0.0.1`; a container sets `0.0.0.0`.

## Build contracts

- **One Vite plugin, two platforms.** `vite.config.ts` is plain Vite configuration (`server`/`preview` host and port from `HOST`/`PORT` through `loadEnv(mode)`: environment, `.env`, `.env.local`, then the mode's files; default `127.0.0.1:3000`; `strictPort`) plus `plugins: [edgy({ mode })]`. **The user's config wins**: the plugin only fills in what is unset (`withDefaults`: `mergeConfig(defaults, config)` written back into the config object, never returned from the `config` hook, because a returned value overrides the file and the command line and `pnpm compile` could not change the output). The plugin owns no `server` setting.
- **The platform is Vite's `--mode`**: `platformOf` returns `worker` for `--mode worker`, node otherwise. Not `--target` (Vite's language level) and not a custom flag (Vite refuses an unknown option before reading the config); mode also selects `.env.worker`.
- **Plugin order** (`builder/edgy.ts`): `edgy:shared` first (`enforce: 'pre'`: `appType: 'custom'`, the output directories `OUT_DIR`/`CLIENT_DIR`, and `MARKO_DEBUG=false` for a build, set before Marko's `config` hook reads it, since Marko optimizes only in `production` mode), then Marko, vanilla-extract, then the platform's. The client build writes into the server's directory without emptying it (the server builds first and empties it).
- **Node** (`builder/node.ts`): `ssr.noExternal: true` (build only; under `vite` the runner leaves `node_modules` to Node), `builder: {}` (every environment, the server first, because `@marko/vite` learns each page's browser entries from the server build and patches `__MARKO_MANIFEST__` into the server chunks), `target: 'node24'`, `assetsDir: 'chunks'` (SSR chunks never collide with `assets/`), entry `src/main.ts` as `index.mjs` with a shebang. `devServerPlugin`; `nodeOutput` (`output.ts`: `package.json` emitted as an asset in the SSR environment's `generateBundle`; the executable bit set in the client environment's `closeBundle`, the first moment the file is final, since Marko patches it while the browser side builds; a Worker build gets neither); **a build fails if a run-time dependency, direct or transitive, ships a native addon** (`builder/native.ts`: `binding.gyp`, `"gypfile": true` or a `.node` file; the bundle inlines every package, which cannot load one; `optionalDependencies` are not read); `nodePreview` (`preview.ts`: `configurePreviewServer`, registered directly so it precedes Vite's static handler; starts the built server on a free port and proxies the preview address to it; fails with "run `pnpm build` first" when `dist/server/index.mjs` is missing).
- **Worker** (`builder/worker.ts`): `edgy:worker` (`builder.buildApp` writing Marko's order out so the Cloudflare plugin does not build the Worker twice; a plain error when `wrangler.jsonc` is missing), `releaseSsrExternal` (vanilla-extract sets `ssr.external`, which the Cloudflare plugin refuses), `dropServerStyles` (the server environment's stylesheet copy is read by nobody), then `cloudflare()`, imported lazily (it costs most of a second and opens a Wrangler log). The lazy import needs Vite's default config loader (`configLoader: 'runner'` closes its module runner first). `CLOUDFLARE_LOAD_DEV_VARS_FROM_DOT_ENV=false` is set first (the plugin would otherwise read `.env.local` over the `wrangler.jsonc` vars; a Worker's local overrides are `.dev.vars`), and `WRANGLER_LOG_PATH` defaults to `.wrangler/logs`. **`wrangler.jsonc` is the only source of the Worker's settings**, `DATABASE_AUTO_MIGRATE` included, for `dev`, `preview` and `deploy` alike. `pnpm run deploy` is `pnpm build --mode worker --minify` then `wrangler deploy`, so what `preview` runs is what `deploy` ships.
- **`pnpm compile`** (`builder/compile.ts`, a script because Vite makes no executables): the same configuration with overrides (one CJS file: `format: 'cjs'`, `codeSplitting: false`, no banner, `import.meta` defined as `({})`; the client output into the same directory) in a temp directory, passing every browser file to `node --experimental-sea-config` as `assets/<name>`, then a copy of `node` and postject. The one `import.meta.url` in the server runs only when `embeddedAssets()` is `undefined`. A native addon cannot be carried.
- **Minification is Vite's `--minify`** (the server; browser assets are always minified); there are no custom build flags. Covered by `tests/platform.test.ts`, `node_output.test.ts`, `native_addons.test.ts`, `vite_config.test.ts` (address, env, command-line and user-config precedence, platform selection; the Worker case runs in a child process), `dev_server.test.ts`.

## Development services

- **`compose.yaml` runs what the app talks to, not the app**: ClickStack (`clickstack`, the all-in-one HyperDX image: UI 8080, OTLP/HTTP 4318; gRPC deliberately not published), a one-shot `clickstack-init`, and Valkey (6379, password `securedb`). `compose:up|down|restart|cleanup` (cleanup also deletes `./.storage`, git-ignored). Host ports are variables (`CLICKSTACK_UI_PORT`, `OTLP_HTTP_PORT`, `VALKEY_PORT`).
- **ClickStack has no collector pipelines until a team exists**, and a team exists only after someone registers; then the collector enforces an ingestion key. `clickstack-init` registers the development account through `POST /api/register/password` (409 = already there is fine) and `INGESTION_API_KEY` fixes the accepted key, so telemetry works from the first `compose:up`. The init retries until healthy (`depends_on: service_started`), because `service_healthy` would hold `up --detach` for a minute. Never reuse these credentials or the key outside development.

## How to change it

- **New module / endpoint**: `src/modules/<resource>/` with `_schema.ts` (entity, request and response schemas, the table type merged into `Database`; a new table also needs a migration and registry entry), `_repo.ts` and `_service.ts` (each a `Context.Service` with `static layer`; the service declares itself in `HttpServices`), `_handler.ts` (one `defineHandler`, or `definePagedHandler` for a collection, per endpoint), `_routes.ts` (a `defineRouteGroup`) → layers into `src/services.ts`, module into `apiModules` in `src/routes/route.ts` → a test beside the code → regenerate `docs/openapi.json` → `docs/api-endpoint.md` row, in the same commit.
- **New page**: `app/pages/<name>.marko` (+ tags, styles as needed) → `<module>_pages.ts` with a `definePageHandler` (lazy `template`) and a `defineRouteGroup` → register it in `pageRoutes` → a test (HTML, headers, a failure) and a `*.spec.ts` in `e2e/screens/` → `pnpm typecheck` (runs `mtc`) → `docs/api-endpoint.md` row, and `docs/frontend.md` for a new concept, in the same commit.
- **New CLI command**: `src/command/<name>.ts` (`Command.make`, flags, handler) → `withSubcommands` in `cli.ts` → `docs/commandline.md` in the same commit. Destructive: `--force` + `confirmDestructive`.
- **New config key**: add a field (`text`, `port`, `int`, `flag`, `milliseconds`, `ratio`, `secret`, `choice`, `choiceList`, `logLevel` from `src/kernel/config/field.ts`) to the section file that owns the concern, with default and description; read it as `(yield* ConfigService).<section>.<key>`. The declaration also feeds `.env.example`: run `pnpm app config:generate` and commit it (a test fails when it is stale) → `docs/configuration.md` row. A **new concern** is one file exporting `<name>Config` (a `group` with a `title`) plus one line in `appConfig` (`config/service.ts`); cross-field checks go in the group's `transform`. A secret uses `secret()` (`Redacted`); its optional third argument is a development default for a Compose service, written to `.env.example`, so it must never be a real credential. **Durations are whole milliseconds** (`milliseconds()` with a `min`; `REQUEST_TIMEOUT=30000`; `30 seconds` fails at startup naming the variable and the unit); names carry no `_MS`.
- **New migration**: `src/database/migrations/NNNNN_name.ts` exporting `up`/`down` → register in `migrations/index.ts` → `pnpm app migrate:up`.

## Traps

- **Tests.** Vitest with `@effect/vitest` for `src/**/*.test.ts` and `tests/**/*.test.ts` (project `unit`); helpers in `tests/`: `components_setup.ts` (the `marko` project's setup: jest-dom matchers and `afterEach(cleanup)`, which the library registers itself only when `afterEach` is a global), `app.ts` (`makeTestApp`), `cache.ts` (`fakeBacking`: a shared store that can fail or hang), `ids.ts` (`MISSING_USER_ID`, `userRow`), `d1.ts` (`fakeD1`: counts statements, injects transient read failures, rejects booleans and `undefined` bindings like D1), `collector.ts` (`startCollector`: an in-process OTLP receiver passed as `makeTestApp(env, { fetch })`; no port, no global stubbed, since Effect caches the default `fetch`). `makeTestApp` builds the real app over an in-memory database; its `console.log` lines are kept in `TestApp.logs`, and a test needing another runtime builds it with `Logger.layer([])`. CLI commands are tested through `runWith` over a temporary SQLite file, `console` spied, `--force` standing in for the prompt. Effect tests use `it.effect` (TestClock) or `layer(...)(name, …)`; never `Effect.provide(layer)` inside a test and never a real `setTimeout` wait. Pass environment overrides as an operator would (`makeTestApp({ RATE_LIMIT_MAX: '2' })`). Code outside Effect that reads `Date.now()` is not moved by TestClock: use Vitest's fake timers. A test that asserts on telemetry sets `OTEL_TRACES_SAMPLE_RATIO=1`.
- **A green unit suite does not exercise the artifacts.** Before claiming a change works also run `pnpm build` + `node dist/server/index.mjs serve`, `pnpm dev` for anything in `app/` or the dev wiring, and, if the Worker's import graph, pages or D1 path changed, `pnpm preview --mode worker`. A sandbox that forbids port binding rejects `serve` and `wrangler dev` with `EPERM`.
- **Component tests** (`app/**/*.test.ts`, project `components`, jsdom, `resolve.conditions: ['browser']`) render one tag with `@marko/testing-library` (`render`, `fireEvent`, `rerender`) and query it the way a user would. The condition is required: without it the library's Node build loads, calls the template's server `render` on a browser-compiled template and throws. A test casts the imported template to `Marko.Template<{ … }>`, since the `*.marko` declaration has no input type. A component test sees no hydration, no CSP and no page; those stay in Playwright.
- **Page-level browser tests run under Playwright Test, not Vitest** (`e2e/**/*.spec.ts`, `pnpm e2e`). Vitest's browser mode runs the test file inside the browser on Vitest's own origin, so server-rendered pages with a per-response CSP nonce cannot be the page under test; and Playwright's library driven from Vitest has no UI mode, trace viewer or fixtures. `playwright.config.ts` starts the production build (`webServer`) and defines four browser projects plus `Dev` (only `hot-reload.spec.ts`, against `pnpm dev`). Scenarios sit in `e2e/screens/`, one spec per page, reaching it through a page object in `e2e/fixtures/`, with helpers in `e2e/utils/` and static inputs in `e2e/test-data/` (`users.json` must match the seeders). A check every page needs (no CSP violation, no console error) is `expectCleanLoad`, called from each spec. What needs a browser: hydration (the `/users` filter narrows the list only once the page's script has run), the CSP (`securitypolicyviolation` events, and an un-nonced inline script that must be blocked), the pager, the HTML-versus-JSON error split, and a style edit reaching an open page in dev. CI installs Chromium (`pnpm e2e:install`) and runs `pnpm e2e --project Chromium`. The Worker build is not under test there.
- **The Worker entry (`src/worker.ts`) exports its handler and nothing else, and builds one app per `env` object.** workerd refuses a module whose named exports are not handlers ("Incorrect type for map entry"), and only a run in workerd shows it. Cloudflare passes one `env` for the life of an isolate, so the app is built once. A different `env` object replaces the app, logs a warning and stops the old runtime after 30 s; a failed build is dropped so the next request retries.
- **workerd is not Node.** No I/O, timers or random values at module load (`crypto.randomUUID()`, `setTimeout`, `fetch` run lazily, inside a layer or handler; otherwise "Disallowed operation called within global scope"), `AsyncLocalStorage.enterWith` is not implemented (use `run`), `process.stdout` is not the log sink, there is no socket address, `node:sqlite` does not exist. Anything shared with the Worker is checked with `pnpm preview --mode worker`.
- **`exactOptionalPropertyTypes` is on**: optional properties in response and error types must be `| undefined`-compatible; `Option` values from `Flag.optional` need `Option.isSome` before `.value`.
- **Effect v4, not v3**: the repo pins `effect@4.0.5`; v3-era APIs do not match, and the pinned `node_modules` types are the truth.
- **Edit races**: never batch several edits to the same file in one parallel block; one is silently lost.

## Plan documents

A plan (`.llms/plans/plan-YYYYMMDD_HHMM.md`) is a contract with a fixed shape: frontmatter (`status`, `updated`, `phases` with per-phase `status`/`note`), Objective, Current state (verified file:line facts), Decisions (dated, rejected alternatives named), execution rules, Phases (each with an objectively checkable validation line and a suggested commit message), test matrix, out of scope. It executes only on the owner's explicit instruction ("continue with phase N"); one atomic commit per phase; after the last phase, stop and recommend the closing commit message, never commit it unasked. Full spec: the `agent-docs` skill.
