## Traps learned (all now in `rules.md`)

- `jsxImportSource` is `@solidjs/web`; `hydrate`/`renderToStream` come from `@solidjs/web`, not
  `solid-js/web` (v2 has no such subpath).
- `@solidjs/router` ships `.jsx` under its `solid` condition — the Solid plugin's include must cover
  `**/node_modules/@solidjs/router/dist/**/*.jsx` (a bare `node_modules/…` pattern misses pnpm's
  nested paths), or Vite compiles it with React's runtime.
- The Solid plugin's SSR transform appends `export const $$moduleUrl` to every application module;
  workerd refuses it in the entry module's export map — `dropEntryModuleUrl` (`builder/worker.ts`)
  strips that name from the entry's export list only.
- Vite `define` replaces exact identifiers and is per-environment: the client manifest is inlined on
  `environments.ssr.define` only, read guarded (`typeof`) because dev has none.
- `pnpm build --mode worker` has `mode: 'worker'`, not `'production'` — do not gate build-time
  behavior on mode alone.
- `ServicesServer<Rpcs>` stays an unresolved conditional on a generic rpc group; the assertions in
  `rpc.ts` name what the composition actually closes (the vendor test uses a concrete group).
- The h3 test harness (`t.request`) consumes the request body — an rpc call in a test goes through
  `app.fetch` with a raw `Request`.
- `filesystem-routing` parses every file in its `dir`; a file with TS generics outside a route
  module (`rpc-client.ts` had one) breaks the scan — helpers live outside `src/pages/`.

  `@solidjs/vite-plugin@3.0.0-next.50`, `@solidjs/router@2.0.0-next.40`). When 2.0 stabilises, bump

  same group when a page needs them.

  posture before adding headers.
