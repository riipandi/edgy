## What changed and why it matters

- **`--log-level` works, and the global flags are the document's three** (F-02, F-05). `Command.run`
  installs the level and dispatches the wizard by *object identity*; the previous `Object.assign({},
  builtIn, …)` clone made `--log-level` a parsed no-op and `--wizard` a silent exit. `cli.ts` now
  provides `[Help, Version, LogLevel]` canonically and runs `Command.runWith` over `normalizeArgs`,
  which lowercases the level so `Debug` matches `debug`. `--wizard`/`--completions` are gone.
- **`serve` is found by parsing argv** (F-04). `subcommandOf` skips global flags and the value
  `--log-level` consumes; `main.ts` branches on it. `vpr app --log-level info serve` used to take the
  `runMain` path — exit `130`, no shutdown lines.
- **`migrate:up --to` is forward-only** (F-01). Kysely's `migrateTo` walks backwards, so an applied
  target used to drop tables with exit `0`. The command reads the status once, refuses an applied
  target before the dry-run branch, and reports it as `CliError.UserError`.
- **`generate:config` cannot be steered into a real `.env`** (F-03, F-07, F-09). The refusal resolves
  the symbolic-link chain (`readLink`, bounded at 32 hops, dangling links included) instead of asking
  `fs.exists`; `--force` alone is a no-op; `--stdout --check` is rejected; `--output`'s help carries the
  documented default.
- **The shutdown path owns its signals and its Redis scopes** (F-06, F-08). Any signal after the first
  exits `128 + signum`; both Redis stores build into a scope they own and log `closing …` then
  `… closed` around `Scope.close`.
- **The command surface is guarded** (F-10). Four specs plus `harness.ts` drive the real `run(args)`
  over a temp SQLite database and a temp directory — 30 tests, each mutation-checked against its fix.

## What stayed open / the traps

- **Nothing from the audit is open.** `docs/commandline.md` was never edited: the code was brought to
  the document. If a future change finds a genuine contradiction inside it, stop and ask the owner.
- **Trap — a built-in global flag must never be copied.** `Command.run` compares `flag === GlobalFlag.X`
  and `activeFlags.includes(GlobalFlag.LogLevel)`; a clone parses and then does nothing, and hiding a
  built-in *requires* a new object. `GlobalFlag.Setting` has the same problem from the other side: each
  construction mints a new service key.
- **Trap — a Redis close line cannot be added after the client's own finalizer.** `NodeRedis.layer`
  closes the client from its scope finalizer and finalizers run LIFO, so the only way to log both sides
  is to own the scope (`Scope.make` + `provideService`, then `Scope.close` inside the finalizer) — the
  shape both `cache.ts` and `rate-limit.ts` now use.
- **Trap — `process.argv[2]` is not the subcommand.** Anything that branches on the invocation before
  the program runs must go through `subcommandOf`.
- **Trap — a signal-only harness exits before it can be signalled.** `awaitShutdownSignal` does not hold
  the event loop open; a probe needs the HTTP server (or a keep-alive interval) for the drain to happen.
