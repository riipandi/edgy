## What changed and why it matters

- **One URL, two transports** (D1/D2). `resolveDatabaseTarget` (`src/kernel/config/database.ts`) is the
  only place a URL becomes a transport: a `file:` URI (RFC 8089: `file:/p`, `file:///p`,
  `file://localhost/p`, `file:./rel`, percent-decoded) or a bare path opens the local engine;
  `libsql://`, `turso://`, `https://`, `http://` opens the remote one and requires `DATABASE_TOKEN`.
  `file://otherhost/p` and `:memory:` are refused by name, because a local engine cannot open another
  machine's file and a second process would get a private database.
- **The dialect keeps `kysely-libsql`'s shape** (D3) over a `TursoExecutor`, so the two transports are
  invisible to feature code. The remote executor maps each row through `result.columns` — Turso returns
  arrays with non-enumerable named properties, and `JSON.stringify` on them yields `[7,"seven"]`. That
  bug was found against the real platform, not the stub.
- **No custom lock** (D4): `supportsMultipleConnections = false` gives the Kysely `ConnectionMutex`, and
  a statement issued inside a transaction waits for it.
- **The engine locks the file exclusively by default** (D13). Without `experimental: ['multiprocess_wal']`
  the container `HEALTHCHECK` and any `migrate:up` run failed while `serve` held the database —
  `node:sqlite` never did that. `LOCAL_CONNECT_OPTIONS` carries the flag; a spec opens the file from a
  child process to keep it honest.
- **`dist/` carries the native addon** (D6). The Turso JavaScript inlines; the compiled addon cannot, so
  the standalone build copies `@tursodatabase/database-<platform>` into `dist/node_modules`
  (dereferenced out of pnpm's store). The Dockerfile now copies `dist/` and nothing else. This retires
  the "zero native dependencies" claim: the image grows ~16 MB and a `dist/` runs only on the platform it
  was built for.
- **The leak guard had a real false positive.** It matched import syntax spelled inside JSDoc examples and
  template literals, so every non-minified standalone build already failed at HEAD (minified ones passed
  only because comments are stripped). It now reads a statement only at a line start or after a `;`, and
  skips `dist/node_modules`.

## What stayed open / the traps

- **Trap — the plain `nonroot` distroless tag cannot start the entry.** The build bakes the shebang as
  `#!/busybox/env node` from `ENV_BINARY_PATH`, and only the `debug` variants ship `/busybox`. Build and
  run with `DISTROLESS_TAG=debug-nonroot` (compose does it through `APP_DISTROLESS_TAG`). This is
  recorded in `.llms/shape.md` and `.llms/rules.md`, not fixed: making `nonroot` work means changing how
  the entry is invoked, which no phase asked for.
- **Trap — a tool outside this application conflicts with the database file.** `sqlite3` or the `turso`
  CLI opening the same file without `multiprocess_wal` is refused by the server's connection, and the
  reverse holds too. Do not "just check" a live database with another client.
- **Trap — copying a WAL-mode database.** Delete `-wal` and `-shm` first, or the stale WAL replays into
  the copy.
- **Trap — `await db.prepare(sql)`.** It is synchronous at runtime but typed `Promise<Statement>`;
  `.then` on the result throws.
- **Nothing is open.** `docs/commandline.md` was never touched (it is the owner's specification and
  describes the CLI, not the driver). The repository database was reset under D12 and rebuilt.
- **Deliberately not done** (plan D8): a statement cache. `prepare` costs ~8 µs on Turso against 7.22 µs
  on `node:sqlite`, so the parked item stays parked with the new measurement recorded.
