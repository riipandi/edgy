# Behaviour logging audit — request-log, observer sinks, dev parity

Point-in-time audit of the access-log and logger surfaces (`src/middleware/request-log.ts`,
`src/observer/*`, the serve and dev compositions). Every finding below was reproduced against a
running process on 2026-10-27, not derived from reading alone. The companion plan carries the
owner's decisions.

## Method

- **Serve repro** — `vpr app serve` (the production composition from source) probed with
  `curl` against `/api/health`, `/`, `/metrics`, `/favicon.ico`, `/api/nope`; console captured in
  both `LOG_FORMAT=pretty` and `LOG_FORMAT=json` runs.
- **Dev repro** — `vpr dev` probed with the same endpoint set; console captured, file sink
  (`storage/logs/app_20261027.jsonl`) inspected after the run.
- **Isolated repro** — `apiHandler()` executed in-process under vitest (identical composition,
  plain node process) with the file transport; the request-log record appeared as expected.
- **Instrumented probes** (temporary, reverted before this record): a raw `process.stdout.write`
  next to `Effect.logInfo` in the middleware, a fiber-level `CurrentLoggers` count, and a
  `applicationRuntime.runPromise(Effect.logInfo(...))` probe in the dev plugin.

## Findings

- **F1 — open — dev request log vanishes entirely (console and file).** In `vpr dev`, requests the
  Effect handler serves (`/api/*`, `/metrics`, `/api-docs` — `src/builder/vite-plugin.ts:148-126`)
  produced zero request-log records. Probes proved the middleware itself runs (the metric series
  `http_requests{GET,200,/api/health}` incremented), `process.stdout.write` works in that process,
  plain timers fire, and logging through `applicationRuntime.runPromise` in the same process prints
  — but `Effect.logInfo` from the `HttpRouter.toWebHandler` request fiber emits nothing. The fiber
  did carry 2 loggers in its `CurrentLoggers` set (the dev transport pair), so the loss sits between
  the seeded set and the batched sinks' flush. The identical composition logs correctly in a plain
  node process, including after the same prepare-then-handler sequence, so the trigger is specific
  to the vite dev process. Root-cause isolation is phase 1 of the plan.
- **F2 — open — pages and assets never traverse the Effect stack in dev.** Start's dev middleware
  renders pages inside Vite (the established dev architecture), so request-log never sees `/`,
  `/favicon.ico`, or asset paths in dev; production logs every request. Dev and prod observability
  disagree structurally, not just by bug.
- **F3 — open — the quiet-path suppressor is only half a suppressor.** The middleware's own line and
  the metric record are suppressed correctly (`src/middleware/request-log.ts:52`; the serve repro
  showed no request-log line for the failing `/favicon.ico`, and `tests/middleware/request-log.test.ts:76-91`
  passes). But `HttpRouter.serve` and `HttpRouter.toWebHandler` install the framework's
  `HttpMiddleware.logger` by default (verified in `node_modules/effect/dist/http/HttpRouter.js`,
  `serve` implementation), so a quiet-path failure still leaks a framework record with the full cause.
- **F4 — open — every successful request logs twice.** The request-log line and the framework
  `Sent HTTP response` record (same `http.*` annotations, no `requestId`) both land in console and
  file. Double volume on every request, two shapes to parse downstream.
- **F5 — open — failed responses render a broken pretty line.** The framework record for a failed
  request carries `message: []` (empty array) with the cause attached; the pretty renderer emits
  `13:19:20.812 INFO   http.method=GET http.url=/ http.status=500` — an INFO line with no message —
  followed by the full stack. Verified in both serve repro runs and in the file sink.
- **F6 — resolved (2026-10-27, `6c137606`) — the stdout sink defects instead of degrading.** `makeBatchedStdout`
  (`src/observer/logger.ts:75-84`) calls `process.stdout.write(chunk, callback)` unguarded; in an
  environment that patches stdout (vitest capture), the flush raised
  `TypeError: Cannot read properties of undefined (reading 'Symbol(kState)')` and killed the flush
  fiber. A sink must degrade to stderr, not defect.
- **F7 — open — failures are recorded as 500 without classification.** The failure branch
  (`src/middleware/request-log.ts:54-62`) records `recordRequest(..., 500, ...)` for any
  `Exit.isFailure`, including client-abort interrupts (no response was ever sent). Server-fault and
  client-disconnect share one metric bucket and one WARN.
- **F8 — wontfix candidate — URL parsing edge.** `new URL(request.originalUrl, baseUrl)`
  (`src/middleware/request-log.ts:52`, same pattern in `error-response.ts:29`) ignores `baseUrl`
  when `originalUrl` is already absolute and throws on an unparseable pair. Low likelihood, no
  observed failure; parked here for the record.

## Observations (not findings)

- `storage/logs/app_20261026.jsonl` reached 311 MB in one day. Not investigated here — the volume's
  source (which transport, which level) is out of this audit's scope; if it recurs after this plan,
  it earns its own issue.
- The `requestId` annotation reaches the request-log lines through `Effect.annotateLogsScoped`
  (`src/middleware/request-id.ts:31`) and is absent from the framework records — resolved as a
  consequence of F4's fix rather than as its own change.
