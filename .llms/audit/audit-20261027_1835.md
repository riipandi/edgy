# Audit — TanStack Start SSR configuration

## Executive summary

The Start SSR wiring is more correct than expected: the plugin option shape matches the documented schema exactly (including the Vite-only `vite.installDevServerMiddleware` key), `ssr.nonce` is a documented router option, the installed TanStack package set is the exact set `react-start@1.169.4` pins itself (no version skew), the dev split is wired per the D-rule, and the built HTML carries nonced stylesheet and client-entry tags.

The real misconfigurations are two: page navigation uses a hand-rolled `src/paths.ts` URL builder with plain `<a href>` — full document reloads instead of TanStack's type-safe `<Link>` client navigation (owner-identified) — and a dead `prebuild: tsr generate` hook plus the redundant `@tanstack/router-cli` dependency that duplicate the generator the Start plugin already runs. Two lower-severity items: relative generator paths that resolve against `srcDirectory` (the trap that already bit this repo once) and missing router preload options the reference template carries.

- Reference comparison: `github.com/riipandi/tanstart` (router.tsx, vite.config.ts, __root.tsx, package.json) fetched at commit `e8b7b27`.

### F1 — Hand-rolled URL builders and full-reload navigation replace TanStack's type-safe `<Link>`

- **Category**: correctness / UX. **Severity**: medium. **Confidence**: high.
- **Location**: `src/paths.ts` (`paths.home()`, `paths.users(id?)` string builders); consumers: `src/resources/components/navbar.tsx:8-9`, `src/routes/(app)/users/index.tsx:27`, `src/routes/(home)/index.tsx:32` — all rendered as plain `<a href>`.
- **Failure scenario**: every internal navigation performs a full document load: the browser re-requests the page, the Effect listener re-renders it server-side, React re-bootstraps — losing Start's client-side routing (scroll restoration state, preload-on-intent, no flash). It also erases the type safety the route tree provides: renaming or moving a route silently breaks these string URLs, which is exactly how the `paths` builders drift from the tree. The detail page already uses `<Link to='/users'>` (`$id.tsx`), so the codebase carries both styles.
- **Fix**: delete `src/paths.ts`; replace every consumer with `<Link to=...>` from `@tanstack/react-router` (`to='/users'`, `to='/users/$id' params={{ id }}`, `to='/'`). The existing E2E specs assert `href` attributes — `<Link>` renders the same anchor markup, so the specs pass unchanged. This matches the owner's direction ("paths.ts juga seharusnya tidak berlaku di tanstack start").

### F2 — Dead `prebuild` hook and a redundant second router generator

- **Category**: hygiene / tooling. **Severity**: medium. **Confidence**: high.
- **Location**: `package.json:49` (`"prebuild": "tsr generate"`), `package.json:76` (`@tanstack/router-cli@^1.167.46`).
- **Failure scenario**: two independent issues compound. (1) `prebuild` is an npm lifecycle hook, and vite-plus does not execute npm pre-hooks — `vpr build` never runs it, so the script is dead configuration. (2) Even if it ran, the Start plugin already generates the route tree: `start-plugin-core` bundles `start-router-plugin` (`tanStackStartRouter`, `vite/plugin.js:14`) which runs `router-generator@1.167.46` on every dev session and build — the exact same generator version `router-cli` would invoke. The duplicate mechanism adds a dependency, a second config surface, and the illusion of a generation step that does not happen.
- **Fix**: remove the `prebuild` script and the `@tanstack/router-cli` dependency; the plugin's generation (and the documented CI ordering — build before check/typecheck) covers all flows. No backward compatibility needed at this stage.

### F3 — Relative generator paths resolve against `srcDirectory` (documented trap)

- **Category**: hygiene / tooling. **Severity**: low. **Confidence**: high.
- **Location**: `vite.config.ts` `tanstackStart({ router: { routesDirectory: 'routes', generatedRouteTree: 'routeTree.gen.ts' } })`.
- **Failure scenario**: both values resolve against `srcDirectory`, not the project root. This repo already shipped a broken tree to `src/src/` once because of this resolution rule (recorded in the archived migration plan's phase 2 note and in `rules.md`). The reference template sidesteps it with absolute paths (`resolve('./src/routes')`, `resolve('./src/routes.gen.ts')`).
- **Fix**: pass absolute paths (`resolve('./src/routes')`, `resolve('./src/routeTree.gen.ts')`). Output paths stay identical; the trap disappears. The `rules.md` trap bullet stays but loses its live trigger.

### F4 — Missing router preload options the reference carries (optional)

- **Category**: operability. **Severity**: low. **Confidence**: high (feature-level, not a defect).
- **Location**: `src/router.tsx` `createRouter({ routeTree, scrollRestoration, ssr: { nonce } })`.
- **Scenario**: the reference template sets `defaultPreload: 'intent'` and `defaultPreloadStaleTime: 0` — links preload their loaders on hover/focus. Without it, client navigation waits for the loader at click time. With F1's `<Link>` adoption this becomes the visible UX difference.
- **Fix**: add both options when F1 lands (they only matter once navigation is client-side). Optional — owner may defer.

### F5 — SSR `origin` resolution unverified (verify before deciding)

- **Category**: correctness. **Severity**: info. **Confidence**: medium → verdict recorded 2026-10-27.
- **Location**: `src/router.tsx` (no `origin` option).
- **Scenario**: `router-core` documents `origin` as the server-side URL resolution base, defaulting to `http://localhost` on the server. The Effect renderer forwards the real request (host headers intact), so relative rendering works — but absolute URL construction during SSR (redirect targets, generated absolute links) has never been exercised against a non-localhost host. Verify in the plan's first phase (probe with a spoofed `Host` header) before deciding whether `origin` should come from `AppConfig`.
- **Verdict (phase 5 of `plan-20261027_1835`)**: no defect. Against the built binary with `Host: evil.example.com` (plus `x-forwarded-host`/`x-forwarded-proto`): the detail page renders 200 with zero absolute URLs in the markup, the trailing-slash redirect answers a relative `location: /users` (no host-header injection), and `/api/health` is unaffected. `origin` stays unset.

### F6 — Lockfile carries TanStack package family versions that differ per package

- **Category**: hygiene (third-party metadata). **Severity**: info. **Confidence**: high.
- **Location**: `pnpm-lock.yaml`.
- **Scenario**: per-package versioning (e.g. `router-core@1.171.39` under `react-router@1.170.46`) is TanStack's normal independent versioning, not skew — `react-start` pins the exact core versions it was built against. Recorded so future sweeps do not re-litigate. `minimumReleaseAge` may still lag the latest release train, which is the intended supply-chain behavior.
