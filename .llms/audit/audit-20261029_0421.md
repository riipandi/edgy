## Details

### F1 — concurrent duplicate-email write answers 503 instead of 409 (medium)

`UserService.create` and `update` are check-then-act: `findByEmail` → `repo.create`/`repo.update`.
`users.email` is UNIQUE (migration 00002), so two concurrent requests with the same email both pass
the check; the loser's INSERT hits the raw constraint, `UserRepositoryError` maps to the sanitized
`DATABASE_ERROR` envelope, and the client gets **503 "temporarily unavailable, retryable"** where
the contract says **409 EMAIL_CONFLICT**. The same race exists for `update` (two PATCHes moving
different users onto one email). Regression test landed with plan-20261029_0447 phase 1
(`1569f9a37`):
`tests/routes/api/users.test.ts` — "responds 409 (not 503) when two concurrent creates take one
email". Fix shape: catch the unique-constraint failure in the repo (or service) and re-raise
`UserEmailConflict`; the check-then-act stays as the fast path.

### F2 — malformed cursor shapes answer 500 instead of 400 (medium)

`decodeCursor` only guards `JSON.parse` failure. `?cursor=bnVsbA==` (base64 of `null`) parses to
`null`, passes the handler's `decoded === undefined` check, and `cursor.sortValue` throws a
TypeError → defect → 500. `[]`, `3`, or `{}` bind `undefined` sort/id values into the Kysely
comparison → driver error → 503. A client can only ever deserve 400 here. Regression test
landed with plan-20261029_0447 phase 2 (`7fc58bfdd`):
`?cursor=bnVsbA==` expects 400 `VALIDATION_FAILED`. Fix shape: validate the decoded shape
(`sortValue`/`id` present and of the right types) inside `decodeCursor` and return `undefined`
(→ 400 "invalid cursor") otherwise.

### F3 — `rate_limits` grows without bound (medium)

`consumeTokenBucket` upserts one row per client IP (`src/middleware/rate-limit.ts`); a repo-wide
search shows the migration and this file are the only touchpoints — no `DELETE`, no TTL sweep, no
expiry on read. A public deployment accumulates one row per distinct IP forever, and every request
pays a write transaction against a slowly growing table. Fix shape: prune rows whose bucket is
exhausted-and-refilled (or older than the window) opportunistically on the write path, or a
periodic sweep keyed off the existing sampler interval.

### F4 — health body leaks dependency error text (low)

`describeError(error)` output lands in the unhealthy `/api/health` response (`CheckResult.error`).
Internal messages (paths, driver text) reach anonymous callers. Fix shape: keep the detail for the
log, return a stable reason code in the body.

### F5 — CORS any-origin with credentials (low, accepted risk)

Empty `CORS_ALLOWED_ORIGINS` echoes any Origin with `credentials: true`. The file's own comment
documents this as intentional until auth lands. Recorded so the trigger is explicit: **the moment
authentication ships, this default must flip**.

### F6 — unbounded shutdown drain (low)

`graceful.ts` closes listeners and waits for in-flight requests; a request that never completes
stalls exit. Node's default `requestTimeout` (300 s) bounds the wait in practice. Fix shape if
desired: a drain deadline that force-closes remaining connections.

### F7 — shared `local` rate-limit bucket (info)

When `remoteAddress` is absent the limiter keys everything as `local`. TCP sockets always carry an
address today; recorded as a latent footgun if the server ever runs behind a socket that omits it.

### F8 — dev OTLP key in source (info)

`DEV_HEADERS = 'authorization=edgy-dev-ingestion-key'` is the default telemetry header. It is a
documented dev-only default (mirrored in `.env.example`); the risk is an operator enabling
telemetry in production without overriding it. A production boot warning when the default header
is active would close the gap.

### F9 — unauthenticated `/metrics` (info, accepted tradeoff)

When `observability.metricsEnabled` is on, `/metrics` serves process internals without auth and
outside the rate limiter. Standard for internal deployments; bind-address or reverse-proxy policy
is the usual control.

### F10 — cache invalidation is best-effort (info)

In redis mode a failed `invalidate` is swallowed; the stale entry serves until TTL. Bounded by the
TTL and consistent with the cache's best-effort contract; recorded for completeness.

## Hypotheses that died

- **SQL injection via `sort_by`** — validated as a two-value literal schema in `user_route.ts`.
- **Token-bucket race** — the single-connection Kysely adapter serializes the transaction.
- **WAL/`-tshm` sidecar permission gap** — already handled and pinned by
  `src/database/dialect.test.ts` ("narrows every file the engine writes beside the database").
- **Cache context shadowing in `cache.ts`** — block-scoped and harmless.
- **Concurrent `--auto-migrate` in cluster mode** — Kysely's migration lock table serializes it.
