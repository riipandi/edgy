# Deferred items from the architecture review

Items the review recommended and the follow-up work did not do, each with the trigger that reopens it. Plans touched: none.

## 1. CI pipeline

- **status**: resolved
- **resolution**: `.github/workflows/ci.yml` runs `pnpm check`, `typecheck`, `test`, `app config:generate --check`, and both builds on every push to `main` and every pull request. It has not run on GitHub yet (nothing here can), so the first run may need a version nudge for the pnpm action.

## 2. Authentication and authorisation

- **status**: open
- **what**: the API is unauthenticated. `apiRoutes` is where the middleware goes. Until then `GET /api/users` lists every user's email to anyone (at most 100 per page; the unbounded `limit=-1` is closed).
- **why deferred**: it needs a product rule (who may call what, what a token carries) that does not exist yet; inventing one would be worse than the gap.
- **trigger**: the first endpoint that must know who is calling.

## 3. Machine-readable API description

- **status**: resolved
- **resolution**: `docs/openapi.json` (OpenAPI 3.1) is derived from the handlers' own schemas: `pnpm app openapi:generate` writes it, `--check` runs in CI, and `openapi.test.ts` compares it with the generator. Effect's `OpenApi.fromApi` (it needs an `HttpApi` contract) was tried on a spike and set aside: it would need annotations for the status, the error envelope, shared components and operation ids, and its API is unstable; adopting `HttpApi` as the routing layer is a much larger change. `@effect/openapi-generator` goes the other way (spec to client) and can consume the file.

## 4. Migrations against a remote D1 database

- **status**: resolved, not yet seen against a real account
- **resolution**: `--remote` on `migrate:up`, `migrate:down` and `migrate:status` points the CLI at the real D1 database through Wrangler's proxy (a temporary copy of `wrangler.jsonc` with the binding marked `remote: true`). `migrate:reset` and `migrate:seed` do not take it. Run for real, it reached Wrangler's own authentication (`CLOUDFLARE_API_TOKEN` in a non-interactive run) and left no temporary file; a login-backed run is the part nobody here could do.
- **trigger**: the first production deploy; record the result here.

## 5. Keyset pagination

- **status**: resolved
- **resolution**: lists are paged by cursor only (`limit`, `cursor`, `sort_by`, `sort_order`); there is no `page`, no total and no "every record" mode. A repository reads `limit + 1` rows after the anchor, and `user_query_plan.test.ts` keeps the keyset queries on their indexes. Described in `rules.md` (collections) and `api-endpoint.md`.

## 6. Shared rate-limit store

- **status**: resolved
- **what**: counters lived in each process, so the effective limit was `RATE_LIMIT_MAX` times the instance count.
- **resolution**: `RATE_LIMIT_STORE=redis` counts through Effect's `RateLimiter` over Redis/Valkey and fails open (timeout, cooldown). Verified against two live instances sharing one Valkey: three requests counted across both, the fourth refused by either. Workers still count per isolate.

## 7. `trace_id` in the envelope

- **status**: resolved
- **what**: the field was in the response type and nothing filled it.
- **resolution**: OTLP export is wired; a successful response carries `metadata.trace_id` when traces are exported and the trace was sampled, and a caller's `traceparent` is continued.

## 8. Behaviour verified only in-process

- **status**: resolved
- **resolution**: `tests/live_server.test.ts` runs a real server on an ephemeral loopback port: a client that destroys its socket interrupts the request fiber (srvx does fire `req.signal`) and frees its in-flight slot, and `BODY_LIMIT` answers `413` for bytes that really arrive, while a lying `Content-Length` ends as `400` or `413` and leaves nothing in flight.
