# Findings from the Marko + Vite + vanilla-extract migration

What the move to Vite (both targets), Marko pages and vanilla-extract left open or unverified. Plans touched: none. The migration itself is described in `rules.md` ("Frontend contracts", the builder bullet) and `architecture.md` ("Frontend", "Build and deploy").

## 1. Not exercised in the session that built it

- **status**: open
- **what**: a sandbox refused to bind a port, so none of these ran: `pnpm dev` over real HTTP (the Vite middleware mounted in h3, the hot-reload socket, a browser hydrating `/users`), `node dist/server/index.mjs serve` and `./dist/edgy serve` serving `/assets/**` (directory source and SEA blobs), `pnpm watch:worker` and `pnpm preview` in workerd (the Cloudflare Vite plugin with Marko in the `ssr` environment, Cloudflare's assets binding serving `/assets`). What did run: `vite build --app` for both targets and the SEA, the built page chunk rendered in-process (assets, nonce), the page rendered through Vite's module runner (the `pnpm dev` path minus the socket), `builder/dev.ts` loading the whole CLI, the full suite, `typecheck` (with `mtc`) and `check`.
- **trigger**: before the first deploy, or the first time someone runs the commands above. Record the result here.

## 2. `users.name` is `NOT NULL` in the initial migration; the application treats it as optional

- **status**: open, waiting for the owner
- **what**: the migration was edited (outside this work) to make `users.name` `NOT NULL`, while `UserSchema` is `NullOr`, `POST /api/users` accepts a body without `name`, and `UserRepository` inserts `null`. 13 tests fail on it (`database.test.ts`, `cancellation.test.ts`, `cache.test.ts`, `error_reporter.test.ts`, `user_service.test.ts`); all pass with the column nullable. Options: make `name` required end to end (schema, request, tests, docs; recommended, since the migration is the newest statement of intent), or make the column nullable again.

## 3. A failed page is answered as JSON

- **status**: considering
- **what**: `definePageHandler` answers a refusal or failure in the API's error envelope, so a browser that asks for a missing or invalid page sees JSON. An HTML error page is a product decision (what it says, whether it carries the trace id, how a 404 differs from a 500).
- **trigger**: the first page a person, rather than a developer, is sent to.

## 4. No browser-level test

- **status**: open
- **what**: page tests assert on the server's HTML only. Hydration, the filter on `/users`, and the CSP in a real browser (does a blocked inline script go unnoticed?) have no test; the AGENTS.md skills name an E2E package that does not exist yet.
- **trigger**: the first interactive component that carries logic worth guarding, or the E2E package.

## 5. A native-addon dependency would not be traced any more

- **status**: open, latent
- **what**: the Rolldown builder detected native packages, kept them external and copied them into `dist/server/node_modules`; per-package chunking went with it. The Vite build inlines everything (`ssr.noExternal`), which cannot work for a package with a `.node` binary, and no step copies one. No current dependency has an addon (`node:sqlite`, a pure-JS Redis client).
- **trigger**: the first dependency that ships an addon. It needs `ssr.external` for that package plus a copy step in `builder/build.ts` (and `seaConfig.assets` for the executable).

## 6. Rough edges of the Vite build

- **status**: open, minor
- **what**: (a) the Worker build emits an unused copy of the page stylesheet under `dist/worker/assets/` (the SSR environment's own CSS, never uploaded: Wrangler takes `**/*.js` modules and the assets directory is `public/`); (b) `@vanilla-extract/vite-plugin` sets `ssr.external`, which the Cloudflare plugin refuses, so `releaseSsrExternal` deletes it for the Worker only (vanilla-extract issue 1684 tracks Vite 8 support; re-check on its upgrades); (c) `pnpm cleanup` is the only way the spike directories `dist/client` and `dist/ssr` left by an earlier run go away; (d) Wrangler writes its debug log under `~/Library/Preferences/.wrangler`, which a sandbox refuses (the build still succeeds, with an error line); `WRANGLER_LOG_PATH` redirects it.
- **trigger**: any of them biting.
