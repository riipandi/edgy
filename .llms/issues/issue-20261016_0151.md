# Findings of the full audit (security, concurrency, performance, cleanup)

Three read-only reviews, each finding re-checked or proven with a throwaway script. What was fixed in the same turn is listed last; everything here is still open. Plans touched: none.

## 1. Unbounded list and a public user directory

- **status**: open
- **what**: `GET /api/users?limit=-1` returns every row without credentials (2 000 rows: 180 KB, 9 ms; on 1 M rows one statement took 1.5 s and +439 MB heap). `UserSchema` exposes `email`. With CORS `*` any site can read it.
- **trigger**: before the API is reachable by anyone untrusted; with item 2 of `issue-20261015_2230.md` (authentication).

## 2. Client address behind an appending proxy

- **status**: open
- **what**: with `TRUST_PROXY=true` the memory limiter keys on h3's leftmost `X-Forwarded-For` entry, which a client controls when the proxy appends: 40 requests with varying values got no 429. `CF-Connecting-IP` (Workers) is not affected.
- **fix sketched**: trust the rightmost N hops (`TRUST_PROXY_HOPS`).
- **trigger**: the first deploy of the Node server behind a proxy.

## 3. Email enumeration on `POST /api/users`

- **status**: considering
- **what**: a duplicate email answers `409`, a new one `201`. A product decision (generic answer plus verification, or accept and rate-limit harder).
- **trigger**: when users become real people.

## 4. No index for `sort_by=name`

- **status**: open
- **what**: `EXPLAIN` shows `SCAN users` plus a temp B-tree: page 1 of 1 M rows 51 ms, page 10 000 1.4 s, all synchronous on the event loop. An index on `(name, id)` brings them to 0.35 ms and 3.7 ms for about 48 MB.
- **options**: add the index, or drop `name` from the sortable columns.
- **trigger**: a table that may grow past ~100 k rows.

## 5. A write racing a cache fill repopulates stale data (shared stores)

- **status**: open, latent
- **what**: a read that started before a write and finishes after its `invalidate` writes the old value to Redis or the Cache API for the full `CACHE_TTL` (proven: `fresh:false`; the memory store is fine). Latent because there is no `PATCH` or `DELETE` yet.
- **fix sketched**: a per-key generation bumped by `invalidate`, checked after the lookup; full closure needs versioned keys.
- **trigger**: the first update or delete endpoint, or the first shared cache store in production.

## 6. A cancelled request's work still runs on the SQLite connection

- **status**: open
- **what**: a query queued behind the single connection cannot be cancelled: after a `504`, the write still executes (row created, client retries, duplicate). A stalled transaction holds the mutex and wedges the connection. Passing the abort signal into `execute` was shown to drop the queued write and keep the connection usable.
- **trigger**: the first write endpoint that is not idempotent, or any use of `transaction` outside `service.ts`.

## 7. Two processes migrating one SQLite file

- **status**: open
- **what**: SQLite has no transactional DDL and Kysely takes no lock here, so two `serve --auto-migrate` processes on one file failed 20 of 20 times with a `UNIQUE` violation (no data lost). Migrations are not atomic either: a failing `up` leaves the tables it created. See also item 4 of `issue-20261015_2230.md` for D1.
- **options**: a lock file, wrap each migration in `BEGIN`/`COMMIT`, or document one migrating process.

## 8. Log pipeline: unbounded buffer, stalled sink, shutdown

- **status**: open
- **what**: `Logger.batched` buffers without a cap; a sink whose write never returns grows the heap (6 MB at 20 k lines, 27 MB at 100 k) and makes shutdown wait for SIGKILL. On macOS the last stdout batch can be cut by `process.exit` with a full pipe. A forced shutdown does not stop request fibers before the database closes.
- **fix sketched**: time-box each flush, cap the buffer (drop oldest, count them), wait for the write callback on the final flush, abort in-flight requests when `SHUTDOWN_TIMEOUT` expires.

## 9. Development stack defaults and preview deploys

- **status**: open
- **what**: `compose.yaml` publishes Valkey, the ClickStack UI and OTLP on `0.0.0.0` with default credentials (`securedb`, `edgy-dev-ingestion-key`, the dev admin account), and the same defaults are the code's defaults for `REDIS_URL` and `OTEL_EXPORTER_OTLP_HEADERS`. `wrangler.jsonc` has `preview_urls: true` and a shared `DATABASE_AUTO_MIGRATE: "true"`, so a preview upload may migrate the production D1 database (unverified); `--env production` is passed but the file has no `env` block.
- **trigger**: before any shared network or the first production deploy.

## 10. Startup and CLI cost

- **status**: open
- **what**: the Redis client (about 1.3 MB of the Node chunks) is statically imported by the entry despite the lazy import, about 19 ms per start; a CLI command with telemetry on took 3.1 s to exit against 0.12 s with `OTEL_SDK_DISABLED=true` (probably the exporter flush at shutdown, unverified); `PRAGMA synchronous=NORMAL` would halve autocommit cost (56 µs to 25 µs) at the price of the last commits on power loss.

## 11. Duplicated fail-open gate, and housekeeping

- **status**: open
- **what**: the timeout, cooldown and bypass logic is written three times (`kernel/cache/guard.ts`, `middleware/rate_limit_shared.ts`, `middleware/rate_limit_binding.ts`); `DatabaseService.transaction` has no production caller and always fails on D1; `/.well-known/security.txt` serves the placeholder `security@example.com`; `README.md` links a `LICENSE` that does not exist; `.oxlintrc.json` turns `no-console` off for the whole tree and ignores directories that do not exist; `tsconfig.json` maps `#/*` and `$/*` to `app/`, which does not exist; `.gitignore` lists `/vendor/` while `vendor/effect` is tracked.

## Fixed in the same turn

`migrateDown` rolled back nothing once two migrations were applied (off by one); the memory limiter scanned every bucket per request once full (now O(1) eviction); `redactText` was quadratic on adversarial text (now a linear scan, bounded input, and flag and fullwidth-colon forms covered); an inbound `x-request-id` is accepted only from a safe charset; a stalled request body was outside `REQUEST_TIMEOUT` and kept its in-flight slot (now `408`); a hung OTLP collector grew memory without bound (now a 5 s deadline per export); a failed Worker build leaked its runtime; the HTTP method label could mint metric series (now an allow-list); an undecodable cache entry was re-read on every request (now dropped); the cache guard let every concurrent caller probe a recovering store (now one); stale statements in `.llms/` and `docs/`; dead builder helpers and unused config re-exports.
