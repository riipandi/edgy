# Audit findings left open

An audit of security, concurrency, performance, flows and stale code. The findings that were safe or decided were fixed in the same pass; these remain. Plans touched: none.

## 1. Telemetry export could stall on a response body

- **status**: resolved
- **resolution**: `ExportHttpClient` reads the response body under the same 5 s deadline (the read is cached, so the exporter's own read returns at once); a stalled body is now a failure that pauses the exporter. Covered by `telemetry.test.ts`.

## 2. A drain does not wait for streamed bodies

- **status**: resolved
- **resolution**: `provideRuntime` holds the in-flight slot until the response body ends, fails or is cancelled (`lifecycle.test.ts`). Consequence: every body is a stream, so a client that stops reading holds its slot until its socket closes, and counts toward `MAX_IN_FLIGHT`.

## 3. Wrong method answers `404`, not `405` with `Allow`

- **status**: resolved
- **resolution**: the catch-all answers `405` with `Allow` when the path exists under other methods, `404` otherwise (`allowedMethods`, `src/kernel/http/allowed_methods.ts`: rou3's `findAllRoutes` over h3's `~rou3`, the `/**` catch-all itself ignored, `HEAD` added where there is `GET`). Under `/api` it is the envelope (`METHOD_NOT_ALLOWED`), elsewhere the error page. Covered by `routes_extra.test.ts` and `allowed_methods.test.ts`, and run against the built server and the Worker in workerd. The one tie to h3's internals is the `~rou3` property.
- **trigger**: an h3 upgrade that renames `~rou3` (the unit test fails), or h3 exposing a public route lookup, which replaces it.

## 4. The Worker's per-isolate memo

- **status**: open, minor
- **what**: the built app is keyed by the identity of the `env` object. A runtime that passes a fresh `env` per request would rebuild and re-migrate every time. `src/worker.ts` now has tests (the app over a D1 binding; a failed start answers `503`), but not this.
- **trigger**: any change to the Worker entry; verify with `pnpm preview --mode worker`.

## 5. Smaller items

- **status**: resolved
- **resolution**, item by item:
  - `redact.ts` unquoted `password=a b`: kept. The space ends an unquoted value and nothing tells it from the next word; a quoted value is hidden whole. Pinned by a test; the trigger below reopens it.
  - `clientAddress`: an empty entry in `X-Forwarded-For` is skipped (`1.2.3.4,,10.0.0.2` finds the client). A bracketed IPv6 with a port was already accepted (the item was stale). `::/0` stays strict (a range covers one family), documented in `docs/configuration.md` and pinned by a test.
  - `readBodyWithin` now reads the stream itself, cancels it at the deadline and answers `408` with `Connection: close`; run against the built server (a stalled client's socket closes at the deadline, was open until the server's own timeouts).
  - Pages and the API share one rate-limit allowance: kept, as designed.
  - `fakeD1` rejects booleans and `undefined` bindings like D1 does.
  - `limit` accepts plain digits only (`1e2`, `0x10`, `+5`, `5.0` are `400`).
  - A failed log directory stops startup under the default transport: intended, and already documented in `docs/configuration.md`.
  - Telemetry samples at 100 % by default (`OTEL_TRACES_SAMPLE_RATIO`, documented), and assets are read from disk per request: both kept.
- **trigger**: `redact`: a real log line where a space-containing unquoted secret leaks; the shared allowance: pages needing a looser budget; sampling and assets: measured cost in production.
